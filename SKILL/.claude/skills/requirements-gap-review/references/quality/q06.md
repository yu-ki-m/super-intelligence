# Q06 セキュリティ(Security)

このカタログを、案件固有の要求候補を発見するために使う。各項目の適用条件・必要性・代替手段を確認し、一律に必須要件としない。技術例や数値をそのまま採用せず、案件の根拠に基づいて判断する。規格・法令・期限を判断に用いる場合は適用範囲と最新性を確認する。

項目IDを使って案件の根拠・要求候補・指摘・検証条件を結び付ける。

<a id="Q06-01"></a>
## Q06.01 機密性(Confidentiality)

### Q06.01.001 アクセス制御・権限管理の適切さ(最小権限の原則)

- `Q06.01.001.01` ロール設計と最小権限での付与
- `Q06.01.001.02` 定期的な権限棚卸しと過剰権限の回収
- `Q06.01.001.03` 機能・データ・API 各層でのアクセス制御の実装
- `Q06.01.001.04` デフォルト拒否(許可リスト方式)の徹底

### Q06.01.002 URL・ID 推測による不正アクセス(IDOR)対策

- `Q06.01.002.01` 全リソースアクセス時の認可チェック(所有者・権限の確認)
- `Q06.01.002.02` 推測困難な ID の採用(ただし ID 秘匿だけに頼らない)
- `Q06.01.002.03` 他人のリソースへのアクセスを試みる認可テストの実施

### Q06.01.003 保存データの暗号化

- `Q06.01.003.01` 保存時暗号化(ディスク・DB・バックアップ)の適用
- `Q06.01.003.02` 機微項目の項目レベル暗号化の要否判断
- `Q06.01.003.03` 暗号鍵と暗号化データの分離管理

### Q06.01.004 通信の暗号化(TLS 等)

- `Q06.01.004.01` 全通信の TLS 化(内部通信を含めるかの方針決定)
- `Q06.01.004.02` TLS バージョン・暗号スイートの適切な設定
- `Q06.01.004.03` 証明書検証の省略(検証スキップ実装)の排除

### Q06.01.005 鍵・シークレットの管理(ハードコード禁止、ローテーション)

- `Q06.01.005.01` シークレット管理サービスの利用(コードへの直書き禁止)
- `Q06.01.005.02` 定期的・漏えい時のローテーション手順の整備
- `Q06.01.005.03` リポジトリへのシークレット混入スキャン

### Q06.01.006 個人情報・機微情報の保護(マスキング、仮名化)

- `Q06.01.006.01` 個人情報の保有項目・保管場所の台帳化
- `Q06.01.006.02` 表示・ログ・帳票でのマスキングの適用
- `Q06.01.006.03` 仮名化・匿名化の適用範囲の設計

### Q06.01.007 匿名化・統計データの再識別リスク評価

- `Q06.01.007.01` 少数件データによる個人特定リスクの評価
- `Q06.01.007.02` k-匿名性等の指標による評価
- `Q06.01.007.03` 公開・外部提供前のレビュープロセス

### Q06.01.008 画面・帳票上の機微情報の表示制御

- `Q06.01.008.01` 権限に応じた項目レベルの表示制御
- `Q06.01.008.02` デフォルトはマスク表示とし必要時のみ開示する設計
- `Q06.01.008.03` 帳票・エクスポートへの機微項目の出力制御

### Q06.01.009 画面共有・のぞき見への配慮(マスク表示の切替)

- `Q06.01.009.01` パスワード等のマスク表示と一時的な表示切替
- `Q06.01.009.02` 画面共有時に映り込む情報の最小化
- `Q06.01.009.03` 離席時の自動ロック・セッションタイムアウト

### Q06.01.010 検索エンジン・外部への意図せぬ公開防止(noindex、公開設定ミス検知)

- `Q06.01.010.01` 認証必須ページのクローラー除外設定
- `Q06.01.010.02` ストレージ・リポジトリの公開設定の定期点検
- `Q06.01.010.03` 公開範囲設定 UI の分かりやすさ(ユーザーの設定ミス防止)

### Q06.01.011 ファイルメタデータ(EXIF、作成者情報)経由の漏えい対策

- `Q06.01.011.01` アップロード画像の位置情報(EXIF)の除去
- `Q06.01.011.02` 文書ファイルの作成者情報・変更履歴の除去
- `Q06.01.011.03` システムが生成するファイルのメタデータの点検

### Q06.01.012 開発・検証環境への本番データ持ち込み制御

- `Q06.01.012.01` 本番データ持ち出しのルールと承認フロー
- `Q06.01.012.02` マスキング済みテストデータの生成手段の整備
- `Q06.01.012.03` 検証環境のアクセス制御(本番同等の保護)

### Q06.01.013 内部不正対策(職務分掌、相互牽制)

- `Q06.01.013.01` 開発者・運用者の本番データアクセスの制限と記録
- `Q06.01.013.02` 職務分掌(申請者と承認者の分離)
- `Q06.01.013.03` 大量ダウンロード等の異常操作の検知

### Q06.01.014 不要データの削除(データ最小化・保持期間)

- `Q06.01.014.01` 取得項目の必要最小限化
- `Q06.01.014.02` 保持期間を過ぎたデータの削除の実施
- `Q06.01.014.03` 退会・契約終了時のデータ削除ポリシー

### Q06.01.015 廃棄・返却時のデータ消去(メディアサニタイズ)

- `Q06.01.015.01` 記憶媒体の確実な消去(規格に準拠した方式)
- `Q06.01.015.02` クラウド解約時のデータ削除の確認
- `Q06.01.015.03` 消去の記録・証明書の保管

### Q06.01.016 間接的な漏えい対策(ログ、エラーメッセージ、キャッシュ、バックアップ経由)

- `Q06.01.016.01` ログへの個人情報・シークレットの出力禁止
- `Q06.01.016.02` エラー画面での内部情報(スタックトレース)の非表示
- `Q06.01.016.03` キャッシュ・バックアップ経由の漏えい経路の点検

### Q06.01.017 クラウド・SaaS の設定不備の検知(ポスチャ管理)

- `Q06.01.017.01` 設定基準(ベンチマーク)との自動照合(CSPM 等)
- `Q06.01.017.02` 公開設定・権限設定の変更の検知
- `Q06.01.017.03` 重要設定の変更に対する承認プロセス

### Q06.01.018 暗号アルゴリズムの陳腐化への備え(暗号アジリティ・耐量子暗号)

- `Q06.01.018.01` 使用中の暗号方式・鍵長・証明書の棚卸し(暗号インベントリ)
- `Q06.01.018.02` 暗号方式を差し替えられる設計(暗号アジリティ)
- `Q06.01.018.03` 耐量子計算機暗号(PQC)への移行計画(NIST は 2030 年非推奨化・2035 年使用禁止の方針)
- `Q06.01.018.04` 「今収集して後で解読」(harvest now, decrypt later)リスクの評価

### Q06.01.019 プライバシー保護の法令対応(開示等請求・同意管理)

- `Q06.01.019.01` 本人からの開示・訂正・削除請求(DSAR)への対応手段
- `Q06.01.019.02` 利用目的の管理と目的外利用の防止
- `Q06.01.019.03` Cookie・トラッキングの同意管理
- `Q06.01.019.04` 越境移転・第三者提供の法的根拠の管理

## Q06.02 インテグリティ(Integrity)

### Q06.02.005 CORS 設定の適切さ

### Q06.02.006 パラメータ・リクエスト改ざん対策

- `Q06.02.007.02` クーポン・ポイントの同時使用による多重取得の防止

### Q06.02.008 ファイルアップロードの検証(拡張子偽装、マルウェア)

- `Q06.02.008.01` ファイル内容の実体検証(拡張子・Content-Type だけに頼らない)

- `Q06.02.009.01` 信頼できないデータのデシリアライズの回避
