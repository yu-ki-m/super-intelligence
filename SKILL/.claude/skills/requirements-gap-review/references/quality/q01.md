# Q01 機能適合性(Functional Suitability)

このカタログを、案件固有の要求候補を発見するために使う。各項目の適用条件・必要性・代替手段を確認し、一律に必須要件としない。技術例や数値をそのまま採用せず、案件の根拠に基づいて判断する。規格・法令・期限を判断に用いる場合は適用範囲と最新性を確認する。

項目IDを使って案件の根拠・要求候補・指摘・検証条件を結び付ける。

<a id="Q01-01"></a>
## Q01.01 機能完全性(Functional Completeness)

### Q01.01.001 要件・仕様の網羅性(要求された機能がすべて実装されているか)

- `Q01.01.001.01` 要件定義書・仕様書の項目と実装機能の突合表の有無
- `Q01.01.001.02` 「今回対象外」とした要件の合意記録と管理
- `Q01.01.001.03` 非機能要件に紐づく機能(監視用エンドポイント、ログ画面等)の実装漏れ確認

### Q01.01.002 暗黙の要件(業界慣習・法令・商習慣)の考慮

- `Q01.01.002.01` 業界特有の帳票・手続き(締め、月次報告等)の要否確認
- `Q01.01.002.02` 適用法令(個人情報保護法、業法等)由来の機能要件の洗い出し
- `Q01.01.002.03` 「言われていないが当然あるべき」機能(印刷、CSV出力等)の確認

### Q01.01.003 ユースケース・ユーザーストーリーの網羅

- `Q01.01.003.01` 全アクター(顧客、管理者、運用者等)ごとのユースケース列挙
- `Q01.01.003.02` 主フローだけでなく代替フロー・例外フローのシナリオ化
- `Q01.01.003.03` ユースケースとテストケースの対応付け

### Q01.01.004 CRUD の網羅(作成・参照・更新・削除の抜け漏れ)

- `Q01.01.004.01` エンティティ×操作の CRUD マトリクスの作成
- `Q01.01.004.02` 作成(単発/一括/複製)・更新(単項目/一括)のバリエーションの要否
- `Q01.01.004.03` 「作れるが消せない」「登録後に修正できない」データの有無確認

### Q01.01.005 データライフサイクル全体の機能網羅(取得→利用→保管→アーカイブ→削除)

- `Q01.01.005.01` 各段階に対応する機能(取込、閲覧、アーカイブ、削除)の対応表
- `Q01.01.005.02` 保持期間満了時の自動処理(削除・匿名化)の有無
- `Q01.01.005.03` アーカイブ後データの参照・復元手段の提供

### Q01.01.006 論理削除・物理削除の使い分けと復元手段

- `Q01.01.006.01` データ種別ごとの削除方式(論理/物理)の方針定義
- `Q01.01.006.02` 論理削除データの検索・集計への影響(混入・除外)の仕様化
- `Q01.01.006.03` 誤削除時の復元操作の提供と実行権限の定義

### Q01.01.007 変更履歴・世代管理機能の要否と網羅

- `Q01.01.007.01` 履歴が必要なエンティティの特定(監査・トレース要件からの導出)
- `Q01.01.007.02` 変更前後の値・変更者・日時の記録粒度の定義
- `Q01.01.007.03` 過去版の閲覧・比較・復元の可否

### Q01.01.008 取消・訂正・差戻し・返品など逆方向操作の提供

- `Q01.01.008.01` 各業務トランザクションに対する取消・赤伝処理の有無
- `Q01.01.008.02` 確定後データの訂正手順(訂正伝票方式か直接修正か)の定義
- `Q01.01.008.03` ワークフローの差戻し・引き戻し操作の提供

### Q01.01.009 下書き・一時保存・承認前状態の扱い

- `Q01.01.009.01` 長い入力フォームでの一時保存の要否
- `Q01.01.009.02` 下書きデータの可視範囲(本人のみか共有か)の定義
- `Q01.01.009.03` 承認前データの集計・検索への含め方の仕様化

### Q01.01.010 一括処理系機能(一括登録・一括更新・インポート)の網羅

- `Q01.01.010.01` 大量データ登録・更新のインポート手段(CSV 等)の有無
- `Q01.01.010.02` 一部エラー時の挙動(全件ロールバックか部分成功か)の仕様化
- `Q01.01.010.03` 取込結果(成功/失敗件数、エラー明細)のレポート提供

### Q01.01.011 検索手段の網羅(部分一致、複合条件、全文検索、横断検索)

- `Q01.01.011.01` 利用者の探し方(ID 直指定、曖昧検索、絞り込み)ごとの手段提供
- `Q01.01.011.02` 検索対象範囲の網羅(備考欄・添付ファイル内も対象か)
- `Q01.01.011.03` 検索条件の保存・再利用と結果の並び替え

### Q01.01.012 正常系ケースの網羅性

- `Q01.01.012.01` 主要業務シナリオの端から端まで(E2E)の動作確認
- `Q01.01.012.02` 入力パターン(任意項目の有無、選択肢の組合せ)の網羅
- `Q01.01.012.03` データ件数の違い(0件、1件、多数件)での正常動作

### Q01.01.013 異常系・例外ケースの網羅性

- `Q01.01.013.01` 入力エラー、通信断、外部サービスエラー時の挙動定義
- `Q01.01.013.02` 業務例外(在庫不足、与信 NG 等)ごとの処理の仕様化
- `Q01.01.013.03` 異常時のメッセージとリカバリ手段の提供
- `Q01.01.013.04` タイムアウト・二重操作・中断からの復帰など操作起因の異常の網羅

### Q01.01.014 境界条件・限界値の考慮

- `Q01.01.014.01` 最大文字数・最大件数・上限金額のちょうど/超過時の挙動
- `Q01.01.014.02` 0・マイナス・空・最小値の扱いの定義
- `Q01.01.014.03` 日付境界(月初月末、年度替わり、期限当日)の扱い

### Q01.01.015 機能間の組み合わせの網羅(機能A×機能Bの同時利用)

- `Q01.01.015.01` 排他が必要な機能の組合せ(締め処理中の入力等)の洗い出し
- `Q01.01.015.02` 機能を跨ぐデータの受け渡し(検索→一括更新等)の整合
- `Q01.01.015.03` 同時に有効化できる設定同士の矛盾チェック

### Q01.01.016 権限・ロールごとの提供機能の網羅

- `Q01.01.016.01` ロール×機能の権限マトリクスの整備
- `Q01.01.016.02` 各ロールで業務が完結すること(必要機能の欠落がないこと)の確認
- `Q01.01.016.03` 代理・兼務・権限委譲時の機能利用可否の定義

### Q01.01.017 チャネル間(Web/モバイル/API)の機能同等性

- `Q01.01.017.01` チャネルごとの提供機能一覧と意図的な差分の明確化
- `Q01.01.017.02` モバイル非対応機能の代替手段の案内
- `Q01.01.017.03` API のみ/画面のみでしか行えない操作の把握

### Q01.01.018 新旧システム・競合製品との機能同等性(フィーチャーパリティ)

- `Q01.01.018.01` 旧システム機能の棚卸しと対応方針(移行/廃止)の決定
- `Q01.01.018.02` 廃止機能の利用者への影響評価と代替案内
- `Q01.01.018.03` 競合比較での必須機能(テーブルステークス)の充足確認

### Q01.01.019 帳票・通知・メール・エクスポート等の出力系機能の網羅

- `Q01.01.019.01` 必要な帳票・通知の一覧化と発生契機の定義
- `Q01.01.019.02` 出力形式(PDF/CSV/Excel)ごとの要否
- `Q01.01.019.03` 通知の宛先・条件・文面の網羅と設定変更可能性

### Q01.01.020 管理・運用機能(マスタ保守、設定、ログ閲覧)の網羅

- `Q01.01.020.01` 全マスタに対する保守手段(画面または運用手順)の提供
- `Q01.01.020.02` 運用者向け機能(再送、締め解除、代行操作)の整備
- `Q01.01.020.03` リリースなしで変更できる設定範囲の定義

### Q01.01.021 移行データ・過去データへの機能適用可否

- `Q01.01.021.01` 移行データに対する検索・修正・帳票出力の動作確認
- `Q01.01.021.02` 旧仕様データ(項目欠損、旧コード体系)の表示・編集の扱い
- `Q01.01.021.03` 過去日付データへの現行ルール適用の是非の判断

### Q01.01.022 要件トレーサビリティ(要件⇔実装⇔テストの対応の完全性)

- `Q01.01.022.01` 要件 ID と設計・実装・テストケースの対応表の維持
- `Q01.01.022.02` 変更要求発生時の影響範囲の追跡可否
- `Q01.01.022.03` どの要件にも紐づかない実装(仕様外機能)の検出

### Q01.01.023 ワークフロー・承認経路のパターン網羅(直列/並列/条件分岐)

- `Q01.01.023.01` 金額・種別による承認段数の変化のパターン化
- `Q01.01.023.02` 代理承認・不在時の委任・引き上げ承認の提供
- `Q01.01.023.03` 承認途中の取り下げ・条件変更時の再承認の扱い

### Q01.01.024 外部公開インターフェース(API・ファイル連携)の機能網羅

- `Q01.01.024.01` 画面でできる操作のうち API でも提供する範囲の定義
- `Q01.01.024.02` 外部からのデータ取得・投入手段の網羅
- `Q01.01.024.03` API の機能不足が手作業運用を生んでいないかの確認

### Q01.01.025 システム停止時の業務継続手段(代替運用)の提供

- `Q01.01.025.01` 停止中の代替手段(紙様式、オフライン処理)の定義
- `Q01.01.025.02` 復旧後の後追い入力・データ取り込みの手段
- `Q01.01.025.03` 代替運用の発動判断と手順の明文化

## Q01.02 機能正確性(Functional Correctness)

### Q01.02.001 計算結果の正確さ(丸め誤差、桁あふれ、精度)

- `Q01.02.001.01` 計算仕様(数式・精度・丸め位置)の文書化と実装の一致
- `Q01.02.001.02` 極端に大きい/小さい値でのオーバーフロー・アンダーフロー確認
- `Q01.02.001.03` 手計算・別実装との突合による検算
- `Q01.02.001.04` 繰り返し計算・大量集計での累積誤差の評価

### Q01.02.002 浮動小数点誤差への対処(金額は固定小数点・整数演算)

- `Q01.02.002.01` 金額・数量計算での decimal/整数型の使用(float の禁止)
- `Q01.02.002.02` 2 進小数誤差(0.1+0.2 問題)の混入箇所の点検
- `Q01.02.002.03` 言語・DB・帳票間の型変換による精度落ちの確認

### Q01.02.003 丸め・切り捨て・切り上げ規則の一貫性

- `Q01.02.003.01` 丸め方式(四捨五入/銀行丸め/切捨て)の全画面・全帳票での統一
- `Q01.02.003.02` 丸めのタイミング(明細ごとか合計時か)の定義
- `Q01.02.003.03` 法令・契約で丸め方が定まる計算(消費税等)の準拠確認

### Q01.02.004 通貨・税・利率など業務ルールへの適合

- `Q01.02.004.01` 税率・利率の改定に備えた適用開始日付き管理

- `Q01.02.004.03` 業務部門による計算結果の検収(サンプル突合)

### Q01.02.005 集計の二重計上・計上漏れの防止(明細と合計の一致)

- `Q01.02.005.01` 明細合計と集計値の突合チェック(バッチ・画面)
- `Q01.02.005.02` 集計対象条件(ステータス、期間)の定義の明確さ
- `Q01.02.005.03` 訂正・取消データの集計への反映(赤黒処理)の正しさ

### Q01.02.006 検索・集計・ソート・フィルタ結果の正確さ

- `Q01.02.006.01` 検索条件と結果の対応(ヒットすべきものが漏れないこと)
- `Q01.02.006.02` フィルタ組合せ時の AND/OR 解釈の仕様どおりの動作
- `Q01.02.006.03` 集計軸を切り替えても総合計が一致することの確認

### Q01.02.007 ソート順・照合順序(大文字小文字、五十音、Unicode)の正しさ

- `Q01.02.007.01` DB の照合順序(collation)とアプリ側ソートの一致
- `Q01.02.007.02` 日本語(濁点・拗音・長音)の並び順の期待との一致

### Q01.02.008 ページング境界でのデータ重複・欠落(取得中の更新の影響)

- `Q01.02.008.01` オフセット方式でのページ送り中の重複・欠落の検証

- `Q01.02.008.03` ソートキーの一意性確保(同値時のタイブレーク)

### Q01.02.009 出力データの正確さ(表示、帳票、エクスポート)

- `Q01.02.009.01` 画面表示と帳票・CSV 出力の値の一致
- `Q01.02.009.02` 桁区切り・通貨記号・日付書式の指定どおりの整形
- `Q01.02.009.03` 長い文字列・特殊文字の欠け・文字化けの確認

### Q01.02.010 データ整合性(入力と保存内容の一致)

- `Q01.02.010.01` 入力値の暗黙変換(トリム、全半角変換)の仕様化

### Q01.02.011 並行実行時の整合性(排他制御、競合状態、デッドロック)

### Q01.02.012 在庫引当・残高更新など競合の多い業務処理の正確さ

- `Q01.02.012.01` 引当・残高計算の直列化(ロック・キュー)の設計
- `Q01.02.012.02` マイナス在庫・残高不整合の検知と補正手段

### Q01.02.013 冪等性(同一操作の再実行で結果が変わらないこと)

- `Q01.02.013.01` リトライ・再送で二重登録されないキー設計(冪等キー)

### Q01.02.014 NULL・空文字・ゼロ・未設定の区別と取り扱い

### Q01.02.015 ID・採番の一意性と欠番・重複時の扱い

### Q01.02.016 キャッシュと実データの整合(更新反映のタイミング)

### Q01.02.017 マスタ・レート類の適用時点(取引時点か処理時点か)の正確さ

- `Q01.02.017.01` 為替・税率・単価の適用日ルールの仕様化
