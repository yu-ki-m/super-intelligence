# Q03 互換性(Compatibility)

このカタログを、案件固有の要求候補を発見するために使う。各項目の適用条件・必要性・代替手段を確認し、一律に必須要件としない。技術例や数値をそのまま採用せず、案件の根拠に基づいて判断する。規格・法令・期限を判断に用いる場合は適用範囲と最新性を確認する。

項目IDを使って案件の根拠・要求候補・指摘・検証条件を結び付ける。

<a id="Q03-01"></a>
## Q03.01 共存性(Co-existence)

### Q03.01.001 同一環境上の他ソフトウェアとの共存(動作干渉の有無)

- `Q03.01.001.01` 同居する主要ソフトの一覧化と組み合わせ動作確認
- `Q03.01.001.02` 自社ソフトのインストール・更新が他ソフトに与える影響の確認
- `Q03.01.001.03` 干渉発生時の切り分け手順の整備

### Q03.01.002 他プロセスへの性能影響(リソースの占有)

- `Q03.01.002.01` CPU・メモリ・I/O の使用上限(cgroups 等)の設定
- `Q03.01.002.02` 高負荷時に他プロセスを圧迫しないことの確認
- `Q03.01.002.03` プロセス優先度(nice 値等)の適切な設定

### Q03.01.003 隣接ワークロードへの影響(noisy neighbor 問題)

- `Q03.01.003.01` 共有基盤上での他テナント・他システムへの影響測定
- `Q03.01.003.02` リソース分離(専有ノード、QoS 設定)の検討
- `Q03.01.003.03` 影響を受けた/与えた際に検知できる監視の整備

### Q03.01.004 リソース競合(ポート、ファイル、メモリ)の有無

- `Q03.01.004.01` 使用ポートの一覧化と他ソフトとの競合チェック
- `Q03.01.004.02` ファイルロック・共有ファイルの競合確認
- `Q03.01.004.03` 競合発生時のエラーメッセージの分かりやすさ

### Q03.01.005 共有ライブラリ・ランタイムのバージョン競合

- `Q03.01.005.01` 必要ランタイムのバージョンと他ソフト要求との両立確認
- `Q03.01.005.02` 依存の同梱・分離(コンテナ化等)による競合回避
- `Q03.01.005.03` ランタイム更新時の影響確認手順の整備

### Q03.01.006 グローバル資源(環境変数、レジストリ、共有設定)の書き換えの有無

- `Q03.01.006.01` インストール・実行時に書き換えるグローバル設定の一覧化
- `Q03.01.006.02` 書き換えの最小化とアンインストール時に元へ戻す手段
- `Q03.01.006.03` 他ソフトの設定を破壊しないことの確認

### Q03.01.007 同一 DB・ミドルウェア共有時の他システムへの影響

- `Q03.01.007.01` 共有 DB での重いクエリ・ロックが他システムへ与える影響の確認
- `Q03.01.007.02` 接続数制限・リソースガバナーの設定
- `Q03.01.007.03` スキーマ・オブジェクト命名の衝突回避ルール

### Q03.01.008 バッチ時間帯・ジョブスケジュールの競合

- `Q03.01.008.01` 関係システム横断のジョブスケジュール表の整備
- `Q03.01.008.02` 重い処理同士の時間帯重複の回避
- `Q03.01.008.03` スケジュール変更時の関係者調整プロセス

### Q03.01.009 常駐ソフト・セキュリティソフトとの相性

- `Q03.01.009.01` 主要なウイルス対策ソフト共存時の動作・性能確認
- `Q03.01.009.02` リアルタイムスキャン除外設定の要否と手順の提示
- `Q03.01.009.03` EDR・資産管理ツール等、企業標準ソフトとの検証

### Q03.01.010 ブラウザ拡張機能・アドオンとの干渉

- `Q03.01.010.01` 広告ブロッカー・翻訳拡張等による画面崩れ・動作不良の確認
- `Q03.01.010.02` 干渉時の切り分け案内(シークレットモードでの確認等)
- `Q03.01.010.03` 拡張機能の介入に壊れにくい実装(DOM 構造の堅牢性)

### Q03.01.011 マルチテナント環境でのテナント間分離

- `Q03.01.011.01` データ・処理・性能のテナント間分離方式の明確化
- `Q03.01.011.02` 1 テナントの高負荷が他テナントへ波及しない制御
- `Q03.01.011.03` テナントを越えたデータ参照がないことの検証

### Q03.01.012 複数バージョンの同時稼働可否

- `Q03.01.012.01` 新旧バージョン並行稼働(カナリアリリース)時の共存性
- `Q03.01.012.02` 同一端末への複数バージョンインストールの可否
- `Q03.01.012.03` バージョン間でのデータ・設定の分離

<a id="Q03-02"></a>
## Q03.02 相互運用性(Interoperability)

### Q03.02.001 データ形式の互換性(CSV、JSON、XML など)

- `Q03.02.001.01` 連携相手と合意したフォーマット仕様書の整備
- `Q03.02.001.02` 囲み文字・エスケープ・改行を含むデータの相互解釈の確認
- `Q03.02.001.03` BOM・ヘッダー行の有無などの細部の取り決め

### Q03.02.002 API・インターフェース仕様の互換性

- `Q03.02.002.01` OpenAPI 等の機械可読な仕様の公開と実装の一致
- `Q03.02.002.02` 必須/任意項目・型・列挙値の相互理解の確認
- `Q03.02.002.03` 仕様と実装の乖離検出(コントラクトテスト)

### Q03.02.003 API バージョニングと後方互換ポリシー

- `Q03.02.003.01` バージョン付与方式(URL/ヘッダー)の一貫性
- `Q03.02.003.02` 破壊的変更の定義と告知・移行期間のルール化
- `Q03.02.003.03` 旧バージョンの廃止(サンセット)プロセスの整備

### Q03.02.004 スキーマ変更時の前方/後方互換性

- `Q03.02.004.01` 項目追加が既存連携を壊さないこと(未知項目の無視)の確認
- `Q03.02.004.02` 項目削除・型変更時の段階的移行手順
- `Q03.02.004.03` スキーマレジストリ等による互換性の機械的チェック

### Q03.02.005 通信プロトコル・業界標準規格(REST、OAuth 等)への準拠

- `Q03.02.005.01` 標準への準拠度と独自拡張箇所の明確化
- `Q03.02.005.02` HTTP ステータス・メソッドの意味論の正しい使用
- `Q03.02.005.03` 標準準拠の検証(適合性テスト)の実施

### Q03.02.006 業界標準・業界 EDI フォーマットへの対応

- `Q03.02.006.01` 業界標準(全銀フォーマット、EDIFACT 等)の対応範囲の明確化
- `Q03.02.006.02` 標準の版数・方言(実装差異)への対応
- `Q03.02.006.03` 標準改定への追従体制の整備

### Q03.02.007 認証連携の相互運用(SSO、SAML、OIDC)

- `Q03.02.007.01` 主要 IdP との接続実績・検証の有無
- `Q03.02.007.02` クレーム・属性マッピングの取り決め
- `Q03.02.007.03` セッション有効期限・ログアウト連携の整合

### Q03.02.008 文字コード・改行コードの互換性

- `Q03.02.008.01` 連携ごとの文字コード(UTF-8/Shift_JIS)の明確な取り決め
- `Q03.02.008.02` 機種依存文字・外字の変換ルールの定義
- `Q03.02.008.03` 改行コード(CRLF/LF)差異の吸収

### Q03.02.009 単位系・タイムゾーン・ロケールの取り扱いの統一

- `Q03.02.009.01` 日時の授受形式(ISO 8601、タイムゾーン付き)の統一
- `Q03.02.009.02` 数値の単位(円/千円、kg/g)の項目定義への明記
- `Q03.02.009.03` 小数点・桁区切り記号のロケール差の吸収

### Q03.02.010 コード体系の変換(マスタコード読み替え)の正確さ

- `Q03.02.010.01` コード変換表の整備と保守責任の明確化
- `Q03.02.010.02` 変換できないコードが現れた場合の挙動定義
- `Q03.02.010.03` 変換表更新の連携先との同期タイミング

### Q03.02.011 住所・郵便番号・金融機関コード等の共通マスタとの整合

- `Q03.02.011.01` 共通マスタの更新頻度と取り込みプロセスの整備
- `Q03.02.011.02` 廃止・統合されたコードを持つ既存データの扱い
- `Q03.02.011.03` マスタ提供元の仕様変更への追従

### Q03.02.012 カレンダー(iCal)・連絡先など汎用形式での連携

- `Q03.02.012.01` 標準形式でのインポート/エクスポートの対応
- `Q03.02.012.02` 主要製品(Google/Outlook 等)との相互接続確認
- `Q03.02.012.03` 繰り返し予定など複雑なケースの互換性確認

### Q03.02.013 ファイル連携の命名規則・配置・受け渡し手順の整合

- `Q03.02.013.01` ファイル名規則(日付、連番)と同名ファイル受信時の扱い
- `Q03.02.013.02` 転送完了の判定方法(終了ファイル、リネーム方式)の合意
- `Q03.02.013.03` 取り込み後のファイル移動・保管ルール

### Q03.02.014 連携方式(リアルタイム/バッチ/イベント)とタイミングの整合

- `Q03.02.014.01` 業務要件に対する連携頻度の妥当性
- `Q03.02.014.02` 双方の処理時間帯・締めタイミングの整合
- `Q03.02.014.03` 連携遅延時の業務影響と代替手順の定義

### Q03.02.015 再送・重複排除・順序保証の連携先との取り決め

- `Q03.02.015.01` 重複受信時の排除キーの合意
- `Q03.02.015.02` 順序が入れ替わった場合の処理の定義
- `Q03.02.015.03` 再送依頼の手順と範囲指定方法の取り決め

### Q03.02.016 エラー応答・リトライ規約の連携先との整合

- `Q03.02.016.01` エラーコード体系と意味の相互共有
- `Q03.02.016.02` リトライ可能/不可のエラーの区別
- `Q03.02.016.03` 双方のリトライ間隔・回数の整合(過剰リトライの防止)

### Q03.02.017 連携先とのテスト環境・スタブの整備(結合試験のしやすさ)

- `Q03.02.017.01` 相手先テスト環境の利用可否と接続手順の整備
- `Q03.02.017.02` スタブ・モックによる単独試験の可否
- `Q03.02.017.03` 本番同等データでの結合試験の実施可否

### Q03.02.018 連携先のバージョンアップ・仕様変更への追従性

- `Q03.02.018.01` 変更通知を受け取るルートの確立
- `Q03.02.018.02` 変更影響の評価と対応のリードタイムの確保
- `Q03.02.018.03` 旧仕様の廃止期限の管理

### Q03.02.019 外部システム連携時のデータ授受の正確さ

- `Q03.02.019.01` 件数・金額のコントロールトータルの突合
- `Q03.02.019.02` 欠落・重複・文字化けを検知する仕組み
- `Q03.02.019.03` 授受ログの保全と事後調査の可能性

### Q03.02.020 連携状態の監視と障害検知

- `Q03.02.020.01` 疎通・連携成否の常時監視
- `Q03.02.020.02` 連携遅延・データ滞留の検知とアラート
- `Q03.02.020.03` 障害時の自他切り分け(どちら側の問題か)の手順

### Q03.02.021 AI エージェント経由の利用への対応(機械可読な操作手段)

- `Q03.02.021.01` エージェントが操作できる API・構造化インターフェース(MCP 等)の提供
- `Q03.02.021.02` エージェント経由アクセスの識別と制御(許可・レート制限)
- `Q03.02.021.03` 画面変更がエージェント連携を壊さないための安定した接点の提供
