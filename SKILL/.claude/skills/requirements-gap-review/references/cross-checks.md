# 品質・業務・変更の横断分析

品質項目を個別に満たしていても、組合せで目的を満たせなくなる。対象となる業務の不変条件と実際の構成に結び付け、次の組合せを使って反例を探す。

## 項目を掛け合わせる軸

主体・代理・組織 × 機能・チャネル × 業務状態 × データ状態 × 許可条件 × 結果・副作用 × 時間・競合 × 外部依存 × 品質副特性 × ライフサイクル × 既存契約 × 故障・誤用を候補とする。全直積ではなく不変条件に影響する組合せを明示的に選ぶ。

| 横断する観点 | 反例を探す問い | 主な品質領域 |
|---|---|---|
| 権限×出力経路 | UIで隠した本文がAPI、件数、CSV、通知、要約、ログに出ないか | 機能完全性、機密性、責任追跡性 |
| 権限変更×時間×キャッシュ | 判定時と取得時、発行済みURL、検索索引で旧権限が残らないか | 機能正確性、機密性、真正性 |
| 最大件数×認可×並び順 | 先に切り捨てて必要な候補を失わないか。最大と必要最低件数を混同していないか | 機能正確性、容量、適切性 |
| 更新×ページング×同順位 | ページ送り中の更新と同値ソートで欠落・重複しないか | 正確性、相互運用性 |
| 再送×応答消失×副作用 | 成功後のタイムアウトで再送し、請求・通知・登録が二重にならないか | 正確性、耐障害性、責任追跡性 |
| 非同期化×受付・完了×取消 | 受付を完了と表示していないか。取消後に遅延処理が確定しないか | 操作性、自己記述性、信頼性 |
| 締め×遅着×訂正 | 月跨ぎ・遡及データ・再集計で適用期や合計が変わらないか | 正確性、相互運用性、回復性 |
| マスタ改定×過去データ | 税率・単価・組織・資格の現行値を過去取引へ誤適用しないか | 正確性、適応性、責任追跡性 |
| 削除×保持×復元 | 削除対象が索引・バックアップから復活しないか。必要な証跡も失わないか | 完全性、機密性、否認防止性、回復性 |
| 一括処理×部分失敗×再実行 | 成功行の再処理、失敗行の修正、結果通知、ロールバックが整合するか | 完全性、正確性、回復性 |
| 性能×整合性×鮮度 | キャッシュや非同期集計による遅延を業務が許容できるか | 時間効率性、正確性、自己記述性 |
| 大量出力×共有資源 | 出力一件がDB接続・メモリを占有して主要業務や隣接システムを止めないか | 資源効率性、共存性、容量、可用性 |
| 自動再試行×障害×費用 | 再試行の集中・回復直後の一斉実行・AI呼出しが二次障害や費用増を起こさないか | 耐障害性、資源効率性、耐攻撃性 |
| スケールアウト×ローカル状態 | セッション、ロック、採番、冪等キーがノード間で共有されず意味が変わらないか | 拡張性、正確性、真正性 |
| 監査×プライバシー×性能 | 証跡の必要粒度を満たしつつ機密・個人情報の過剰記録や容量枯渇を避けられるか | 責任追跡性、機密性、容量 |
| 可用性×安全状態 | 継続と停止のどちらが安全か。縮退で認可や安全機能を省いていないか | 可用性、フェイルセーフ、運用制約性 |
| 警告×抑止×障害 | 通知経路停止、無期限ミュート、警告集中で重大事象が見えなくならないか | 危険警告性、可用性、解析性 |
| 安全情報×統合×遅延 | 単体では安全でも時刻ずれ・単位違い・古い値で統合先が危険動作しないか | 統合時安全性、相互運用性、正確性 |
| 入力補正×文字多様性 | 自動正規化・氏名制限・IME処理で正当なデータを変えたり拒否したりしないか | 正確性、包摂性、エラー防止性 |
| セッション×入力保持×共有端末 | 作業継続のための保持データが再認証や別利用者への交代後に漏れないか | 操作性、真正性、機密性 |
| UI変更×支援技術×説明 | モーダル、フォーカス、動的状態、翻訳、ヘルプと実画面が一致するか | 支援性、習得性、適応性、自己記述性 |
| 便利さ×判断の主導権 | 自動確定、既定値、通知、解約導線、AI提案が意図しない行動を誘わないか | 適切性、エラー防止性、利用者関与性 |
| 新旧混在×スキーマ×展開順 | 新しい書込みを旧読込が処理できるか。旧ジョブ・古いイベントを新実装が扱えるか | 相互運用性、設置性、可用性 |
| 切戻し×切替後データ | バイナリを戻しても新データ・新状態が旧系で処理できず復旧不能にならないか | 修正性、置換性、回復性 |
| インストール×共有環境 | PATH・レジストリ・ランタイム変更、ポート・ファイル占有が他製品を壊さないか | 設置性、共存性、適応性 |
| 共通化×利用元×契約差 | 似た処理でも変更理由が異なる機能を統合し、個別ルールを失っていないか | 再利用性、モジュール性、修正性 |
| 障害調査×再現性×権限 | 相関ID・時刻・設定版がなく再現不能でないか。調査用機能が越権経路にならないか | 解析性、テスト可能性、機密性 |
| 移行×業務停止×教育 | データが移っても、権限・帳票・手作業・習得が不足して業務が止まらないか | 置換性、完全性、習得性 |
| AI更新×品質×説明 | モデル・プロンプト・RAG更新で精度・公平性・権限境界・再現性が変わらないか | 正確性、包摂性、信頼性、テスト可能性 |
| AI自動操作×権限×停止 | 不正な参照文、過剰な権限、停止後の待機ジョブで無許可の操作が続かないか | 耐攻撃性、責任追跡性、フェイルセーフ |

## 組織固有の期待を追加する

カタログ外も `ORG-*` などのIDで登録し、発見元と適用条件を残す。

- 部門間の受渡し時刻、締め後の責任、権限委譲・不在代理、例外承認の実際の慣行。
- 運用が手修正・Excel・目視で補っている条件、その作業量と担当者の交代可能性。
- サポート受付時間、調査時の情報、問い合わせID、復旧連絡、顧客説明の約束。
- 契約プランごとの機能・上限・データ返却、個別顧客との約束、段階移行・終了条件。
- 旧形式・旧帳票・特殊データを使い続ける利用者、連携先が暗黙に頼る順序・命名・周期。
- 証跡・承認・変更管理、委託先との責任分界、社内の例外承認、引継ぎが必要な判断。
- 実施可能な試験環境、業務ピークを含むデータ、再現できない状態、外部組織が握る前提。

組織の開発責任が広い場合、「要求書にない」「開発の外側にある」で除外せず、確認先を特定する。調査・エスカレーション責任と、要件採用や実装責任は分けて記載する。

## 組合せの記録

| 組合せID | 元の観点ID・対象 | 不変条件と根拠 | 操作列・境界・障害 | 現状と期待の差 | 指摘／判断事項／未検証 |
|---|---|---|---|---|---|

同じ指摘へ複数IDが対応してよい。安全性・保守性などを他分野の大きな見出しへ吸収してIDを失わない。今回発見した条件は、要求・要件・仕様・実装・検証のどの層に不足があるかまで戻して判定する。
