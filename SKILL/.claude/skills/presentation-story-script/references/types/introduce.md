# 紹介：聞き手に試してもらう・申し込んでもらう発表

製品やサービスの紹介、展示会のセミナー、ウェビナー、営業の場での説明、採用説明会やチーム紹介に使う。
発表の後に聞き手にしてほしいことは、資料請求、無料トライアルの申し込み、商談の予約、社内での導入検討の開始、
採用説明会なら応募やカジュアル面談の申し込みである。

## 聞き手と始点

聞き手は、紹介するものをまだ使っていない人である。
売り込まれることを警戒しながら、「自分に関係があるか」を判断して聞いている。
そのため、紹介するものの機能を順に説明するだけでは、聞き手が自分との関係を感じる前に、注意が離れやすい。

始点の「△△だと思っていた」には、次のようなものが多い。

- 今のやり方で何とかなっている。困っているのは自分たちの頑張りが足りないからだ。
- 問題の原因は、別のところ（人の怠慢、予算、季節）にある。
- 似たものは前に試したが、うまくいかなかった。

この型では、売り込みへの警戒をほどくfunnyも、紹介するものが必要な理由を納得させるinterestingも、
聞き手に行動を起こしてもらうための手段として両方使う。

## 展開の段階

次の8つの段階で進めると、funnyとinterestingを置く場所と、それぞれの役割を決めやすい。
この並びは、Andy Raskinが紹介した営業資料の構成を下敷きにしている。
その構成は、世の中の大きな変化を示し、目指す状態を見せ、製品をその状態に至るための手段として出し、最後に証拠を示す。
そこに、Nancy Duarteが示した「現状」と「ありうる姿」を行き来させる考え方と、笑いと興味の置き場所を加えた。
段階の名前と数は目安であり、持ち時間や聞き手に合わせて、まとめたり省いたりしてよい。

| 段階 | 聞き手の頭の中 | 入れるもの | ヘルプデスクの例（仮） |
| --- | --- | --- | --- |
| 1. 掴み | この話は自分に関係があるか | interesting：答えたくなる問い。funny：あるある | 「今年いちばん多かった問い合わせは何でしょう」と予想してもらう |
| 2. 変化の提示 | なぜ今この話なのか | interesting：否定しにくい変化 | 社内で使うツールが増え、どこに聞けばよいか分かりにくくなった |
| 3. 今のやり方の限界 | 確かに困っている | funny：誇張したあるある | 2位は「これってどこに聞けばいいですか」 |
| 4. 原因の見直し | そういうことだったのか | interesting：見方の転換 | 社員は病名ではなく症状で話す |
| 5. 目指す状態 | そうなるといい | 実現した後の一日の具体的な描写 | 社員が自分の言葉で聞けば、答えか担当者にたどり着く |
| 6. 製品の登場 | どうやって実現するのか | 機能を、障害ごとの解決策として出す | 言い換えを理解して答える。答えられなかった質問からFAQの候補を作る |
| 7. 証拠 | 本当にできるのか | interesting：その場で確かめられるデモ | 「家から社内に入れない」と入力すると、VPNの接続手順が出る |
| 8. 回収と行動 | 次に何をすればいいか | funny：冒頭の回収。次の一歩を一つに絞る | 「どこに聞けばいいですか」への答えを示し、無料トライアルを案内する |

## 時間の配分

時間の配分は、紹介するものの説明に偏らないようにする。
20分の枠なら、仮に、段階1〜3に5分、段階4に3分、段階5〜6に5分、段階7に5分、段階8に2分といった配分になる。
段階1〜4は製品がまだ出てこないが、聞き手が「この製品が必要だ」と感じる理由はここで作られる。
ここを短くして機能の説明を長くすると、聞き手は必要性を感じないまま機能を聞くことになる。

10分以下の枠では、段階2と3、段階5と6をまとめる。
それでも段階4（原因の見直し）と段階8（回収と行動）は残す。
段階4がないと製品が必要な理由が弱くなり、段階8がないと聞き手が次に何をすればよいか分からなくなるためである。

## 段階ごとの考え方

### 1. 掴みは聞き手の世界の話から始める

紹介の発表は、会社紹介や自己紹介から始まることが多い。
しかし、聞き手はまだ関心を持っていないため、話し手の会社の情報は、この時点では聞き手と関係がない。
最初の1分は、聞き手が毎日経験していることについての問いか、あるあるから始める。

問いを出したら、間を置いて、聞き手に頭の中で予想してもらう。
自分の予想を持った聞き手は、答えが自分の予想と合っているかを確かめたくなり、答えを待つ理由ができる。
ヘルプデスクの例では、「今年いちばん多かった問い合わせは何でしょう。パスワードの再設定でしょうか」と問いかけて、間を置く。
手を挙げてもらう依頼と自己紹介は、台本に入れない。

### 2・3. 変化と限界で、今のやり方を続けにくくする

段階2では、聞き手のせいではなく、世の中や業界で起きた変化として、今のやり方が合わなくなった理由を示す。
「あなたのやり方が悪い」と言われると、聞き手は自分のやり方を守ろうとして身構える。
一方、「環境が変わった」と言われれば、聞き手は自分を否定されずに、やり方を変える理由を受け取れる。
この前置きがあることで、段階3で今の状況を笑っても、聞き手自身を笑うことにならず、笑いが無害なものになる。

掴みから段階2に移るときは、黙って世の中の変化の話を始めない。
掴みで出した問いや笑いと、これから話す変化がつながることを、先に言う。
ヘルプデスクの例では、「実は、その答えには、ここ数年の、職場の変化が関わっています」と言ってから、ツールが増えた話をする。
世の中の変化の話は、聞き手には題材と関係のない前置きに聞こえやすいので、つながりを言わないと、聞き手は聞き流すか戸惑う。

段階3では、今のやり方の限界を、聞き手が経験しているあるあるとして、少し誇張して描く。
聞き手が笑うのは、その状況を自分も経験していると認めたときである。
そのため、笑いが起きたかどうかは、聞き手が痛みを自分のこととして受け取ったかどうかの目安になる。
ヘルプデスクの例では、問い合わせランキングの2位として「これってどこに聞けばいいですか」を見せる。
問い合わせ窓口に「どこに聞けばいいか」を聞いているというずれが笑いになり、同時に、問い合わせ先が分かりにくいという限界も伝わる。

### 4. 原因の見直しをストーリーの山にする

段階4は、interestingの中心である。
答えを出す前に、「FAQを充実させても問い合わせが減らないのはなぜか」と問い、聞き手に少し考えてもらう。
聞き手の多くが「社員がFAQを読まないから」と考えているところで、別の原因を示す。
ヘルプデスクの例では、「患者は病名ではなく症状で話す」という類似を使う。
社員は「VPN 接続 手順」ではなく「家から 社内 入れない」と探すが、FAQは「VPN接続手順」という管理者の言葉で書かれている。
社員は調べていないのではなく、自分の言葉で調べて見つからなかったので、問い合わせているのである。

原因の見直しは、製品の考え方につながっていなければならない。
原因が「社員の怠慢」なら、対策は社員への周知や教育になり、この製品は必要ない。
原因が「言葉のずれ」なら、社員の言葉とFAQの言葉をつなぐ仕組みが必要になり、それがこの製品の役割になる。
このように、意外な原因が製品の必要性を導くとき、interestingは紹介の役に立つ。
製品につながらない意外性は、聞き手に雑学として楽しまれても、行動にはつながらない。

### 5・6. 製品は目指す状態への手段として出す

製品を出す前に、段階5で、問題が解決した後の状態を具体的に描く。
目指す状態を先に見せておくと、聞き手は「どうやって実現するのか」と考え、段階6の機能の説明をその答えとして聞く。
目指す状態を見せずに機能を並べると、聞き手にとって機能は仕様の一覧にしかならない。

段階6では、機能を一つずつ、段階3と4で示した障害に対応させて出す。
ヘルプデスクの例では、「言葉のずれ」に対して「社員の言い換えを理解して答える機能」を出す。
「FAQに載っていない質問がある」に対しては、「答えられなかった質問を担当者に回し、その質問からFAQの候補を作る機能」を出す。
障害に対応しない機能は、この場では説明しないか、資料に回す。
この段階では分かりやすさを優先し、笑いは控えめにする。
作り手の実際の失敗談が依頼文か資料にあれば、「開発チームも最初はFAQを増やせば減ると思っていた」のように、
聞き手と同じ勘違いを作り手もしていたと示す形で入れる。
笑いと同時に、作り手が問題を理解しているという信頼も生まれる。
実際の失敗談がなければ、入れない。

### 7. 証拠はその場で確かめられる形にする

証拠は、導入企業の事例、数字、デモで示す。
中でもデモは、聞き手が自分の目で確かめられるため、interestingの効果が大きい。
ヘルプデスクの例では、聞き手に「家からつながらないとき、何と検索しますか」と聞き、出てきた言葉をそのまま入力する。
聞き手は、自分の言葉でも答えが出るかを確かめたくなり、答えが出たときに段階4の主張を自分で確かめたことになる。
会場の回線や想定外の入力でデモが失敗することもあるため、録画したデモを予備として用意しておく。

事例の数字は、導入前の状態、期間、対象の規模といった条件と一緒に示す。
「問い合わせが減った」という結果だけでは、聞き手は自社でも同じ結果になるかを判断できない。
聞き手が自社の状況と比べられる条件が付いていると、数字は判断の材料になる。

### 8. 最後に冒頭を回収し、次の一歩を一つに絞る

最後は、冒頭の問いや段階3の笑いに戻って締める。
ヘルプデスクの例では、「これってどこに聞けばいいですか、という質問に、来年からはツールが答えます」と締める。
質疑応答の後に、回収の一言と次の行動の案内をもう一度置く。
次の行動は一つに絞り、QRコードや申し込み先など、その場で行動できる手段を示す。
資料請求、トライアル、商談、メルマガ登録を同時に頼むと、聞き手はどれを選ぶかで迷い、どれもしないことがある。

## 紹介するものが組織や人のとき

採用説明会やチーム紹介では、紹介するものが製品ではなく、組織や仕事になる。
段階は同じ並びで使い、中身を次のように読み替える。

| 段階 | 読み替え |
| --- | --- |
| 変化の提示 | 聞き手の職種や業界で起きている変化（求められる仕事の変化など） |
| 今のやり方の限界 | 聞き手が今の職場や転職活動で経験しているあるある |
| 原因の見直し | 聞き手が「働きやすさ」や「成長」の理由だと思っているものの、別の見方 |
| 目指す状態 | 入社した後の、ある一日の具体的な描写 |
| 製品の登場 | 仕事の進め方、制度、チームの決まりごとを、聞き手の悩みに対応させて出す |
| 証拠 | 社員の実際の言葉、数字、実際の画面や成果物 |

社員の言葉を引用するときは、本人の許可を取る。
在籍する社員や、前の職場の人を笑いの対象にしない。

## funnyとinterestingの比重

funnyとinterestingを両方使う。
funnyは段階1、3、8に多く置き、段階6と7は落ち着いて話す。
interestingの山は段階4に置き、段階7のデモでもう一度確かめさせる。
聞き手に役員や決裁者が多い場、安全や信頼が重視される分野では、funnyを段階3と8に絞る。

## 起きやすい失敗

| 失敗 | 起きる理由 | 直し方 |
| --- | --- | --- |
| 会社紹介から始まる | 話し手が話す順番を、聞き手の関心ではなく自分たちの資料の順で決めている | 会社紹介は、聞き手の判断に要る分だけを、段階6で製品を出すときに短く言う |
| 掴みの後に、黙って変化の話を始める | 段階の並びに沿って書き、掴みと変化の提示のつながりを言っていない | 掴みで後に回した答えや問いを受け、変化とつながることを先に言ってから話す |
| 機能を全部説明する | 機能の数が多いほど価値が伝わると考えている | 段階3と4の障害に対応する機能だけを出し、残りは資料に回す |
| 原因の見直しが製品とつながらない | 意外な話を、聞き手を驚かせるためだけに選んでいる | 見直した原因から、製品の役割が導けるかを確かめる |
| 頼む行動が複数ある | 取りこぼしを減らそうとして、全部を並べている | 一つに絞り、その場で行動できる手段を付ける |
