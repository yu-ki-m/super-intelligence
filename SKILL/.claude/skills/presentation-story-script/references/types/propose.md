# 提案：聞き手に決めてもらう発表

社内の企画提案、予算や人員の申請、方針やルールの変更の提案、顧客に導入の判断を求める場、投資家へのピッチに使う。
発表の後に聞き手にしてほしいことは、承認する、予算を付ける、試行を許可する、次の検討の場を設ける、といった判断である。

## 聞き手と始点

聞き手は、提案を決める立場の人（決裁者）と、決裁者に意見を言う立場の人である。
決裁者は、多くの案件を限られた時間で判断しており、
「この提案を通すと何が良くなり、何が危ないか」「今決めなければならないか」を考えながら聞いている。
紹介の型の聞き手と違い、決裁者は判断するために集まっているので、何を決めてほしいかを隠されると、判断の材料を集めながら聞けない。

始点の「△△だと思っていた」には、次のようなものが多い。

- 今のやり方で大きな問題は起きていない。
- 問題は知っているが、原因は別のところ（人の頑張り、見積もりの甘さ、一時的な事情）にある。
- 必要かもしれないが、今やる理由がない。費用や手間に見合わない。

人は、変えることより今のままでいることを選びやすい傾向（現状維持バイアス）が知られている。
決裁者にとって最も選びやすい選択肢は「今回は見送る」なので、
提案は、見送った場合に何が起き続けるかを、決裁者が比べられる形で示す必要がある。

## 展開の段階

提案の型は、紹介の型と同じく「現状」と「目指す状態」を行き来させる。
違いは、決めてほしいことを最初に言うこと、他の選択肢（何もしないことを含む）と比べること、
危険と小さな始め方を話し手から先に示すことである。
段階の名前と数は目安であり、持ち時間に合わせて、まとめたり省いたりしてよい。

| 段階 | 聞き手の頭の中 | 入れるもの | テスト自動化の提案の例（仮） |
| --- | --- | --- | --- |
| 1. 掴み | 何を決めさせられるのか。自分に関係があるか | 決めてほしいことを一言で言う。interesting：決裁者が自分の数字で予想できる問い | 「今日お願いしたいのは、3か月の試行の承認です。その前に質問です。前回のリリースが遅れた10日のうち、開発が遅れた日は何日だったと思いますか」 |
| 2. 変化の提示 | なぜ今この話なのか | interesting：否定しにくい変化 | リリースの回数が年4回から月1回に増えた |
| 3. 放っておいた場合の損失 | 確かに放っておけない | funny：現場のあるある（状況を笑う）。interesting：比べられる形にした数字 | 「手作業のテストは3日かかります。3日目に見つかった不具合を直すと、また1日目からやり直しです」 |
| 4. 原因の見直し | そういうことだったのか | interesting：見えていなかった原因。ここから提案の必要性が導ける | 遅れた10日のうち、開発の遅れは2日で、残りの8日はテストの待ちとやり直しだった |
| 5. 提案と目指す状態 | 何をして、どうなるのか | 実現した後の具体的な描写 | 回帰テストの主要な30項目が、毎晩自動で流れる。不具合はその翌朝に分かる |
| 6. 選択肢の比較 | 他のやり方ではだめなのか | 何もしない場合を含めて比べる。interesting：見送った場合の損失 | 見送る、テスト担当を増やす、自動化を試す、の三つを、費用と効果で比べる |
| 7. 危険と小さな始め方 | 失敗したらどうなるのか。本当にできるのか | 危険を先に言い、試行の範囲と止める条件を示す。証拠になる小さな実験の結果 | 対象を30項目に絞った3か月の試行。2か月目にやり直しの日数が減っていなければ止める |
| 8. 回収と決めてほしいこと | 何を、いつまでに決めればいいのか | funny：冒頭の回収（控えめに）。決めてほしいことを一つにし、期限を言う | 「次のリリースでは、3日目に1日目へ戻らなくて済むようにしたいと思います。3か月の試行を、今月中に承認いただけますか」 |

## 時間の配分

10分の枠なら、仮に、段階1に1分、段階2〜3に2分、段階4に1分30秒、段階5に1分30秒、
段階6に1分、段階7に2分、段階8に1分といった配分になる。
決裁者が最も気にするのは段階6と7なので、ここを削らない。
5分以下の枠では、段階2と3、段階5と6をまとめ、段階4と段階7と段階8は残す。

## 段階ごとの考え方

### 1. 掴みで、決めてほしいことを先に言う

決裁者は、何を判断するための話かが分からないと、聞きながら判断の材料を集められない。
そのため、最初の一言で決めてほしいことを言う。
結論を先に言っても、「なぜそれが必要なのか」「本当にうまくいくのか」という空白は残るので、interestingは働く。
続けて、決裁者が自分の管轄の数字で予想できる問いを出すと、聞き手は答えを待つ理由を持つ。
問いは、決裁者が答えを間違えても恥をかかないものにする。
人前で予想が外れることを嫌う決裁者もいるので、手を挙げてもらうより、「何日だと思いますか」と問いかけて間を置く程度にする。

### 2・3. 変化と損失で、見送りにくくする

段階2では、紹介の型と同じく、聞き手のせいではない変化として、今のやり方が合わなくなった理由を示す。
決裁者の判断や、その部下の働き方を責める形にすると、聞き手は今のやり方を守ろうとして身構える。

段階3では、今のやり方を続けた場合の損失を、決裁者が比べられる形で示す。
金額、日数、人の時間など、決裁者が普段使っている単位に置き換える。
funnyは、現場で起きている状況や手順のおかしさを笑う形にする。
「3日目に見つかった不具合を直すと、また1日目からやり直し」は、手順のおかしさが笑いになり、同時に遅れの仕組みも伝える。
テスト担当者や開発者を笑う形にすると、決裁者の部下を笑うことになる。

### 4. 原因の見直しから、提案の必要性を導く

段階4は、interestingの中心である。
決裁者が考えている原因（見積もりが甘い、人が足りない）の裏に、別の原因があることを、数字や具体的な一件で示す。
見直した原因は、提案の中身につながっていなければならない。
原因が「見積もりが甘い」なら、対策は見積もりの研修になり、テストの自動化は必要ない。
原因が「テストの待ちとやり直し」なら、テストの時間を短くする仕組みが必要になり、それが提案の役割になる。

### 5・6. 提案は目指す状態への手段として出し、他の選択肢と比べる

提案の中身を出す前に、実現した後の状態を具体的に描く。
目指す状態を先に見せると、決裁者は提案の中身を「その状態に至る手段として妥当か」という基準で聞ける。

段階6では、提案を、何もしない場合と、他に考えられるやり方と並べて比べる。
決裁者は、話し手が他の選択肢を検討したかどうかを見ている。
比べる観点（費用、効果が出るまでの期間、危険、元に戻せるか）を揃えると、決裁者は自分の基準で選べる。
提案だけを示すと、決裁者は他の選択肢を自分で考え始め、質疑がそちらに流れやすい。

### 7. 危険は話し手から先に言う

決裁者は、提案の危険を探しながら聞いている。
話し手が先に危険と対策を言うと、隠していないという信頼が生まれ、質疑が「やるかどうか」から「どう進めるか」に移りやすい。
大きな判断を一度に求めるより、範囲と期間を絞った試行と、止める条件を示す方が、決裁者は決めやすい。
小さく試した結果や、他社や他部署の先行事例があれば、ここで証拠として示す。
数字には、期間、対象の規模、比べる前の状態を付ける。

### 8. 決めてほしいことを一つにし、期限を言う

最後は、冒頭の問いや段階3の状況に戻って締め、決めてほしいことをもう一度言う。
「ご検討ください」で終えると、決裁者は何をいつまでに決めればよいか分からない。
「3か月の試行を、今月中に承認いただけますか」のように、判断の中身と期限を言う。
複数の判断を一度に求めない。
質疑応答の後にも、決めてほしいことを一言でもう一度言う。

## funnyとinterestingの比重

interestingを中心にし、funnyは控えめにする。
決裁者が多い場では、笑いが多いと提案まで軽く見られることがある。
funnyは段階3の状況のおかしさと、段階8の回収に絞る。
話し手自身の失敗談（「私も最初は見積もりのせいだと思っていました」）は、
決裁者と同じ勘違いを話し手もしていたと示せるので、笑いと同時に、問題を理解しているという信頼も生まれる。

## 起きやすい失敗

| 失敗 | 起きる理由 | 直し方 |
| --- | --- | --- |
| 提案の中身から話し始める | 話し手の関心が、提案の中身の正しさにある | 決めてほしいことを一言で言った後、必要性を作る段階2〜4を先に話す |
| 費用だけを示して効果を比べられない | 費用は数字にしやすいが、効果は数字にしにくい | 効果を、決裁者が使う単位（日数、金額、人の時間）に置き換える |
| 何もしない場合を示さない | 提案が最善だと考えているので、比べる必要を感じていない | 見送った場合に起き続ける損失を、提案と同じ観点で並べる |
| 「ご検討ください」で終わる | 決めてほしいことを強く言うと押し付けになると考えている | 判断の中身と期限を一つに絞って言う |
| 現場の人を笑う | 現場の状況を笑うつもりが、人の失敗談になっている | 笑う対象を、手順や仕組みのおかしさにする |

## 下敷きにした考え方

- Barbara Mintoのピラミッド原則と、状況（Situation）・複雑化（Complication）・問い（Question）・答え（Answer）の順で導入を組む考え方：決めてほしいことを先に言い、その理由を後から支える
- 現状維持バイアス（William SamuelsonとRichard Zeckhauserが名付けた）：人は今のままでいることを選びやすいという傾向
- 紹介の型の8つの段階（types/introduce.md）：「現状」と「目指す状態」を行き来させ、原因の見直しを山にする並び
