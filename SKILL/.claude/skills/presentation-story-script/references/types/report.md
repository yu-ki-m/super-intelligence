# 報告：聞き手に状況を分かってもらい、判断や支援につなげる発表

プロジェクトの成果報告、試行の結果報告、進捗報告、振り返りの共有、調査結果の発表、障害の報告に使う。
発表の後に聞き手にしてほしいことは、結果を正しく理解したうえで、次の判断をする、支援する、
同じやり方を自分のチームに広げる、といったことである。

## 聞き手と始点

聞き手は、結果が良かったのか悪かったのかを最初に知りたがる。
そのうえで、「自分は何をすればいいか」「この結果は信用できるか」を考えながら聞いている。
報告は事実を伝える場なので、interestingは作り込むより、結果の中にある「予想と違ったこと」から取る。

始点の「△△だと思っていた」には、次のようなものが多い。

- 始める前に、聞き手自身が持っていた予想（うまくいかないだろう、相談が減るだろう）。
- 結果の原因についての思い込み（担当者が頑張ったから、たまたまだ）。
- 自分たちのチームには関係のない話だ。

## 展開の段階

報告の型は、結果の要点を先に言い、予想と違ったことを空白として残す。
良し悪しを隠して引っ張ると、聞き手は中身より結果の推測に気を取られ、報告全体を疑いながら聞くことになる。
結果の要点を先に言っても、「なぜそうなったのか」「予想と違ったのは何か」という空白は残るので、interestingは働く。
段階の名前と数は目安であり、持ち時間に合わせて、まとめたり省いたりしてよい。

| 段階 | 聞き手の頭の中 | 入れるもの | 定例会議を減らした試行の例（仮） |
| --- | --- | --- | --- |
| 1. 掴み | うまくいったのか。何の話か | 結果の要点を一言で言う。interesting：予想と違ったことが一つあると予告する | 「定例会議を週5回から週2回に減らした3か月の結果を報告します。困ったことは起きませんでした。一つだけ、予想と違うことがありました」 |
| 2. 目指していたこと | 何と比べた結果なのか | 目標と、始める前の予想。聞き手も同じ予想をしていたことを確かめる | 会議の時間を減らして作業の時間を増やす。心配は、チームの相談が減ること |
| 3. 結果 | どのくらい良かったのか、悪かったのか | interesting：目標、前の期間、他のチームと比べられる数字 | 会議の時間は週3時間減った |
| 4. 予想と違ったこと | なぜそうなったのか | interesting：予想と違った結果と、その原因の見直し。funny：予想が外れた話し手自身や、仕組みのおかしさ | 相談の件数は、減るどころか1.5倍に増えた。「毎朝の定例で、いちばん多かった発言は『特にありません』でした」 |
| 5. 学んだこと | 何が分かったのか | 具体的な一件から原則へ | 相談は決まった時間ではなく、困ったときに起きる。定例は、相談を翌朝まで待たせる場になっていた |
| 6. 次の打ち手 | これからどうするのか | 学んだことに対応する次の打ち手 | 残りの週2回は、決めることがある議題だけにする |
| 7. 回収とお願い | 自分は何をすればいいのか | funny：冒頭の回収。お願い（判断、支援、広げること）を一つにし、期限を言う | 「来月から、隣のチームでも『特にありません』を減らしてみませんか。試行の許可をお願いします」 |

## 時間の配分

10分の報告なら、仮に、段階1に1分、段階2に1分、段階3に2分、段階4に2分30秒、段階5に1分30秒、段階6に1分、段階7に1分といった配分になる。
経緯を時系列で話したくなるが、聞き手が知りたいのは経緯より、結果と、予想と違ったことと、自分がすることである。
経緯は、段階4の原因を説明するのに必要な部分だけを話す。
5分以下の報告では、段階2と3、段階5と6をまとめる。

## 段階ごとの考え方

### 1. 掴みで結果の要点を言い、予想と違ったことを予告する

報告で結果を最後まで隠すと、聞き手は「結局どうだったのか」が気になって、途中の説明を聞けない。
そのため、最初の一言で結果の要点を言う。
続けて「一つだけ、予想と違うことがありました」と予告すると、聞き手は答えを待つ理由を持つ。
予告した「予想と違ったこと」は、段階4で必ず答える。

### 2・3. 目指していたことと結果を、比べられる形で示す

結果の数字は、何と比べるかが分からないと、良いのか悪いのかを判断できない。
目標、始める前の値、前の期間、他のチームなど、比べる相手を先に示してから結果を言う。
数字には、期間と対象の規模を付ける。

悪い結果を後ろに回したり、言葉を弱めたりしない。
後で気づいた聞き手は、報告全体を信用しにくくなる。
悪い結果ほど先に、数字のまま言い、その後に原因と打ち手を話す。

### 4. 予想と違ったことをストーリーの山にする

段階4は、interestingの中心である。
聞き手が段階2で持っていた予想（相談が減るだろう）を、結果で外す。
答えを言う前に「相談の件数は、どうなったと思いますか」と問い、聞き手に一度予想してもらう。
外れた理由（原因の見直し）が、段階5の学んだことと、段階6の打ち手につながっていなければならない。

funnyを入れるなら、予想を外した話し手自身か、仕組みのおかしさを笑う。
「毎朝の定例で、いちばん多かった発言は『特にありません』でした」は、会議という仕組みのずれを笑い、同時に、定例が相談の場になっていなかったことを伝える。
特定の参加者の発言や振る舞いを笑いの材料にしない。

### 5・6. 学んだことと次の打ち手

学んだことは、具体的な一件を示してから、原則として言う。
聞き手が自分のチームに当てはめられるように、どの条件なら同じことが起きそうかも言う。
次の打ち手は、学んだことに対応させて出す。

### 7. お願いを一つにし、期限を言う

報告は「以上です」で終わりやすい。
しかし、聞き手は報告を聞いた後に何をすればよいかが分からないと、聞いた内容を判断に使えない。
最後に冒頭の予想や段階4の笑いに戻り、聞き手へのお願い（判断、支援、広げること）を一つ、期限と一緒に言う。
お願いがない報告（共有だけの報告）でも、聞き手が次にすること（質問を送る先、資料の場所）を一つ示す。

## 障害や損害の報告

障害、事故、失注など、損害を受けた人がいる出来事の報告では、funnyを入れない。
報告の聞き手は、影響と対策を判断するために聞いており、そこで笑いを入れると、話し手が事態を軽く見ていると受け取る。
技術発表やLTのように、自分の失敗から得た知見を共有する場で笑いをどう扱うかは、
story-principles.md の「笑いを入れるときの作法」にある。
interestingは、段階4の原因の見直し（なぜ防げなかったのか、なぜ気づくのが遅れたのか）に置く。
原因は、個人の不注意ではなく、仕組み（確認の手順、監視の項目、引き継ぎの方法）として扱う。
個人の責任として話すと、聞き手は再発防止策を、その人が気をつけることとしか受け取れない。
冒頭では、影響の大きさと、今の状態（復旧したか、まだ続いているか）を先に言う。

## funnyとinterestingの比重

interestingを中心にし、funnyは控えめにする。
funnyは段階4と7に置き、話し手自身の外れた予想や、仕組みのおかしさを使う。
interestingの山は段階4に置き、段階1の予告で空白を作る。
障害や損害の報告では、funnyを入れない。

## 起きやすい失敗

| 失敗 | 起きる理由 | 直し方 |
| --- | --- | --- |
| 経緯を時系列で全部話す | 起きた順に話すのが正確だと考えている | 結果の要点を先に言い、経緯は原因の説明に必要な部分だけにする |
| 数字を比べる相手がない | 話し手は前の値を知っているので、言わなくても分かると感じている | 目標、前の値、他のチームなど、比べる相手を先に示す |
| 良い結果だけを話す | 悪い結果を言うと評価が下がると考えている | 悪い結果を先に数字のまま言い、原因と打ち手を続ける |
| 「以上です」で終わる | 報告は伝えれば終わりだと考えている | お願いか、聞き手が次にすることを一つ言う |
| 担当者個人を笑う、または責める | 出来事の原因を人に求めている | 原因を仕組みとして扱い、笑う対象は仕組みと話し手自身にする |

## 下敷きにした考え方

- 紹介の型の段階と、情報ギャップ理論：結果を先に言っても、予想と違ったことを空白として残す
- 振り返りで、原因を個人ではなく仕組みとして扱う考え方：再発防止策を、仕組みの変更として受け取ってもらうため
