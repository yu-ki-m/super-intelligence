# 話し言葉の台本の書き方

台本は、話し手が声に出して話し、聞き手が耳で聞いて理解するための文章である。
目で読む文章は、読み手が読み返したり、表を見比べたりできる前提で書かれている。
耳で聞く聞き手は、聞き逃した文に戻れず、記号や括弧や表の区切りも聞こえない。
そのため、台本はスライドや資料の文章をそのまま使わず、耳で聞いて分かる話し言葉で別に書く。

## スライドと台本の役割を分ける

スライドは見せるもの、台本は話すものとして、別に書く。
スライドの文を読み上げると、聞き手は耳で聞く文と目で読む文を同時に追うことになり、どちらにも集中しにくくなる。

表、細かい数値の一覧、URL、QRコード、コード、コマンド、ファイル名は、台本で読まない。
何のためのものか、そこから何が分かるかを、言葉で言う。
細かい数字は、見る場所を案内する。

- スライド「https://example.com/trial」
  台本「申し込みは、右下のQRコードからできます。」
- スライド「導入企業3社の比較表（業種、従業員数、導入前後の問い合わせ件数）」
  台本「3社とも、問い合わせが3割ほど減りました。」「業種と規模の違いは、表にまとめてあります。」

台本とスライドを矛盾させない。
台本で言う数字、条件、名前は、スライドと同じにする。
台本でだけ言って、スライドにない数字を出すときは、出典と条件を台本の中で言う。

## まとまりの最初に、何の話かを言う

耳で聞く聞き手は、話の向きが分からないと、続く文を聞き取りにくい。
段落やスライドの最初の文で、問い、答え、場面のどれを話すのかが分かるようにする。

- 「ここで、一つ質問です。」
- 「答えは、言葉のずれでした。」
- 「ある月曜日の、ヘルプデスクの様子です。」

ただし、問いで引っ張る場面（掴み、原因の見直し、予想と違った結果）では、答えを先に言わない。
問いを先に言い、答えは〔間〕の後に言う。
最初に言うのは、そのまとまりが問いであることまでである。
テーマが変わる所では、何の話かを言う前に、前の話とのつながりも言う（次の節）。

## テーマを切り替えるときは、黙って切り替えない

段階が変わる所や、同じ段階の中で話題が変わる所で、前の話に触れずに次の話を始めると、
聞き手はなぜ話が変わったのかが分からず、落ち着かないまま次の話を聞くことになる。
スライドを切り替えても、話が変わった理由は聞き手に聞こえない。
テーマを切り替える所では、話す言葉で次の三つを順に言う。

| すること | 言う中身 | ヘルプデスクの例（仮） |
| --- | --- | --- |
| 前の話を締める | 前の話で分かったことを一文で言う。問いを出した後なら、その問いに触れる | 「ツールが増えると、困ったときに、どこに聞けばいいかが分かりにくくなります。」 |
| つながりを言う | 次の話に移る理由を、前の話とつなげて言う。「だから」「ところが」「では、なぜ」が入る形にする | 「では、そんな職場に、実際にどんな問い合わせが届いているのか。」 |
| 次の話を告げる | 次のまとまりが、問い、場面、答えのどれなのかを言う | 「最初の質問の答えです。」 |

段階の切り替わりでは、三つを合わせて二、三文で言う。
同じテーマの中でスライドを替えるだけの所では、つながりの一文でよい。
長い振り返りを毎回入れると、話が重くなる。

「本題の前に」「さて」「ところで」「話は変わりますが」「次に」「続いて」「もう一つ」は、話が変わることは伝えるが、変わる理由は伝えない。
これらで次の話を始めるときは、すぐ後に、前の話とのつながりを言う。

- 理由がない：「さて、次は、社内のツールの数です。」
- つながりを言う：「実は、その答えには、ここ数年の、職場の変化が関わっています。」

自己紹介やお礼のように、話の途中に挟む一言も、テーマの切り替わりである。
問いを出してから答えるまでの間には挟まない。
聞き手は答えを待っているので、そこで名乗りが入ると、問いがどこへ行ったのか分からなくなる。
挟むときは、答えを後に回すと言った後のような話の区切りに置き、名乗る文の中で、直前の話と話し手の関わりを言う。

- 関わりがない：「申し遅れました。」「〇〇株式会社の〇〇です。」
- 関わりを言う：「申し遅れました。」「この問い合わせを減らすツールを作っている、〇〇です。」

名乗りでチームや部署の名前を出すときは、何をしているチームかも言う。
チームの名前は社内の言葉なので、別の部署の聞き手には、名前だけでは何のチームか分からない。

- 名前だけ：「〇〇チームの〇〇です。」
- 何をしているかも言う：「社員の問い合わせに答える仕組みを作っている、〇〇チームの〇〇です。」

聞き手に問いを出したり、手を挙げてもらったりした後は、その問いに触れてから次の話に移る。
触れずに次の話を始めると、聞き手は、自分の答えが何に使われるのか分からないまま置いていかれる。
反応を決めつける言い方（「半分くらいですね」）は書けないので、問いを短く言い直すか、「その答え」のように指して、次の話とのつながりを言う。

意図して話を飛ばし、聞き手に「どうした？」と思わせるときも、黙っては飛ばさない。
前の話を締めてから飛び、飛んだ直後に、前の話とつながることだけを言う。
つながり方は、同じ段階の中で明かす。

- 「急に何の話かと思われたかもしれません。」「でも、この話が、問い合わせが減らない理由につながっています。」

## 一文を短くし、一文で一つのことを言う

書き言葉のように「〜し、〜であり、〜のため、」とつなげた長い文は、聞き手が主語と述語の対応を覚えきれない。
文を切り、前から順に言う。

- 書き言葉「本ツールの導入により、問い合わせ件数は導入前比で約3割削減され、担当者の対応時間も大幅に短縮された。」
  話し言葉「このツールを入れた会社では、問い合わせが3割ほど減りました。」「入れる前と比べて、です。」「担当者が答えるのに使う時間も、その分減っています。」

名詞の前に長い修飾を付けない。
「社員が自分の言葉で探しても見つからなかったので問い合わせてくる質問」は、
「社員は、自分の言葉で探します。」「でも、見つかりません。」「だから、問い合わせてきます。」のように分ける。

主題を先に言う。
「原因は、〜です。」「今日お願いしたいのは、〜です。」のように言うと、聞き手は文の最初で何の話かが分かる。
読点は、話し手が息継ぎをする場所に打つ。

## 聞き手が判断に使うことを、声でも省かない

数字の条件（比べる前の状態、期間、規模）と、仮の値であることは、スライドに書いてあっても声で言う。
声だけを聞いた聞き手が、確定した数字や、自分の会社でも同じになる数字だと誤解しないようにするためである。

- 「仮に、1日15件、1件5分とすると、毎日75分です。」
- 「従業員800人の会社で、半年間の平均です。」

一度に言う数字は、一つか二つにする。
それ以上は、スライドの表で見せる。
話し言葉にするときに削ってよいのは、聞き手の判断に要らない細かさだけである。
注意点、例外、できないこと、悪い結果は省かない。

## 聞き手が知らない前提は、初めて出る所で言う

耳で聞く聞き手は、知らない言葉が出ても、聞き返すことも、調べることもできない。
意味を推測している間にも話は進むので、その言葉を使った主張の根拠を聞き逃す。
Markdownの「聞き手に説明する前提」の表にある前提は、台本の中で、初めて出る所で説明する。
後で説明すると、聞き手はそれまでの話を、分からないまま聞いたことになる。
問いに要る前提は、問いの前に説明する。
前提を知らない聞き手は、予想を立てられないからである。

説明では、辞書のような定義より、その発表の中で何を指すのかを言う。
先に中身を言い、名前は後に付けると、聞き手は名前を聞いた時点で、それが何かを分かっている。

- 定義だけ：「回帰テストとは、ソフトウェアの変更が既存の機能に影響していないかを確認するテストです。」
- 中身を先に言う：「リリースの前には、毎回、前から動いていた機能が壊れていないかを、手で確かめています。」「この確認を、回帰テストと呼んでいます。」「今は、これに3日かかります。」

「これを〜と呼んでいます」と名前を付ける言い方は、聞き手が初めて聞く言葉にだけ使う。
聞き手の業界で一般に使われている言葉に使うと、聞き手は知らない人として扱われたと感じる。
上の例でも、事業部長に向けて「回帰テスト」には名前を付けているが、「リリース」は説明していない。

一度名前を付けたら、最後まで同じ名前で呼ぶ。
「回帰テスト」「リグレッション」「確認の作業」のように呼び方を変えると、聞き手は別のものの話だと受け取る。
一度しか出ない前提には、名前を付けずに中身だけを言う。
覚える名前が増えるほど、聞き手が追うものが増えるからである。

説明は一、二文にする。
それより長くなる前提は、この発表に本当に要るかを見直し、要るなら、展開の中で時間を取って話す。

立場の違う聞き手が混ざる場では、一部の聞き手だけが知らない言葉も、全員が知らない言葉と同じように、はっきり説明する。
知っている人に遠慮して、説明を名前の前の修飾にまぎれさせると、知らない人には説明として聞き取れない。
耳で聞く聞き手は、修飾の部分を聞いている間は、それが後に来る名前の説明だと分からないからである。

- 修飾にまぎれる：「24時間見張っているミハリが、止まりました。」
- はっきり言う：「システムが止まっていないかを、24時間見張っている仕組みがあります。」「社内では、ミハリと呼んでいます。」「このミハリが、止まりました。」

説明は一、二文で済ませ、「ご存じない方のために」のように、知らない人を名指しする前置きは付けない。
知っている人にとっては、短い確認として聞き流せる長さである。

聞き手の業界で一般に使われている言葉は、説明しない。
業界の中で職種を問わず通じる言葉と、仕事をする人なら誰でも使う言葉がこれに当たる。
厳密な定義を言えなくても、おおよその意味が分かっていれば、聞き手は話を追える。
ニュースや他社の人とのやりとりでも説明なしで使われている言葉は、特定の職種から出た言葉でも説明しない。
「リリース」「バグ」は説明しないが、「プルリクエスト」は、開発の人以外がいれば説明する。
社内の言葉は、社内に向けた発表でも説明する。
入ったばかりの人や別の部署の人には通じないことがあり、部署によって指すものが違うこともあるからである。
ヘルプデスクの例の聞き手（社員からの問い合わせに答えている担当者）に、「VPN」が何かを説明する必要はない。
同じ話を社員に向けてするなら、「VPN」ではなく「家から社内のシステムに入るための仕組み」と言う。
ただし、社員に向けた話でも、「ログイン」「パスワード」は説明しない。
説明を足して台本が長くなったときは、説明を削らずに、聞き手の判断に要らない細かさを削る。

## 話し言葉の言い回しにする

文末は「です・ます」を基本にする。
LTや社内の気軽な場では、場に合わせて崩してよいが、一つの台本の中では揃える。

書き言葉の言い回しを、話し言葉にする。

| 書き言葉 | 話し言葉 |
| --- | --- |
| しかしながら | でも、ところが |
| したがって | なので、だから |
| 〜であり、 | 〜で、 |
| 〜し、 | 〜して、（または文を切る） |
| 〜することが可能です | 〜できます |
| 〜と考えられます | 〜だと思います、〜のようです |
| 当該の、本件の | この、今回の |

聞き手への呼びかけと問いかけを入れる。
「皆さんの職場では、どうでしょう。」のように、聞き手が自分の場合を思い浮かべるきっかけにする。

聞き手にしてほしいこと（手を挙げる、予想を言う、チャットに書く、試す、承認する）は、言葉ではっきり頼む。

- 「パスワードだと思う方、手を挙げてください。」
- 「3か月の試行を、今月中に承認いただけますか。」
- 「明日、ログを一つ選んで、それで答えたい問いを一つ書き出してみてください。」

聞き手の反応で変わる一言は、どちらに転んでも使える言い方にする。
手が多く挙がっても少なくても使える「ありがとうございます。」のような言い方にし、「半分くらいですね」のような、反応を決めつける言い方を書かない。

英字や数字は、普通の表記で書く。
台本は話し手が目で読んで話すものなので、読みがなに直さない。

## ト書きを話す言葉と分ける

話す言葉以外は、行の最初から最後までを〔 〕で囲み、別の行に書く。
話し手が誤って読み上げないようにし、後で話す言葉だけを取り出せるようにするためである。

| ト書き | 書く場所 |
| --- | --- |
| 〔スライド：見せる内容〕 | スライドを切り替える場所。見せる内容を短く書く |
| 〔間〕 | 問いの後、笑いを狙ったセリフの後、大事な一言の前後 |
| 〔手を挙げてもらう〕〔チャットに書いてもらう〕 | 聞き手の反応を待つ場所 |
| 〔デモ：約3分〕〔ワーク：約8分〕 | 話す言葉以外に時間がかかる場所。時間を書く |
| 〔笑いが起きたら待つ〕 | 笑いを狙ったセリフの後。笑いが起きなくても、そのまま次に進む |
| 〔動作：画面を指す〕 | 話し手の動作 |

時間がかかるト書きには、「約3分」「約30秒」のように時間を書く。
scripts/render_html.py が、台本の長さの目安に足す。

## 笑いのセリフの書き方

ずれ（オチ）は文の最後に置く。
日本語は文末まで聞かないと意味が決まらないので、ずれを最後に置くと、聞き手が予想を立てた後に外れる。

- 「1位は、パスワードの再設定。」「2位は、『これってどこに聞けばいいですか』でした。」

三つ目でずらすときは、一つ目と二つ目を同じ形の短い文にする。
形が揃うほど、三つ目のずれがはっきりする。

オチの後に説明を足さない。
〔間〕を置き、次の話に進む。
外れたときの言い直しや、「今のは冗談です」のような言葉は台本に書かない。

笑いのセリフも、情報を運ぶようにする。
笑いが起きなかったときも、話が先に進むようにするためである。
「2位は『これってどこに聞けばいいですか』」は、笑いが起きなくても、問い合わせ先が分かりにくいという事実を伝える。

## 問いの書き方

問いは、聞き手が自分の経験から答えられそうなものにする。
問いの後に〔間〕を書く。
聞き手が考える時間であり、話し手がすぐに答えると、聞き手は考えるのをやめる。

答えを言う場所で、問いをもう一度短く言ってから答える。
問いと答えの間に別の話が入ると、聞き手は問いを忘れているからである。

- 「最初にお聞きした、今年いちばん多かった問い合わせ。」「答えは、〜です。」

## 台本の長さ

日本語を人前で話す速さは、1分あたり300字前後が目安とされる。
台本の話す言葉の文字数を、持ち時間から、デモや聞き手の反応を待つ時間を引いた残りに合わせる。
仮に、20分の枠で、デモに5分、反応を待つ時間に1分かかるなら、話す言葉は14分ほどで、文字数にして4,200字前後になる。
早口になりやすい話し手や、オンラインで聞き取りにくい場では、もう少し少なくする。

質疑応答の時間が持ち時間に含まれるときは、その時間を先に引く。
質疑の後に置く回収の一言とお願いは、台本の最後の段階に書いておく。

## 台本の書式

台本の節は、次の書式で書く。
scripts/render_html.py がこの書式を読み、HTMLの表にする。

- 段階ごとに「### 段階の名前」の見出しを付ける。名前は、展開の表の段階の名前と同じにする。段階の番号は付けない。
- 1行に1文を書く。
- ト書きは、行全体を〔 〕で囲む。
- スライドを切り替える場所に〔スライド：見せる内容〕を書く。次の〔スライド：…〕までが、そのスライドで話すことになる。
- 意味のまとまりの切れ目には空行を入れてよい。
- 差し替えが必要な箇所は、その行の頭に【仮】を付ける。

## 台本を見直す観点

| 観点 | 確かめる問い |
| --- | --- |
| スライドとの役割 | スライドの文をそのまま読んでいないか。表、URL、コードを読んでいないか |
| 最初の一文 | まとまりの最初の文で、何の話かが分かるか。問いの場面で答えを先に言っていないか |
| テーマの切り替え | 黙ってテーマを切り替えていないか。切り替えの最初の二文までで、前の話を受け、次の話に移る理由と、何の話かを言っているか。問いを出した後、その問いに触れてから次に進んでいるか |
| 文の長さ | 1行に1文になっているか。主語と述語の間に長い修飾が入っていないか |
| 条件と仮 | 数字の条件と、仮の値であることを声でも言っているか |
| 前提知識 | 聞き手が知らない言葉、社内の名前や経緯、仕組みが、説明なしに出ていないか。説明は、初めて出る所と、問いの前にあるか。社内の言葉や、一部の聞き手だけが知らない言葉を、何を指すかを言わずに修飾にまぎれさせていないか。聞き手の業界で一般に使われている言葉まで、「〜と呼んでいます」のように定義していないか |
| 言い回し | 書き言葉の接続や硬い言い回しが残っていないか。文末が揃っているか |
| ト書き | 話す言葉とト書きが混ざっていないか。問いと笑いの後に〔間〕があるか |
| 笑いのセリフ | ずれが文の最後にあるか。オチの後に説明を足していないか |
| 頼む行動 | 聞き手にしてほしいことを、言葉ではっきり頼んでいるか |
| 長さ | 段階ごとの台本の長さが、予定の時間に合っているか |

## 台本の例

ヘルプデスクの例の、掴みから今のやり方の限界までの台本の例である。
内容は説明のための仮のものなので、別の発表には使わない。
言い回しと書式の参考にする。

```
### 掴み
```
