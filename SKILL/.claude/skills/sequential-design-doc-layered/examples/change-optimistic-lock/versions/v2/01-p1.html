1. タスクの更新（PUT /api/tasks/:id）

1.1 処理概要

文書の種類変更設計（基準：現行コード task-api から書き起こした v1）
対象処理タスクを 1 件更新する
種別Web API（同期）
HTTPメソッドPUT
エンドポイント/api/tasks/:id
入力ヘッダー X-API-Key、パス id、ボディ title・status・dueDate
出力200：更新後のタスク（JSON）／ 異常時 400・401・404・409・500
認証API キー（ヘッダー X-API-Key。No.04〜11）
トランザクション明示的な開始なし（SQL は 1 文ごとに確定する〔推定〕）
使用テーブルapi_clients（参照）、tasks（更新）
外部システムなし
起点（根拠）tasks.ts:63-80

1.2 入力項目

{
  "title": "  見積書を送付する  ",
  "status": "DOING",
  "dueDate": "2026-11-20",
  "version": 4
}
項目受け取り位置型必須検証内容（コード上の条件）値の例
X-API-Keyヘッダーstring必須空でないこと（No.05）。SHA-256 が api_clients.key_hash と一致し、失効していないこと（No.08・09）tk_live_7f3a9c…
idパスstring → number必須正の整数（No.13）"42"
titleボディ（JSON）string必須文字列で、前後の空白を除いて空でなく、100 文字以内（No.16・19）" 見積書を送付する "
statusボディ（JSON）string任意TODO・DOING・DONE のいずれか（No.23）。省略時は TODO"DOING"
dueDateボディ（JSON）string / null任意YYYY-MM-DD 形式（No.28）。省略・null は null"2026-11-20"
versionボディ（JSON）number必須正の整数（No.31b）。取得したときの値を送る4
