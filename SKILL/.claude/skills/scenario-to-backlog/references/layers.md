# 段0〜3の書き方と、段の間の点検

## 1. シナリオの洗い出し（段0）

### 1.1 候補の作り方

シナリオは、ある人がある状況に置かれ、何かを達成しようとして、その途中に妨げや懸かっているものがある場面である。1行の作業の説明（「〜が〜する」）や、システムに求める振る舞いの一覧は、シナリオではない。場面が浮かばず、細かくするときに物語の材料にならないため。

候補は、次の4つの要素を1つずつ埋めて作る。どれかが空なら、まだシナリオになっていない。

| 要素 | 書くこと | 例（デモのデータの企画） |
|-|-|-|
| 誰が | 役割と、その人の状態（経験・立場・慣れ） | 展示会を初めて担当する販促担当 |
| きっかけ・状況 | いつ・何が起きて、その場面に入るか。期限や制約 | 来週の展示会で、来場者の業種に合うデモを見せることになった |
| 達成したいこと | その人が得たい成果。機能名・操作ではなく、成果で書く | 客層に合うデータでデモを見せ、商談につなげたい |
| 妨げ・懸かっていること | 何がうまくいかなそうか。うまくいかないと何を失うか | エンジニアに頼むと1日待つ。間に合わなければ、ありあわせのデータで見せることになる |

- 誰がの候補：使う人、管理・運用する人、承認する人、選ぶ・買う人、影響を受ける人。
- きっかけ・状況の候補：初めて、ふだん、急ぎ・期限の前、量が多いとき、失敗したとき・やり直すとき、権限がないとき、やめる・引き継ぐとき。これは種類の目安であり、候補に書くときは「初めて」ではなく、その人がその場面に入る具体的な出来事で書く。

応答の一覧には、4つの要素をつないだあらすじ（1〜2文）を示す。形は「〔きっかけ・状況〕、〔誰が〕は〔達成したいこと〕。〔妨げ・懸かっていること〕」とし、状況から書き始める。状況が先にあると、読んだ人がまず場面を思い描けるため。例：「来週の展示会で業種に合うデモを見せることになった販促担当は、自分でデータを用意して商談につなげたい。エンジニアに頼むと1日待つので、間に合わないかもしれない。」

候補に書かないもの：

| 書き方 | 例 | 直し方 |
|-|-|-|
| 作業の説明だけ（状況と妨げがない） | 研修担当が、振り返りで扱う問題を選ぶ | いつ・何のために選ぶのか、選べないと何が困るのかを足す |
| 行為者がいない | 証拠が足りない問題で、判断を保留する | 誰がその場面にいるのかを主語にする |
| 解決策・システムの振る舞い | 足りない資料と次の調査を示す／7つの要素を揃えて公開する | 利用者が何を得たいかに戻す（「保留した理由を答えとして認めてほしい」）。解決策はユースケースとストーリーの段で考える |
| 起きる出来事だけ（壊しうる） | 生成されたデータが誤っている | 誰が、何をしようとしている途中で、それに出会うのかを書く |

入力に思考ノートがあれば、地図から引き継ぐ。

| 思考ノート | シナリオの洗い出しでの使い方 |
|-|-|
| 課題・価値の輪 | 主シナリオの「何を達成したいか」と「価値とのつながり」 |
| 対象者と場面の輪 | 主シナリオの「誰が・どんな状況で」 |
| 体験の全体 | 状況の候補（初めて・使い続ける・やめる） |
| 分岐点 | 分かれた道ごとのシナリオ。開いている分岐点は、両方を候補に置く |
| 仮置き | `00_進行.md` の「仮置き」の表に引き継ぐ |

### 1.2 種類

| 種類 | 意味 | 例 |
|-|-|-|
| 主 | 価値の中心を届けるシナリオ。多くは1つ | 来週の展示会で業種に合うデモを見せることになった販促担当は、自分でデータを用意して商談につなげたい。エンジニアに頼むと1日待つ |
| 壊しうる | 主シナリオの途中で、利用者を失敗させうる状況に出会う | 前日の夜にデータを用意していた販促担当は、出来上がったデータに実在の取引先の名前が混ざっていることに、会場で気づくかもしれない |
| 運用 | 管理・運用・承認する人が、主シナリオを続けて回すためのシナリオ | 販促担当が自分でデータを作り始めた翌月、管理者は、誰がどの顧客データまで使えるかを決めておきたい。決めないまま使われると、持ち出しの責任が取れない |
| 広げる | 別の対象者・状況へ広げるシナリオ | 商談中に急にデモの条件を変えたくなった営業が、チャットで頼んでその場で見せたい |

「壊しうる」と「運用」は、依頼にも思考ノートにも出てこないことが多い。Claude が見つけて置く。どちらも、起きる出来事や管理の作業だけで書かず、1.1 の4つの要素を持つシナリオとして書く。

### 1.3 細かくする順番

1. 主シナリオ。2つ以上あれば、価値の中心に近いほう。
2. 壊しうるもののうち、起きたときの影響が重いもの。
3. 運用のシナリオ。
4. 広げるシナリオ。

対象外にするシナリオには、理由を書く。後で対象に戻すときの判断材料になるため。

## 2. 物語（段1）

### 2.1 形

```
〔誰（状況で）〕は、〔いつ・どこで・何がきっかけで〕〔何をしたいか・なぜ〕。
〔何をするか〕。〔どこでつまずきそうか、どう感じるか〕。
〔どうなって終わるか（成果）〕。
```

- 5〜10行で書く。具体的に：役割、時刻、期限、件数、使っている道具、周りの人。細部は仮置きでよい。物語の下に「物語の仮置き」として並べる。
- 新しいやり方での物語（あるべき姿）を書く。今のやり方との違いが課題そのものなら、今のやり方の物語も1〜3行添える。
- 機能名・画面名を書かない。利用者の行動と気持ちで書く。機能名を書くと、手段が先に決まり、ほかのやり方を考えられなくなるため。

### 2.2 点検

- 読んだ人が、場面を思い描けるか。
- 課題（思考ノートの課題の輪、または候補の一覧の「価値とのつながり」）につながるか。
- 終わりに、成果があるか。
- 主語が利用者か。システムが主語になっていないか。

## 3. 体験の流れ（段2）

### 3.1 形

| 時期 | すること | 接点（画面・人・紙・通知など） | 気持ち | つまずき | 機会 |
|-|-|-|-|-|-|

- 時期の分け方：きっかけ → 準備 → 実行 → 確かめる → 終わった後（共有・振り返り・次回）。使い始めることが中心のシナリオなら：知る → 初めて使う → 価値を実感する → 使い続ける。
- つまずきごとに、機会（どう良くできるか）を書き、ID を付ける（S1-機1）。手を付けないなら、対象外として理由を書く。
- 画面の外の接点を入れる：問い合わせ、上司への確認、紙、メール、ほかの人への受け渡し。
- 気持ちは、谷（不安・面倒・焦り）を特に書く。谷は、ユースケースの例外の流れや、支えになる手順の材料になる。

### 3.2 点検

- 物語のつまずき・気持ちの谷が、表にあるか。
- 表の行が、物語から来ているか。物語にない行が要るなら、先に物語を直す。
- つまずきのすべてに、機会か対象外（理由）があるか。

## 4. ユースケース（段3）

### 4.1 形

```
### ユースケース：〔動詞で終わる名前。例：デモのデータを準備する〕

- 主体：
- 関係者（人・システム）：
- 前提：
- きっかけ：
- 正常の流れ：
  1. 〔主体〕は〜する。（S1-1）
  2. 〔システム／相手〕は〜を示す。（S1-2）
- 代わりの流れ：
  - S1-2a 〔条件〕のとき：〔流れ〕→〔どこに戻るか／どう終わるか〕
- 例外の流れ：
  - S1-2x 〔条件〕のとき：〔流れ〕→〔どこに戻るか／どう終わるか〕
- 終わりの条件：
  - 成功：〔観察できる状態〕
  - 失敗・中断：〔観察できる状態〕
- 決まりごと（業務のルール）：
- 機会の行き先：S1-機1 → S1-3、S1-機2 → S1-2a
- 対象外（理由）：
```

- 手順は「誰が何をする」を1行に1つ書く。利用者の行動と、システム・相手の応答を交互に書く。画面の部品（ボタン名など）は書かない。
- 手順は3〜9個を目安にする。多ければユースケースを分け、少なければ粒度が粗すぎないかを見る。
- 終わりの条件は、観察できる状態で書く（「適切に完了する」ではなく「デモ環境に、指定した件数のデータが入っている」）。受入条件のもとになるため。

### 4.2 例外の観点

手順ごとに、次を一通り見る。該当しないものは「該当なし：〔観点〕」と1行にまとめて書き、見たことを残す。

- 入力の誤り・不足
- 権限がない・範囲の外
- 対象が見つからない・空
- 外部の仕組みが止まっている・遅い
- 途中でやめる・中断して後で再開する
- 取り消す・やり直す
- 同時に別の人が同じものを操作する
- 量が多い・期限ぎりぎり
- 結果が誤っている（生成AI を使うなら特に）
- 二重に実行する
- 通知・連絡が届かない

### 4.3 点検

- 体験の流れの機会のすべてに、行き先（手順・代わり・例外の流れ）か対象外（理由）があるか。
- 手順のすべてが、物語か体験の流れで説明できるか。
- 例外の観点を一通り見たか。
- 終わりの条件が、成功・失敗の両方で観察できる形か。

## 5. 段の間の点検

段を終えるとき、両方向で点検する。下向きは漏れ（上の段にあるのに、下の段に落ちていない）、上向きは根拠のないもの（下の段にあるのに、上の段に元がない）を見つける。

| 段の間 | 下向き（漏れ） | 上向き（根拠のないもの） |
|-|-|-|
| 洗い出し → 物語 | 順番の上位のシナリオに、物語がある | 物語の主人公と目的が、候補の一覧にある |
| 物語 → 体験の流れ | 物語のつまずき・気持ちの谷が、表にある | 表の行が、物語から来ている |
| 体験の流れ → ユースケース | 機会のすべてに、行き先か対象外（理由）がある | 手順が、物語か体験の流れで説明できる |
| ユースケース → ストーリーマップ | 手順・代わり・例外の流れのすべてに、ストーリーか対象外（理由）がある | ストーリーが、手順か代わり・例外の流れを由来に持つ |
| ストーリーマップ → バックログ | マップのストーリーが、すべてバックログにある | バックログのストーリーが、すべてマップにある |

上の段にないが要るものが、下の段で見つかったら、上の段に足してから下の段に書く。これを省くと、なぜ要るのかを説明できないストーリーが残る。
