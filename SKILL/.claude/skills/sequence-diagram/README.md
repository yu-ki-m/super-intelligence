# sequence-diagram スキル

ソースコード・設計書・処理仕様・自然言語の説明から、エンタープライズ Web アプリケーションの処理を
**メソッド単位のライフライン**で正確に追跡したシーケンス図を作り、操作できる**単一ファイルの HTML ビューア**として出力する
Claude Code 用スキル。

- 図の描画は Mermaid（公式構文のみ）。日本語のフラグメント名・色分け・クリック操作は、描画後の SVG への後処理で付与する。
- 解析結果は「処理モデル（JSON）」として保存され、Mermaid と HTML はスクリプトがそこから機械的に生成する。
- すべての呼び出し・DB 操作・分岐・例外にソースの行番号（根拠）を付け、確認済み／推定／未確認を区別して表示する。

## 使い方

Claude Code で次のように依頼する（スキル名を言わなくても、シーケンス図・処理の流れの可視化の依頼で起動する）。

```
/sequence-diagram src/main/java/.../OrderController.java の POST /api/orders の処理をシーケンス図にして
```

```
docs/処理仕様書_返品.md の返品受付処理を、DB アクセスと例外の流れがわかるシーケンス図にしてください
```

```
会員登録 API（NestJS）の処理の流れを可視化したい。メール送信がキュー経由なのでそこも含めて
```

Claude は次の 5 段階で作業し、`sequence-diagrams/<名前>/<名前>.html` を出力する。

| 段階 | 内容 | 主な成果 |
|---|---|---|
| Phase 1 解析 | 起点から呼び出しを深さ優先で追跡。実装解決・AOP・ORM・イベント等の暗黙処理も確認 | 根拠行つきの事実（大規模なら台帳 `.analysis.md`） |
| Phase 2 モデル化 | ライフライン・呼び出し・引数・戻り値・分岐・例外・DB 操作・TX・ロックを構造化 | `<名前>.model.json` |
| Phase 3 Mermaid 生成 | モデルの検証、根拠行の照合（ファイル・行範囲・メソッド名）、Mermaid 生成 | 検証結果、`.mmd`（任意） |
| Phase 4 HTML 生成 | Mermaid・ビューア・モデル・ソース抜粋を 1 ファイルに埋め込み | `<名前>.html` |
| Phase 5 品質検証 | ヘッドレスブラウザで全図を描画し、対応付け・文字の重なりを検査、スクリーンショット確認、ソースとの再照合、独立レビュー | 検証レポート |

手作業で使う場合（Node.js 18 以上）：

```bash
S=.claude/skills/sequence-diagram/scripts
node $S/seqdiag.cjs init     out/order.model.json         # 雛形
node $S/seqdiag.cjs validate out/order.model.json         # 検証と根拠の照合
node $S/seqdiag.cjs build    out/order.model.json -o out/order.html
node $S/seqdiag.cjs verify   out/order.html --screenshots out/shots --full
```

## ビューアの操作

画面構成：上部にヘッダーとツールバー、左に図一覧（全体図→詳細図の階層）とアウトライン、中央に図、右に詳細パネル。

| 操作 | 方法 |
|---|---|
| 詳細を見る | メッセージ（矢印・文字）、ライフライン、枠の見出し、注記をクリック。引数表・戻り値・SQL・根拠のソース抜粋（VS Code で開くリンク付き）・分岐の文脈が表示される |
| 関連の強調 | ライフラインをクリックすると、その送受信メッセージだけを強調（他は薄く）。メッセージを選ぶと呼び出しと戻りの対を強調 |
| 順に追う | ↑ / ↓（または k / j）で前後のメッセージへ |
| 検索 | `/` で検索欄へ。メソッド名・処理名・テーブル名・条件・SQL・引数名で全図を横断検索。Enter / Shift+Enter で次 / 前へ移動 |
| 拡大・縮小 | ＋ / − ボタン、Ctrl + ホイール、`+` `-` `0` キー。「全体表示」(F)、「幅合わせ」(W) |
| 移動 | スクロール、または図の余白をドラッグ。下へスクロールするとライフライン名（メソッド名／クラス名の 2 段）が上部に固定表示される。大きな図では右下のミニマップ（全体の縮図と表示範囲）をクリック・ドラッグして移動 |
| 全体図⇄詳細図 | 「詳細参照：…」の注記をクリック、図一覧、パンくず、ブラウザの戻る。詳細パネルから「この図の中で展開」も可能 |
| 折りたたみ | 「▶ … （集約）」の注記をクリックで展開。表示設定から一括展開／折りたたみ |
| 表示設定 | 戻り値の矢印、引数名、分岐の条件式、補助的な自己メッセージ、クラス単位への集約、レイヤーの囲み |
| 保存 | SVG / PNG / Mermaid（.mmd）/ 処理モデル（JSON） |
| パネル | ☰（Alt+1）でナビ、右上のボタン（Alt+2）で詳細パネルの開閉。パネル幅はドラッグで変更 |
| 検証 | ヘッダーの「検証OK / 警告」チップ → 検証タブ。モデルの検証結果と、表示の自己検証（対応付け・文字の重なり）を表示 |

URL で状態を指定できる：`#d=<図ID>&s=<ステップID>`（共有用）、`?diagram=<図ID>`、`?theme=dark`、`?zoom=1`、`?verify=1`（全図の自己検証）。

## 図の表記

| 表現 | 意味 |
|---|---|
| 実線・塗り矢じり（濃紺） | 同期メソッド呼び出し |
| 点線・塗り矢じり（灰） | 戻り値 |
| 実線・開いた矢じり（紫／桃） | 非同期呼び出し・メッセージ送信／イベント発行 |
| 点線・開いた矢じり（紫） | コールバック・非同期処理の完了通知 |
| 緑の矢印 | DB アクセス（`SELECT：在庫を取得 ［FOR UPDATE］` など） |
| 赤い点線・× | 例外の送出・伝播 |
| 枠：◇条件分岐／?条件付き実行／↻繰り返し／∥並列処理／■排他処理／⤓処理中断／⚡例外処理 | Mermaid の alt / opt / loop / par / critical / break と、try-catch から生成した alt。色と線種で区別し、条件文は見出しのすぐ右に表示 |
| 青い背景帯＋「TX開始」「COMMIT」 | トランザクションの範囲（参加するライフラインの範囲だけに表示）。赤い「ROLLBACK」注記は例外が境界を抜けた時点の取り消し |
| 黄色の背景帯＋「finally」 | 例外の有無に関わらず実行される処理 |
| 「詳細参照：…」（青い注記） | 別の図に分割した処理（クリックで移動） |
| 〔推定〕〔未確認〕 | コードで直接確認できなかった内容 |
| ライフラインの色 | レイヤー（Controller・Service・Repository・DB・外部など）。DB は角丸、キューは破線、外部は点線の枠 |

詳しい規約は `references/notation.md`。

```
sequence-diagram/
├── SKILL.md                    Claude 向けの手順（5 段階のワークフロー）
├── README.md                   このファイル
├── references/
│   ├── analysis-guide.md       Phase 1：ソース解析の手順・フレームワークの暗黙処理・根拠の付け方
│   ├── model-schema.md         Phase 2：処理モデル JSON の仕様と生成規則
│   ├── notation.md             Phase 2：どの処理をどの要素で表すか
│   └── quality-checklist.md    Phase 5：検証項目
├── scripts/
│   ├── seqdiag.cjs             CLI（init / validate / mmd / build / verify）。Node.js 18+、依存なし
│   ├── lib/core.cjs            モデルの正規化・検証・Mermaid 生成（CLI とビューアで共用）
│   ├── build_html.py           Node が無い環境用の組み立て（検証なし）
│   └── update-mermaid.cjs      同梱 Mermaid の更新（保守用）
├── assets/
│   ├── viewer/                 template.html / viewer.css / viewer.js（ビューア）
│   └── vendor/                 mermaid.min.js 11.17.2（MIT）と VENDOR.md
└── examples/order-system/      Spring Boot の注文登録処理（ソース 46 ファイル・モデル・HTML）
```

### 設計方針

- **解析と表示の分離**：解析結果は処理モデル（JSON）だけに書く。`core.cjs` がモデルから Mermaid を生成し、`viewer.js` が描画と操作を担う。
  ビューアのデザインを変えても解析結果やモデルに影響しない。モデル項目の追加は `core.cjs` と `model-schema.md` を更新する。
- **Mermaid の正確性を損なわない**：Mermaid テキストは公式構文のみ（エスケープは公式のエンティティコード）。
  日本語化・色分け・クリック判定は描画後の SVG に対して行い、生成時の対応表と `data-et` / `data-id` 属性で要素を対応付ける。
  種別が一致しない場合は日本語化を中止して警告するため、図中の他の文字列を誤って置換しない。
- **自己検証**：ビューアは描画のたびに、対応付けの数・送受信者・表示文字列・文字の重なり・はみ出しを検査する。
  `verify` コマンドはこれをヘッドレスブラウザで全図に対して実行する。
- **根拠の照合**：`build` / `validate` は根拠のファイル・行範囲・参照行に含まれるべきメソッド名／例外名を照合し、誤った行番号を検出する。

### 依存ライブラリ

| 依存 | 用途 | 方針 |
|---|---|---|
| Mermaid 11.17.2（MIT、同梱） | シーケンス図の描画 | バージョン固定。理由と更新手順は `assets/vendor/VENDOR.md` |
| Node.js 18+ | CLI | 標準モジュールのみ使用（npm install 不要） |
| Chrome / Edge / Chromium | `verify` の表示検証 | 既存のブラウザをヘッドレスで起動（Playwright 等は不要） |
| Python 3（任意） | Node が無い場合の HTML 組み立て | 標準ライブラリのみ |

フォントは閲覧環境の日本語フォント（BIZ UDPゴシック、Yu Gothic UI、ヒラギノ角ゴ、Noto Sans JP、メイリオ）を使い、外部から読み込まない。

### 既知の制約

- Mermaid のシーケンス図は、離れたライフライン間の長いラベルの幅をすぐ右隣の間隔として確保するため、ライフラインが多い図は横に長くなる。
  詳細図への分割・クラス単位表示・ラベルの短縮で対処する。
- Mermaid 11.17.2 の database / queue 形状は長い名前でアイコンと文字が重なるため使用していない（通常の箱を色と枠線で区別）。
- 枠の幅が狭いと、条件文が Mermaid によって折り返される（重なりは verify で検出されるが、折り返しは検出されない）。条件文を短くして対処する。
- 同梱版 HTML は約 3.7MB（Mermaid を含むため）。`--mermaid cdn` で約 0.2MB になるが、閲覧にネットワーク接続が必要。
