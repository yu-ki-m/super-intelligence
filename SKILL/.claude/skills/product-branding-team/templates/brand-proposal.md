# ブランド提案

`python pbteam.py export` が `output/brand-proposal.md`（詳細）と `output/summary.md`（要点の1ページ）を書き出す。プロダクトごとに一つ作る。共有された情報だけをまとめ、AIに未入力の情報は未確認とする。要約でも重要な未確認状態や提供条件を消さない。

各シートと、内容の出どころは次のとおりである。該当する作業が実行されていなければ「未実施」と出力する。

| シート | 出どころ |
| --- | --- |
| 1. 対象と今回の検討目的 | 依頼の整理（`brief.json`） |
| 2. 優先する顧客、関係者の役割、選択の場面 | 顧客分析（`customer_analysis`） |
| 3. 顧客の課題・望む状態と確認状況 | 顧客分析と主張の確認状態 |
| 4. 現在の認識と目指す認識 | 採用された戦略（`adopted_strategy`） |
| 5. 代替手段と選択理由の比較表 | 比較（`competitive_comparison`） |
| 6. ブランドの仮説文と選定理由 | 採用された戦略 |
| 7. 主張・根拠・提供条件の対応表 | 根拠と主張の記録 |
| 8. 顧客向けの短い説明と30秒程度の説明 | 短い紹介文（`short_intro`） |
| 9. 接点と利用体験の対応表、改善課題 | 接点表（`touchpoint_matrix`） |
| 10. 実際の反応、AIの解釈、伝え方の修正点 | 資料にある顧客の発言と、AIの評価を別々に示す。顧客確認がなければ未実施と書く |
| 11. 30日間の検証計画と判断基準 | 検証計画（`validation_plan`） |
| 12. 未確認事項、意見の相違、保留事項、未実施工程 | 各成果物の未確認事項、未解決の批判、保留と失敗の作業 |
| 13. 実際の相互討論の記録 | 発言の記録 |
| 14. 批判前後の案の差分と、変更・維持・撤回の理由 | 版の差分と発言の記録 |
| 15. 採用しなかった案の長所と棄却理由、少数意見、推奨を変更すべき条件 | 採用された戦略と候補 |
| 16. 実際に起動した役割、実行した巡、失敗や未実施、終了理由 | 稼働の記録 |
| 17. 依頼範囲の制作物 | 紹介ページ、営業原稿、デモ、FAQ など。計画だけで作成済みとしない |
| 18. 作業台帳と検査結果 | 台帳と検査の記録。完了、保留、失敗、対象外を区別する |
| 19. 稼働実績と人間の介入 | 稼働の記録。50役割のうち何を実施し、何が測定でき、何が未検証かを示す |
| 20. 他業務への引き渡し事項 | 各成果物の `handoffs`。根拠となる顧客価値、現状との差、受入条件 |

## ブランドの仮説文の型

```
【状況】にある【対象】にとって、【製品名】は【カテゴリー】であり、【方法】によって【価値】を提供する。
【代替手段】との比較では【選ぶ理由】があり、その根拠は【証拠】である。
このため、【覚えてほしい認識】として認識されたい。
```

全項目を一文に詰め込む必要はない。内部で判断をそろえるための文章と、顧客向けの短い説明を分ける。

## 接点と体験の対応表の列

接点／顧客が知りたい・したいこと／伝える約束／実際に必要な体験／現状／差分／対応担当・次の行動

## 終了状態の表示

提案の冒頭に、実行方式（実エージェント、模擬、設計のみ）と終了状態（品質契約充足、仮説案の契約充足、資料不足による保留、予算上限による未達、実行失敗、中止）を表示する。完成した内容はブランドの仮説であり、チーム内の合意やAIの評価で需要や差別化が検証されたものではないと明記する。
