# 主張と根拠の対応

`python pbteam.py export` が `output/evidence-register.md` に書き出す。主張と根拠はIDで紐づけ、根拠のない項目は未確認とする。

IDは根拠を後から参照するための識別名である。例えば、主張 C1「担当未定の依頼を画面で確認できる」に対し、根拠 E1「試作品の確認記録」を対応させる。E1 が画面での確認しか示していない場合、C2「対応漏れが減る」の根拠として流用しない。C2 には、確認後の割り当てや対応まで含む別の調査が必要である。「顧客が発言した」という事実と「その発言内容が客観的に正しい」ことも分ける。

## 根拠

| 項目 | 内容 |
| --- | --- |
| 根拠ID | `E1` など。同じ資料の同じ引用は一つにまとめる |
| 種類 | `document_fact`（資料の事実）、`customer_statement`（顧客の発言）、`customer_behavior`（顧客の行動）、`public_web`（公開情報）、`general_knowledge`（一般的な考え方）、`ai_inference`（AIの推論）、`requester_wish`（依頼者の希望） |
| 出所 | 資料IDと版、または URL |
| 箇所、引用 | 資料の文言そのまま |
| 確認日 | 古い競合情報は確認済みの主張の根拠にできない |
| 機械確認 | `quote_found`（引用が資料に実在する）、`url_not_machine_checked`（公開情報で未確認）。実在は裏づけを意味しない |
| 状態 | `current`、`stale`（資料の更新で確認できなくなった） |
| 適用条件 | 主張の成立条件として記録する |

## 主張

| 項目 | 内容 |
| --- | --- |
| 主張ID | `成果物ID#C1` |
| 種類 | 事実、顧客の発言、推論、仮定、判断、約束、数値、需要、顧客の反応、競合、予定、価値、差別化 |
| 確認状態 | `confirmed`（確認済み）、`hypothesis`（仮説）、`unverified`（未確認）、`planned`（予定）、`retracted`（撤回） |
| 対象、利用状況、成立条件 | 誰の、どの状況で、どの条件なら成り立つか |
| 根拠 | 紐づく根拠ID |
| 派生元 | 上流の主張と、関係の種類（参照、要約、推論、方針決定、表現変換） |
| 数値の定義 | 名称、値、単位、期間、母数、測定条件 |

## 機械で拒否される組み合わせ

存在しない資料や引用が見つからない根拠。根拠のない確認済みの主張。実際の顧客の発言や行動の根拠がない、需要や顧客の反応についての確認済みの主張。確認日がない、または1年より古い根拠による、競合についての確認済みの主張。別の製品の根拠。派生元が未確認なのに、根拠を加えず確認済みにした主張（横断検査）。資料の根拠に届かない循環した主張（横断検査）。

同じ資料を複数の担当が引用しても、独立した複数件の証拠にはならない。
