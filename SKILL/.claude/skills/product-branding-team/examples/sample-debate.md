# 架空の討論例

**これは架空の例であり、実行の記録ではない。** 実際の討論の記録は `evals/results/` の実行フォルダーの `output/debate-log.md` にある。この例を実行証跡として使わない。

架空の製品「問い合わせ台帳」について、論点「依頼を見失わないという説明で、現在の方法から変える理由になるか」を討論する。資料には、架空の窓口の観察記録（根拠 E1〜E3）と製品資料（根拠 E4）があるとする。批判によって案が変わる様子と、未解決の問題が両方残る様子を示すための例である。

## 第1巡

**M1　D01（表現担当）→ 全体　提案（案 P1 v1 の主張 C1）**

顧客向けの説明として「依頼を見失わない問い合わせ台帳」を提案する。窓口の担当者が最も困っているのは、依頼がどこにあるか分からなくなることだからだ（E1）。

**M2　P04（製品担当）→ D01　批判・重大（C1 について）**

これは弱い。「見失わない」は、記録と確認の運用が必要なのに自動で保証するように読める。製品ができるのは担当者が記録した依頼を一覧に表示することまでで（E4）、記録されなければ一覧にも出ない。誰かが一覧を確認しなければ、依頼は見失われたままである。求める修正は、記録と確認の条件を説明に入れることだ。

**M3　C02（顧客担当）→ D01　支持（C1 の場面の部分について）**

担当者不在という場面の具体性は残すべきだ。観察記録では、担当者が休んだ日に共有表の更新が止まっている（E2）。場面を特定したことで、履歴の保存が誰の判断に役立つかを説明できている。修正でこの場面を失わないでほしい。

**M4　D01 → P04　応答（M2 への応答：条件を限定する）、案 P1 v2 を提出**

批判を受け入れ、条件を補う。案を「担当者が記録した依頼を、責任者が一覧で確認して割り当てを判断できる問い合わせ台帳。担当者が不在の日も経緯を確認できる」に変える。C02 が指摘した不在の場面は残した。「見失わない」という保証の表現は撤回する。

**M5　P04 → D01　再評価（M2 について：解消）**

条件が明示されたので、自動保証に見える問題は解消した。記録の主語が担当者、確認の主語が責任者になり、製品資料と一致している。

**M6　M03（競争担当）→ D01　批判・重大（P1 v2 の選択理由について）**

変更する理由はまだ弱い。担当者が記録し責任者が確認するなら、既存の共有表の備考欄と担当列でも同じことができる。共有表は追加費用がかからない（E3）。共有表から変える理由が書かれていない。この指摘が解消しなければ、理解されても選ばれない。

## 第2巡

**M7　D01 → M03　応答（M6 への応答：反論）**

共有表は更新が止まる日がある（E2）のに対し、台帳は登録時に対応状況が必ず付くので、未更新の依頼を絞り込める（E4）。これが違いになる。

**M8　M03 → D01　再評価（M6 について：部分解消）**

未更新の絞り込みは共有表のフィルターと条件付き書式でも近いことができるので、機能の差としては弱い。ただ、私は「共有表で同じことができる」と断定したが、共有表の更新が止まる日に誰も気づけないという E2 の点は見落としていた。この点については指摘を撤回する。残るのは、その違いが変更の負担を上回るかである。これは資料からは分からない。

**M9　D01 → 全体　情報不足として保留（M8 への応答）**

変更の負担を上回るかは、顧客の判断であり、追加の討論では分からない。外部確認事項にする。案の選択理由は「更新が止まる日があるなら、未更新の依頼に気づける」という条件付きの主張に留める。

## この例で確認できること

| 発言 | 示していること |
| --- | --- |
| M2 | 根拠のある強い批判。対象と求める修正を示している |
| M3 | 称賛に対象と理由がある。修正時に残す長所を指定している |
| M4 | 批判を受けた修正で、保証の表現を撤回し、長所を維持している |
| M5 | 批判者が応答を読んで解消を判断している |
| M6 | 修正後の案に対する別の観点からの異論 |
| M8 | 批判者が自分の指摘の一部を撤回している |
| M9 | 追加の討論で解消しない論点を外部確認へ送り、未解決として残している |

最終的に案は変わったが、「変える理由が十分か」という問題は未解決のまま残る。この未解決は統合の成果物の `carried_forward` に記録され、検証計画で確かめる対象になる。全員の合意は得られておらず、顧客の需要も検証されていない。
