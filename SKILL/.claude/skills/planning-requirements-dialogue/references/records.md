# 記録の書き方

案件のフォルダ `企画要求/<YYYY_MMDD>_<案件名>/` に、次の4つを置く。書くタイミングは SKILL.md の4.2。

| ファイル | 作り方 | 役目 |
|-|-|-|
| `00_進行.md` | `new_case.py` がひな形 `assets/progress.md` から作る | 再開のための状態 |
| `01_対話記録.md` | 最初の応答のときに Write で作る（形は下） | 対話そのもの。正の記録 |
| `02_分析.md` | 最初に提案書を作るときに、ひな形 `assets/analysis.md` をもとに Write で作る | 段階ごとの分析 |
| `03_提案書.md` | 最初に提案書を作るときに、ひな形 `assets/proposal.md` をもとに Write で作る | 依頼者に示す提案 |

どのファイルでも、確からしさは言葉で書く（〔事実〕〔申告〕〔仮説〕〔提案〕〔決定〕〔未確認〕）。作業用の番号は、対話記録の問いの番号だけにする。ほかのファイルでは、論点・要求・利用シーンを名前で呼ぶ。読む人が番号を引き当てなくても分かるように。

一度できたファイルの書き直しは Edit で、直す箇所だけを置き換える。ファイル全体を書き直さない。時間がかかり、止まったときに中身を失う危険があるため。ただし `00_進行.md` は小さいので、Write で全体を書き直してよい（再開の履歴は消さない）。

## 00_進行.md

- 提案書を作るとき、中断・再開のとき、打合せの結果を取り込むときに書く。毎回は書かない。
- 「分析への反映」は、分析に反映し終えた最後の問いの番号（「問い7まで」）。分析をまだ作っていなければ「まだ」。次に提案書を作るとき、これより後の記録をまとめて反映するため。
- 「次にやること」は、初めて読む人がそれだけで続けられる具体さで書く。例：「対話記録の最後の問い（デモの準備にかかる時間）の答えを受けて、現状の数字を固め、段階3を閉じる」。
- 「段階の進み具合」の状態は、未着手／進行中／済み／仮説で先へ（足りないもの）／省略（ライト）のどれか。
- 「意思決定できる状態か」は、提案書を作るたびに判定し直す。満たしていない条件には、残っていることと、誰が何をすれば満たせるかを書く。
- 「再開の履歴」は消さない。後から、中断の前後で何が起きたかを追えるようにするため。

## 01_対話記録.md

最初の応答のときに、次の形で Write で作る。

```
# 対話記録：〔案件名〕

## 依頼の原文

> 〔相談者が示した原文。改変しない〕

- 出典：〔相談者が貼った文／ファイル名／メール。原文がなければ「相談者による要約」〕
- 受け取った日：YYYY-MM-DD

## 読んだ資料

〔名前・場所・読んだ範囲・分かったこと。読めなかった資料は「読めなかった（理由）」。なければ「（まだない）」〕

## 最初の整理

- 依頼の分解：〔最初の応答で示したもの。確定している依頼、指定された手段、利用シーン、制約、決まっていないこと、依頼者と承認者、動かせない条件〕
- 論点（重要な順）：
  - 〔論点〕（誰に：相談者／依頼者／利用者・現場／資料・ログ。見立て：〔Claude の推奨の答え〕）

## 問いと答え

### 問い1（段階0）
- 問い：
- 聞く理由：
- 見立て：
- 答え：（待ち）
```

- 依頼の原文は、相談者が示したとおりに引用し、改変しない（ガイド T1）。
- 毎回書くのは、このファイルだけ。答えを受けたら、「答え：（待ち）」を答えと記録に置き換え、続けて次の問いを書く。1回の Edit で行う。
- 問いの見出しは「### 問いN（段階M）」とし、日時は書かない（調べるだけで往復が増えるため）。日を改めて再開したことは、`00_進行.md` の再開の履歴で分かる。
- 答えは、相談者の言葉をそのまま「」で書く。要約しない。後で解釈を見直せるようにするため。
- 「記録」は、1つの事柄を1行で書く（確からしさ・中身・分析のどの節に入れるか）。多くても5行ほどにする。長い説明は書かない。毎回の書き込みを短くして、相談者を待たせないため。
- 新しい論点は「→ 未確認：…（誰に）」、依頼者に回すものは「→ 依頼者に確認」と書く。分析を作るまでは、「最初の整理」の論点と、これらの行が、未確認の事項の一覧になる。
- 段階のまとめを示した回は、その問いの後に「### 段階Nのまとめ」を置き、相談者に示したまとめを箇条で書く。分析を作るとき、ここが各節の下書きになる。

答えを受けた後の例：

```
### 問い4（段階1）
- 問い：販促担当は、今デモの準備に1回あたりどれくらいの時間をかけていますか？
- 聞く理由：改善の基準値になるため。これがないと、MCPを入れた効果を数字で示せない。
- 見立て：エンジニアがスクリプトを直して流しており、半日〜1日〔仮説：根拠なし〕。
- 答え：「測ったことはないけど、エンジニアが半日から1日くらい使ってると思う。月に2〜3回」
- 記録：
  - 〔申告：相談者の感覚、測定なし〕準備は1回あたりエンジニアの半日〜1日、月2〜3回 → 分析「作業ごとのベースライン」
  - 〔仮説〕年間のエンジニアの作業は 0.5〜1日 × 2〜3回 × 12か月 = 12〜36日 → 分析「作業ごとのベースライン」
  - → 未確認：実際の準備時間と回数（直近3か月の依頼の記録で数える。相談者、次の打合せまで）

### 段階1のまとめ
- 〔仮説〕事業の目的：来期の重点「生成AI対応」として、12月の展示会で AI 連携を見せる
- 〔申告：相談者〕利用者の目的：販促担当がデモのデータを早く、自分で作れるようにする
- 足りないもの：成功の基準（依頼者に確認）。仮説で段階2へ進む
```

依頼者との打合せの例：

```
### 依頼者との打合せ 2026-10-20（出席：依頼者の企画担当、相談者）
- 内容：「展示会で見せたいのが一番。チャットボットは来年度でいい。予算は決まってない」
- 記録：
  - 〔決定：依頼者、2026-10-20〕最初の利用シーンは展示会のデモの準備。チャットボット経由は来年度 → 分析「優先順位と計画」
  - 〔申告：依頼者〕予算は未定 → 「未確認の事項」の予算の行を更新（誰に：承認者）
  - 覆った仮説：なし
```

## 02_分析.md

- 最初に提案書を作るときに、ひな形をもとに、対話記録（最初の整理、各問いの記録、段階のまとめ）から Write で作る。まだ扱っていない節は「（未着手）」のままにする。ライトのモードで扱わない節は「（ライトのため省略）」にする。ただし、重大なリスクと外部への影響に関わる節は省略しない。
- 2回目からは、直す節だけを Edit で直す。直す節が複数あれば、Edit を1つのメッセージに並べる。
- 各行・各項目に、確からしさを付ける。〔申告〕には発言者、〔事実〕には出典、〔決定〕には決定者と日付を添える。
- 要求は、ガイド5章の記述型（〔主体〕は、〔前提・条件〕において、〔対象〕に〔振る舞い／制約〕を適用でき、その結果〔観測可能な状態〕となること）で書く。システム以外の要求は、状況に合わせて言い換えてよい。要求と、それを満たす設計案を混ぜない。
- 数字は、値・単位・分母・対象期間・対象集団・情報源・算定式・確度を書く。計算した数字は、式と入力値を並べて書く。
- 「未確認の事項」の表が、次の問いの候補の一覧になる。「誰に」が相談者の行から次の問いを選び、依頼者の行は提案書に回す。状態が確認済み・反証済み・対象外（根拠あり）になった行も消さずに残す。何をいつ確かめたかを追えるようにするため。
- 「決定の記録」には、ガイド7.3の項目（論点、選択肢、採用した案、根拠、却下した案と理由、前提、残るリスク、決定者、日付、見直す条件）を書く。
- 20のレンズの表は、見るもの（ガイド4.1）を写さず、判定と理由だけを書く。

## 03_提案書.md

依頼者に示す文書。です・ます調で書く。

- 作業用の番号や記号は書かない。確からしさは、確かめていない前提にだけ〔仮説〕〔未確認〕を付ける。全部に付けると読みにくいため。
- 「1. ご依頼の理解と対応」は、依頼された手段にどう応えるか（何を、どの範囲から作るか）を最初に書く。
- 「2. 目指す成果」の数字は、ガイド6.1の記述型で、根拠の種類（実測・推計・仮定）を必ず書く。現状値が分からなければ、測る計画と、その間の仮の扱いを書く。
- 「4. 選択肢」は、現状維持を必ず含め、同じ条件で比べる。
- 「7. 主な要求」は、種類ごとの見出しの下に並べ、依頼者が言ったものか、分析で見つけたものかを書く。必須の要求には受入条件を付ける。該当がない種類の見出しは消す。
- 「9. 決めていただきたいこと」は、論点ごとに、選択肢・推奨と理由・決まらないと止まること・いつまでに、を書く。問いだけを並べない。
- 「10. 確認させていただきたいこと」は、依頼者が知っている事実と、それが要る理由を書く。
- 「11. 次の進め方」には、次にお持ちするものと、その日程を書く。動かせない期限があれば、そこから逆算した日程（決めていただく期限、確かめる期限、作る期間）を短い表にする。
- 同じ内容を複数の節に書かない。たとえばリスクへの対処が決めていただきたいことでもあるなら、「9.」に書き、「8.」ではそれを指す名前だけを書く。
- 初回の打合せ用は、各節1〜3行に縮め、表は選択肢と日程だけにする（付録Aの1ページの骨子）。使わない節は消す。
