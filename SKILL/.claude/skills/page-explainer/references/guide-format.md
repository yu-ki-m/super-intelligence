# 案内のデータの形

案内は、1 つの JSON にまとめて書く。
`scripts/guide.py inject` は、この JSON を検査してから HTML に埋め込む。
埋め込んだあとは、HTML の中の `<script type="application/json" id="page-explainer-data">` に入っている。
`guide.py extract` で取り出せる。
URL のページを操作しながら解説するライブの案内では、同じ形の JSON に 7 章の項目を足し、HTML には埋め込まずに `scripts/live-tour.mjs` に渡す。

## 目次

1. 全体の形
2. 案内全体の項目
3. 手順の項目

5. 説明のブロック

## 1. 全体の形

```json
{
  "schema": "page-explainer/1",
  "id": "inventory-list",
  "title": "在庫一覧の画面の使い方",
  "summary": "この画面は、倉庫の品物ごとに在庫の数を並べ、注文が必要な品物に印を付けて、その場で注文を出すための画面である。",
  "reader": "この画面を初めて使い、倉庫の在庫を扱ったことがない人",
  "style": "plain",
  "start": "welcome",
  "launcher": { "position": "bottom-right" },
  "chapters": [ { "id": "read", "title": "表を読む" }, { "id": "order", "title": "注文する" } ],
  "steps": [ … ]
}
```

## 2. 案内全体の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `schema` | 必須 | `"page-explainer/1"` |
| `id` | 必須 | 英小文字・数字・ハイフン。ページごとに違う名前にする。ブラウザーに、読み手の進み具合（どこまで読んだか、誘いを出したか）を残すときの名前に使う |
| `title` | 必須 | 案内の題名。目次と、初めて開いたときの誘いに出る |
| `summary` | 必須 | ページが何のためのものかを 1〜2 文で。誘いの最初に出る |
| `reader` | 必須 | 想定した読み手を、名詞の形で書く（句点で終えない）。誘いに「この案内は、〈reader〉に向けて書いている。」と出る |
| `style` | 任意 | `"plain"`（だ・である、既定）か `"polite"`（です・ます）。案内の本文と、吹き出しの決まり文句の文体をそろえる |
| `start` | 任意 | `"welcome"`（既定。そのブラウザーで初めて開いたときだけ、案内への誘いを出す）か `"manual"`（出さない） |
| `launcher` | 任意 | 案内を開くボタン。`label`（1〜10 文字、既定「解説」。依頼者の指示で、どのページでも「解説」のままにする。この案内は、操作の使い方だけでなく、ページに書かれている内容の解説にも使うためである。依頼者が別の文字を指定したときだけ書く）と `position`（`bottom-right` 既定 / `bottom-left` / `top-right` / `top-left`）。`false` にするとボタンを出さない（その場合、ページの側で `pageExplainer.open()` を呼ぶ仕組みが要る） |
| `chapters` | 任意 | 章の一覧（`id` と `title`）。手順が 8 より多いときに付けると、目次で探しやすい |
| `steps` | 必須 | 手順の配列。並べた順に案内する |

## 3. 手順の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 英小文字・数字・ハイフン。案内の中で重ならない名前。質問文に出るので、手順の中身が分かる名前にする（例：`reorder-point`） |
| `title` | 必須 | 手順の題名。部品の名前を、画面と同じ文字で「」に入れると、読み手が画面の中で探せる（例：「『発注点』の列」） |
| `target` | 必須 | 指す部品。部品を指さない手順（ページ全体の説明）では `null`。書き方は 4 章 |
| `targetAll` | 任意 | `true` にすると、`target` に当てはまる見えている要素をすべて囲む（例：ツールバーの 3 つのボタンをまとめて指す） |
| `placement` | 任意 | 吹き出しを置く向きの第一候補（`auto` 既定 / `below` / `above` / `right` / `left`）。置けないときは、ほかの向きに置く |
| `reveal` | 任意 | 部品が隠れているときに、見せるために押す部品の配列（`[{ "click": 部品の指定 }]`）。部品がすでに見えていれば押さない。押してよいのは、タブ・開閉の見出し・パネルの開閉のように、画面の表示を切り替えるだけで、データを変えたり送ったりしない部品だけである |
| `missing` | 任意 | 部品が今の画面に見えないとき（狭い画面で隠れる、別のタブにあるなど）に、吹き出しの上に出す文。部品を見えるようにする方法を書く（例：「画面の幅が狭いときは、左上の『≡』を押すと表示される。」） |
| `chapter` | 任意 | 章の `id` |
| `interactive` | 任意 | `true` にすると、暗幕を出さず、吹き出しを開いたまま、読み手がページを自分で操作できる手順になる（例：自分で検索してみる、自分でログインする）。冒頭の文の下に、そのことを知らせる 1 行が出る。「操作と結果」（`do`）で、何をして、何が起きたら次へ進むのかを書く |
| `levels` | 必須 | 説明の細かさの段の配列（2 段以上）。`levels[0]` が最初に出る説明で、「分からない」を押すたびに次の段へ移る |

段（`levels` の要素）は、次の 2 つの項目を持つ。

| 項目 | 必須 | 内容 |
|---|---|---|
| `added` | 2 段目から必須 | 前の段と比べて、何を足したかを 1 文で書く。吹き出しの題名の下に出る |
| `blocks` | 必須 | 説明のブロックの配列。最初は `summary` |

## 4. 部品の指し方（target）

`target` には、次の 3 つの書き方がある。

| 書き方 | 例 | 使う場面 |
|---|---|---|
| `null` | `null` | ページ全体の説明。吹き出しは画面の中央に出る |
| CSS セレクターの文字列 | `"#order-form"`、`"button[aria-label=\"発注する\"]"`、`"#stock th.reorder-point"` | 部品に id か、ほかと区別できる属性・クラスがあるとき |
| 文字で探す | `{ "selector": "button", "text": "発注する" }`、`{ "selector": "section", "text": "在庫の推移", "nth": 0 }` | id も区別できる属性も無いとき。`selector` の要素のうち、文字（表示の文字・aria-label・placeholder・title・値）に `text` を含むものを探し、入れ子になっているときは内側のものを選ぶ。`nth` は、当てはまるものの何番目（0 から数える）か |

部品の選び方と指し方の決まりは次のとおりである。

- **ページに手を加えない**：部品を指すために、ページの HTML に id や属性を足さない。
  足すと、案内を外しても元のファイルに戻らなくなる。
  指す手段が無いときは、文字で探す書き方を使う。
- **1 つの手順で 1 つの部品を指す**：大きな領域（ページの本文全体、表全体）を指すと、吹き出しを置く場所が無くなり、部品に重なる。
  領域の中の見出しや、1 つの列・1 つの行を指せないかを考える。
  画面全体の役割を説明するときは、`target` を `null` にする。
- **番号での指定を避ける**：`:nth-child(3)` のような指定は、ページの並びが変わると別の部品を指す。
  id・属性・文字での指定を先に考える。
- **候補の一覧を使う**：`node scripts/check-guide.mjs --outline PAGE.html --out DIR` は、指せる部品の候補を、セレクター・文字・位置と、画面の大きさごとに見えるかを添えて一覧にする。
  一覧のセレクターは、ページの中で 1 つに決まることを確かめてある。

## 5. 説明のブロック

各段の `blocks` に、次のブロックを並べる。
吹き出しでは、冒頭の 1〜2 文（`summary`）は札を付けずに強調し、ほかのブロックには種類ごとに札（「前提」「例」など）が付く。
手順を開いた直後は `summary` だけが見え、ほかのブロックは、読み手が「詳細」を押すと開く。
「分からない」で細かい段に切り替えたときは、詳細を開いた状態で出る。
読み手は札を見て、今読んでいるのが前提なのか、例なのかを区別できる。

| `type` | 項目 | 吹き出しの札 | 書くこと | 対応する決まり |
|---|---|---|---|---|
| `summary` | `text` | （札なし。左の線と背景で強調） | 部品が何で、何をするものか（1〜2 文）。各段の最初に 1 つだけ。手順を開いた直後に見えるのは、この文だけである | 1 |
| `premise` | `text` | 前提 | 説明を読む前に知っている必要がある事実 | 6 |
| `term` | `term`, `text` | 言葉の意味 | 1 つの言葉の、この画面での意味。`term` に言葉、`text` に意味 | 2・8 |
| `text` | `text` | （札なし） | 部品の役割・理由・読み方の説明 | 3・4・5 |
| `example` | `text` | 例 | 直前の説明の具体例を 1 つ。このページの実際の値で | 7 |
| `cause` | `title`（任意）, `steps` | なぜそうなるか | 原因から結論までの途中を、1 段ずつ（2 段以上）。番号と矢印でつながって出る | 10 |
| `do` | `action`, `result` | 操作と結果 | 読み手がする 1 回の操作（`action`）と、その結果（`result`。結果を起こす主体を書く）。続けて並べると、番号付きの手順になる | 5・10 |
| `note` | `text` | 注意 | 間違えやすい点、元に戻せない操作、画面によって違う点 | — |

文字の中で使える飾りは、`**太字**` と `` `コード` `` だけである（HTML としては解釈しない）。
画面のボタンや見出しの文字は「」で囲む。

検査（`guide.py validate`）は、ブロックの並びについて次を問題として示す。

- 最初のブロックが `summary` でない。`summary` が 2 つ以上ある。`summary` が 3 文以上ある。
- 案内の文に「つまり」を使っている（依頼者の指示で使わない。「」の中の画面の文字の引用は除く）。
- `example` が無い。`example` が続いている。
- 2 段目以降に `added` が無い。細かい段なのに、文の数が増えていない、または文字の数が 1.1 倍に満たない。
- 「柔軟」「高度」「効率」「最適」「シームレス」「直感的」「スムーズ」を使っている（「」『』`` の中は除く）。
- `term` に 2 つ以上の言葉を入れている。`cause` の段が 1 つしかない。`do` に `result` が無い。

## 7. ライブの案内の項目

ライブの案内（[URL のページを操作しながら解説する](live-tour.md)）では、次の項目を足す。
`start_url` がある案内は、`guide.py inject` で HTML に埋め込めない（`inject` は止まる）。

| 項目 | 置く所 | 必須 | 内容 |
|---|---|---|---|
| `start_url` | 案内全体 | 必須 | 最初に開くページの URL（`http://`・`https://`・`file://`）。案内全体の `start` は使わない（ブラウザーを開くとすぐに手順 1 が出る） |
| `actions` | 手順 | 任意 | その手順を出す前に、`live-tour.mjs` が行う操作の配列。読み手が前の手順で「次へ」を押すと、順に行う。操作の種類は [ライブの案内の 5 章](live-tour.md) にある |
| `url` | 手順 | 任意 | その手順の画面の URL。`start_url` からの相対でもよく、変わる所は `*` にする（例：`ticket.html?id=*`）。確かめるときに、今の URL と合わなければ注意を出す |

操作（`actions` の要素）の項目は次のとおりである。

| 項目 | 内容 |
|---|---|
| `do` | 操作の種類（`click` / `fill` / `select` / `check` / `uncheck` / `press` / `goto` / `hover` / `scroll` / `wait`） |
| `target` | 操作する部品。書き方は 4 章と同じ |
| `value` | `fill` で入れる文字、`select` で選ぶ選択肢（表示の文字か値。複数選ぶなら配列） |
| `key` | `press` で押すキー（例：`Enter`、`Tab`、`ArrowDown`） |
| `url` | `goto` で開く URL |
| `say` | 読み手に見せる、この操作の中身（例：「『検索』の欄に『プリンター』と入れる」）。`hover`・`scroll`・`wait` 以外では必須。前の手順の吹き出しに予告として出たあと、操作の直前に、操作する部分の横の吹き出しに出る |
| `text` / `ms` | `wait` で待つもの（出るまで待つ文字か、待つミリ秒） |
| `timeout` | 部品が出るのを待つ長さ（ミリ秒。既定 15000） |
| `allow_change` | 依頼者が、案内で行ってよいと明示した、データを送る・変える操作にだけ `true` と書く。書かなければ、`guide.py` と `live-tour.mjs` が、その種の操作を止める |
