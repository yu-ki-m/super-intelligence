# URL のページを操作しながら解説する（ライブの案内）

ライブの案内は、依頼者から URL を渡されたときに使う、案内の 2 つ目の形である。
`scripts/live-tour.mjs` が Playwright でブラウザーを開き、開いたページに案内を差し込み、読み手が「次へ」を押すたびに、クリックや入力を自動で行って次の画面へ進み、その画面の部分を解説する。

依頼者は、HTML ファイルを渡したときは HTML に埋め込み、URL を渡したときは Playwright で開いて、開いたページ以外の画面まで操作しながら解説を進めるように指示した。
このファイルは、その 2 つ目の場合の進め方を書く。
説明の文章の決まり（12 の決まり、「詳細」、説明の細かさの段）は、埋め込む案内と同じである。

## 1. 埋め込む案内との違い

埋め込む案内は、1 つの HTML ファイルの中で完結する。
案内のデータとエンジンをファイルに書き込むので、読み手はそのファイルを開くだけで案内を使え、ページを移る操作は扱わない。

ライブの案内は、ファイルを書き換えず、ブラウザーの側で案内を足す。
`live-tour.mjs` は、Playwright の `addInitScript` で、そのブラウザーが読み込むすべてのページに、案内のエンジンと案内のデータを差し込む。
そのため、リンクを押して別のページに移っても、移った先のページにも案内が出せる。
吹き出しの「次へ」は、Playwright の `exposeBinding` でつないだ関数を呼び、`live-tour.mjs` に「次へ進む」と知らせる。
知らせを受けた `live-tour.mjs` は、次の手順の台本（`actions`）に書いた操作を Playwright で行い、操作が終わった画面で、次の手順の吹き出しを出す。

| 観点 | 埋め込む案内 | ライブの案内 |
|---|---|---|
| 渡されたもの | HTML ファイル | URL（http:// か https://） |
| 案内の置き場所 | HTML の `</body>` の直前（印で囲む） | ブラウザーの中だけ。サイトにもファイルにも書き込まない |
| ページの移動 | しない（1 ページの中だけ） | 台本の操作で、別のページへ移って解説を続ける |
| 読み手の操作 | 案内を開いている間は、ページを操作できない | 同じ。ただし、読み手が自分で操作する手順（`interactive`）では、吹き出しを開いたまま操作できる |
| 案内を開く方法 | 読み手がファイルを開き、「解説」ボタンを押す | Claude が `live-tour.mjs` を起動すると、ブラウザーが開き、手順 1 が出る |
| 残るもの | 案内を付けた HTML | 台本（`WORK/tour.json`）だけ。ブラウザーを閉じると、案内は消える |
| 確かめる道具 | `check-guide.mjs` | `live-tour.mjs --check` |

## 2. どちらにするかの決め方

- HTML ファイル（パスや添付）を渡されたときは、SKILL.md の進め方で埋め込む。
- `http://` か `https://` の URL を渡されたときは、ライブの案内にする。
- `file:///` の URL は、手元の HTML ファイルを指しているので、埋め込む。
  ただし、依頼者が、ページを移りながら操作して解説してほしいと言ったときは、ライブの案内にする。

依頼者が URL を渡して「この HTML に埋め込んで」と明示したときは、その指示に従う。
URL のページのファイルを手元に持っていなければ埋め込めないので、そのときは、ファイルの場所を尋ねる。

## 3. 守ること

ライブの案内は、依頼者の本物のサイトを、依頼者のアカウントで操作する。
そのため、埋め込む案内には無い、次の決まりを守る。

1. **データを送る・変える操作をしない。**
   送信・保存・削除・購入・登録・確定・承認のような操作を押すと、案内を読んだだけで、本物のデータが変わる。
   台本では、その操作の手前までを見せ、押したときに何が起きるかは、「操作と結果」（`do`）のブロックで文として説明する。
   例えば、問い合わせのサイトなら、コメントの欄に文を入れるところまでを見せ、「コメントを送信」は押さずに、押すとコメントが担当者に届くことを文で書く。
   依頼者が、ある操作を案内で行ってよいと明示したときだけ、その操作に `"allow_change": true` を付け、報告にそのことを書く。
   歯止めは 2 つある。
   `guide.py validate` は、`say` や `target` にこの種の言葉がある `click` を問題として示す。
   `live-tour.mjs` は、押す部品の文字にこの種の言葉があるとき、または POST のフォームを送るときに、押す前に止める。
2. **パスワードを扱わない。**
   Claude は、パスワードを尋ねず、台本にも書かず、入力もしない。
   ログインが要るサイトでは、依頼者が自分でログインする（4.1）。
   `guide.py validate` は、パスワードの欄に入れる `fill` を問題として示す。
3. **台本に、依頼者の個人の情報を書かない。**
   `fill` で入れる値は、「テスト」「会議室のモニターが映らない」のような、例として作った値にする。
4. **ページの確認の窓は、案内が「キャンセル」で閉じる。**
   `confirm` などの窓が出ると、`live-tour.mjs` はデータを変えないよう「キャンセル」を選び、吹き出しにそのことを出す。
   ページを離れるときの確認（`beforeunload`）だけは「離れる」を選ぶ（離れても、入れかけた内容が保存されずに消えるだけである）。
5. **依頼者が使ってよいサイトだけを開く。**
   依頼者が URL を渡したサイトと、そのサイトの中のページだけを開く。

## 4. 進め方

コマンドは、このスキルのフォルダーを基準にした相対パスで書いている。
必要なものは、Node.js 18 以上と、Playwright（`playwright-core` か `playwright`）、Chrome か Edge である。
`live-tour.mjs` は、Playwright を、まず普通の読み込み、次に `npm root -g` の下（`@playwright/cli` や `@playwright/mcp` の中のものも含む）から探す。
見つからないと止まるので、依頼者に `npm install -g playwright-core` で入れてよいか尋ねる。

台本と、確認の結果は、埋め込む案内と同じく、作業用の一時フォルダー（`WORK`）に置く。

### 4.1 ログインが要るか確かめる

最初に、渡された URL の画面を出す。

```sh
node scripts/live-tour.mjs --outline URL --out WORK/o-start
```

`WORK/o-start/page-1440x900.png` がログインの画面なら、依頼者に自分でログインしてもらう。

```sh
node scripts/live-tour.mjs --login URL --profile WORK/profile
```

このコマンドは、ブラウザーを閉じるまで終わらないので、背景で実行する（Bash の `run_in_background`）。
依頼者には、「ブラウザーが開くので、ログインしてから閉じてほしい」と伝える。
閉じたあとは、ログインした状態が `WORK/profile` に残るので、以後のすべてのコマンドに `--profile WORK/profile` を付ける。
`WORK/profile` には、ログインの状態（クッキー）が入っている。
Claude はその中身を読まない。
作業が終わったら、依頼者に場所を伝え、消してよいかを尋ねる。

### 4.2 画面を調べる

`--outline` の一覧には、見出し・領域・ボタン・入力欄ごとに、ページの中で 1 つに決まるセレクター、表示の文字、位置が出る。
スクリーンショットと一覧から、画面の目的、部分ごとの役割、どこを押すとどの画面に移るかを読み取り、`WORK` にメモする。
埋め込む案内と同じく、確かめた事実と、推測を分けて書く。
押した結果を確かめたい部分は、台本に操作を書き足して `--outline --at K` で確かめる（4.3）。
データを変える部分は押さないので、その結果は、画面の文字（ボタンの説明、確認の文）から分かることだけを書く。

### 4.3 順路を決め、台本を 1 手順ずつ書き足す

順路は、読み手が実際に仕事をする順に、画面をまたいで並べる。
例えば、問い合わせのサイトなら、「サイトの目的 → 一覧の検索欄 → 検索した結果の一覧 → 1 件の詳細 → コメントの欄 → 新規作成の画面」の順になる。

台本（`WORK/tour.json`）は、埋め込む案内のデータに、`start_url` と、手順ごとの `actions`・`url` を足したものである。
手順 K の `actions` は、手順 K を出す前に行う操作である。
読み手が手順 K−1 で「次へ」を押すと、`live-tour.mjs` は手順 K の `actions` を順に行い、終わった画面で手順 K の吹き出しを出す。
手順 1 の `actions` は、`start_url` を開いた直後に行う。
手順 K−1 の吹き出しには、手順 K の `actions` の `say` が、「「次へ」を押すと、案内が次の操作を自動で行う。」の下に番号付きで並ぶので、読み手は押す前に何が起きるかを知る。

1 手順ずつ、次のように書き足す。

1. 手順 K の `actions` を書く。
2. 移った先の画面を出す。

   ```sh
   node scripts/live-tour.mjs WORK/tour.json --outline --at K --out WORK/o-K
   ```

   `live-tour.mjs` は、手順 1〜K の `actions` を順に行い、その画面の部品の一覧とスクリーンショットを出す。
   一覧の先頭に、その画面の URL が出るので、手順 K の `url` に書く（変わる所は `*` にする。例：`ticket.html?id=*`）。
3. 一覧から、手順 K で指す部分を選んで `target` に書く。

### 4.4 説明を書く

埋め込む案内と同じく、[案内の文章の決まり](writing-rules.md) と [説明の細かさの段の作り方](granularity.md) に従う。
ライブの案内では、次の 3 点を加える。

- 操作のあとの手順の冒頭の 1〜2 文は、操作の結果として、今の画面が何を示すかを書く。
  例：「この一覧は、『プリンター』を題名に含む問い合わせだけを並べたものである。」
- `say` には、読み手が画面で見て分かる言葉で、何をどう操作するかを書く。
  例：「『言葉で探す』の欄に『プリンター』と入れる」「一覧の『プリンターが印刷できない』を押す」。
  1 つの操作に 1 つの `say` を書く。
- 読み手に自分で操作してもらう手順は `"interactive": true` にし、「操作と結果」（`do`）で、何をして、何が起きたら次へ進むのかを書く。
  読み手の操作でページが移ると、移った先で同じ手順の吹き出しが出直すので、移ったあとに指す部分が無くなるなら、`missing` に「ログインが終わると、この部分は消える。『次へ』を押して進む。」のように書く。

### 4.5 検査する・読み手役で点検する

```sh
python scripts/guide.py validate WORK/tour.json
```

文の決まりの検査に加えて、`actions` の形、`say` の有無、データを変える操作、パスワードの入力を調べる。
「問題」が 0 件になるまで直し、SKILL.md の 6 のとおり読み手役で点検する。
`guide.py text WORK/tour.json` の文章には、手順ごとに、案内が自動で行う操作も出る。

### 4.6 ブラウザーで確かめる

```sh
node scripts/live-tour.mjs WORK/tour.json --check --out WORK/check --size 1440x900,390x844
```

見えないブラウザーで、台本の操作を本当に行いながら全手順を出し、次を確かめる。
ログインが要るサイトでは `--profile WORK/profile` を付ける。

- 各手順の操作が最後まで行えたか（部品が見つからない、データを変える操作で止めた、など）。
- 手順の画面の URL が、台本の `url` と合うか（合わなければ注意を出す）。
- 指す部分が見つかり、見えているか。吹き出しが画面に収まり、指す部分に重なっていないか。
- 手順を開いた直後は冒頭の 1〜2 文だけが見え、「分からない」が詳細の中にあるか。
- 読み手が自分で操作する手順で、指す部分を押せるか。
- 吹き出しの「次へ」を本物のクリックで押したとき、操作と次の手順の表示までが通るか。
- 前の手順へ戻るとき、最初の画面から操作をやり直して、その手順の画面に戻れるか。

`WORK/check/index.html` に、スクリーンショットと操作の記録が並ぶ。
`sNN-…png` が手順 NN、`sNN-op-…png` が手順 NN の前の操作を見せているところ（暗幕と橙の枠で操作する部分を照らし、横の吹き出しに操作の中身を出した状態）、`next-click-…png` が「次へ」を押したあと、`back-…png` が戻ったあとである。
少なくとも、全手順の 1440×900 と、操作を見せているところを 1 枚、390×844 の数手順を見る。

### 4.7 依頼者に案内を開く

```sh
node scripts/live-tour.mjs WORK/tour.json
```

このコマンドも、ブラウザーを閉じるまで終わらないので、背景で実行する。
ブラウザーの窓が開き、`start_url` の画面に手順 1 の吹き出しが出る。
読み手が操作すると、次のように動く。

| 読み手の操作 | 動き |
|---|---|
| 「次へ」 | 解説のときと同じ暗幕のまま、照らす所が操作する部分へ動き、橙の枠で囲む。横の吹き出しに「自動で操作中」と `say` を出し、少し待って（既定 1.2 秒、`--slow` で変えられる）から、Playwright がクリックや入力を行う（文字は 1 字ずつ入る）。暗幕・枠・吹き出しはクリックを受け取らないので、操作はページの部分にそのまま届く。操作が終わった画面で、次の手順の吹き出しが出る |
| 「戻る」・目次から前の手順 | 最初の画面から、その手順までの操作をやり直してから、その手順の吹き出しを出す |
| 目次から先の手順 | 間の手順の操作を順に行ってから、その手順の吹き出しを出す |
| 「やめる」・Esc | 案内を閉じる。ページは自由に操作できる。画面の隅の「解説」ボタン（`launcher.label`）を押すと、閉じた手順から開き直す |
| 読み手が自分で操作する手順で、ページを移った | 移った先のページで、同じ手順の吹き出しが出直す |
| ブラウザーを閉じる | 案内が終わり、`live-tour.mjs` も終わる |

操作が途中で止まったとき（部品が見つからない、歯止めで止めた）は、止まった所の前の手順の吹き出しに、止まった理由が出る。

### 4.8 報告する

SKILL.md の 9 の項目に加えて、次を書く。

- ブラウザーで案内が開いていること、進め方（上の表）、もう一度開くコマンド
- 案内が自動で行う操作の一覧と、データを変えるので行わずに文で説明した操作
- 依頼者が許して行う操作（`allow_change`）があれば、その操作と、許しを受けたこと
- ログインの状態を残したフォルダー（`--profile`）の場所と、消し方

## 5. 台本の書き方

台本の項目は、[案内のデータの形](guide-format.md) の 7 章にある。
`actions` の操作は、次の 10 種類である。

| `do` | 行うこと | 要る項目 |
|---|---|---|
| `click` | 部品を押す | `target`、`say` |
| `fill` | 入力欄の中身を消してから、文字を入れる | `target`、`value`、`say` |
| `select` | 選ぶ欄で、選択肢を選ぶ（表示の文字か値） | `target`、`value`、`say` |
| `check` / `uncheck` | チェックを付ける／外す | `target`、`say` |
| `press` | キーを押す（`target` があれば、その部品で） | `key`（例：`Enter`、`Tab`）、`say` |
| `goto` | URL を開く（`start_url` からの相対でもよい） | `url`、`say` |
| `hover` | ポインターを重ねる（重ねると開くメニューなど） | `target` |
| `scroll` | 部品が見える所まで画面を送る | `target` |
| `wait` | 部品か文字が出るまで待つ。どちらも無ければ `ms` ミリ秒待つ | `target` か `text` か `ms` |

どの操作にも、`timeout`（部品を待つ長さのミリ秒。既定 15000）を付けられる。
`target` の書き方は、埋め込む案内と同じである（CSS セレクターか `{ "selector", "text", "nth" }`）。

## 7. 動きの細部と制約

- 前の手順へ戻るときは、操作をやり直すので、同じ操作がもう一度行われる。
  データを変えない操作だけを台本に書くのは、やり直しても困らないようにするためでもある。
- リンクが新しいタブを開くときは、案内は新しいタブに移って続く。
- 画面を読み込み直さずに中身を切り替えるサイト（SPA）でも、エンジンはページに残り続けるので、そのまま動く。
- `iframe` の中の部分は、指すことも操作することもできない。
- ロボットの確認（CAPTCHA）があるサイトや、自動の操作を止めるサイトでは、操作が止まることがある。
  そのときは、止まった所と理由を報告する。
- サイトの Content-Security-Policy は、案内を止めない（`live-tour.mjs` は、そのブラウザーの中だけで、この指定を無視する設定で開く）。
- ライブの案内は、サイトの localStorage に何も書かない。
- 表示する値が時間とともに変わるサイト（在庫の数、新着の一覧）では、例に使った値が、読み手が開いたときには変わっていることがある。
  例に値を書くときは、確かめた時点の値であることが分かるように書くか、変わらない部分（列の名前、ボタンの文字）を例にする。
- 確かめるとき（`--check`）も、操作は本物のサイトで行われる。
  データを変える操作は、`allow_change` を付けていても、`--allow-change` を付けない限り、確かめるときには行わない。
