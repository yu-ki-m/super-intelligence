# 考える観点

一緒に考えるときの地図と、地図のどこを考えるかの観点。相談者に順番に聞くためのチェックリストではない。Claude が自分で考えを進め、仮置きを置き、弱いところを見つけるために使う。

## 1. 論理の鎖

企画の考えは、次の輪をつないだ鎖として組み立てる。1つでも輪が切れていると、その先の結論は根拠のない推測になる。

| 輪 | 考えること | 書く形 |
|-|-|-|
| 起点 | なぜ今この話が出たか。やらないと何が起きるか | きっかけの出来事、上位の目標、やらない場合の損失 |
| 事実 | 何が観察・記録されているか | 具体的な事例・数字・資料と、その出典 |
| 課題 | 誰が、どの場面で、何に困っているか | 課題文（2.2） |
| 原因 | なぜその課題が起きているか | 原因の見立てと、ほかの原因の候補 |
| 価値 | 何が変われば、課題が解けたと言えるか | 価値提案の1文（2.5）と、期待する利用者の行動の変化 |
| 方向 | どんな解き方が原因に効くか | 複数の解き方と、それぞれが原因に効く理由 |
| 手段 | 依頼された（思いついた）手段は、その解き方のどこを担うか | 手段が担う部分と、担わない部分 |
| 成果 | 何をもって解けたとするか | 最終成果・途中の兆し・悪化させてはいけないもの |
| 検証 | 一番危ない仮置きを、どう確かめるか | 危ない仮置きと確かめる順番（2.8） |

依頼や思いつきは、たいてい「手段」の輪から来る。そのまま進むと、起点から方向までが空のまま、手段と成果だけが埋まる。地図を見せるとき、どの輪が空いているかを示す。

### 1.1 輪のつなぎ方

それぞれの輪について、次の4つを考える。

- 今の考え：その輪の中身。
- 確からしさと根拠：〔事実〕〔あなたの見方〕〔仮置き〕〔決めた〕と、何に基づくか。
- 前の輪からの推論：前の輪から、なぜこの輪が導けるのか。「なぜなら」で書けること。
- 崩れたら：この輪が違っていたら、後ろのどの輪が崩れるか。

### 1.2 よくある飛躍

隣り合う輪の間に「なぜなら」が書けないところが、飛躍である。見つけたら、つなぐ候補を出す。

- 起点から手段へ：「生成AI対応が来期の重点だから、MCPを作る」。間に、誰のどの課題を解くかがない。
- 伝聞から事実へ：「部長が困っていると言っていた」を、利用者が困っている事実として扱う。
- 1つの事例から全体へ：1人の声や1回の出来事を、全体の課題とする。
- 原因の決めつけ：原因を1つに決め、ほかの候補を見ていない。
- 機能から成果へ：「この機能があれば時間が減る」の間に、利用者が実際に使うかどうかがない。
- 平均の利用者：特定の人と場面を決めず、「みんな」のために作る。

## 2. 企画の観点

観点ごとに、考える問いと、強いしるし・弱いしるしを示す。弱いしるしが見えたら、そこが次に考える候補になる。

### 2.1 起点

- 考える問い：なぜ今か（きっかけの出来事）。誰の発案か。上位の目標とどうつながるか。やらなかったら何が起きるか。依頼者がいれば、どんな場面を見たら「頼んでよかった」と思うか。
- 強いしるし：きっかけと、やらない場合の損失を、具体的に言える。
- 弱いしるし：「上から言われた」「流行っているから」で止まっている。

### 2.2 課題の実在

- 課題文：「〔誰〕は、〔場面〕で〔したいこと〕をしたいが、〔障害〕のためにできず、〔損失〕が生じている」。
- 考える問い：直近の具体的な事例、頻度、痛みの強さ（時間・お金・失敗・不満）、今の対処（回避策）とそのコスト、当事者自身が課題と思っているか。
- 根拠の強さ（弱い順）：思い込み → 伝聞 → 当事者の話 → 具体的な事例 → 記録・観察 → 測った数字。
- 強いしるし：課題文が書け、具体的な事例か記録がある。
- 弱いしるし：「あったら便利」「みんな困っているはず」。今の対処に時間もお金もかかっていない課題は、解いても使われにくい。

### 2.3 対象者と場面

- 最初に狙う利用者と場面を、1〜2に絞って考える。年齢や部署などの属性ではなく、状況で書く。
  - 形：「〔状況〕のとき、〔動機〕したい。そうすれば〔期待する成果〕になる」（片付けるべき用事。JTBD の形）。
- 選ぶ理由：課題が最も強い／人数や件数が多い／届けやすい／確かめやすい。
- 役割で分ける：使う人、選ぶ・買う人、管理・運用する人、承認する人、影響を受ける人。社内の仕組みや B2B では、使う人と決める人が違うことが多い。
- 弱いしるし：「全員向け」。誰の場面にも合わなくなる。

### 2.4 今のやり方と乗り換え

- 利用者は、今その課題をどう片付けているか。表計算、紙、人に頼む、我慢する、何もしない、も代わりの手段に入れる。
- 乗り換えの4つの力：
  - 押す力：今のやり方への不満。
  - 引く力：新しいやり方の魅力。
  - 不安：新しいものへの心配（覚える手間、失敗、信頼できるか）。
  - 慣れ：今のやり方への慣れ・習慣・すでにかけた投資。
- 押す力と引く力が、不安と慣れを上回らなければ、作っても使われない。

### 2.5 価値提案

- 1文で書く：「〔対象者〕は〔場面〕で〔課題〕に困っている。〔解決の方向〕によって〔得られる成果〕が得られる。今の〔代わりの手段〕と比べて〔違い〕がある」。
- 書けない部分が、まだ考えていない輪である。

### 2.6 体験の全体

- 流れ：知る → 初めて使う → 価値を実感する → 使い続ける → やめる・広げる。
- 価値を実感するまでの時間と手間。最初の利用で価値が分からなければ、2回目はない。
- 画面やシステムの外：問い合わせ、紙・対面の業務、通知、ほかの人への受け渡し。
- 例外と回復：失敗・中断・取消・やり直し・権限がないとき。

### 2.7 事業とのつながり

- 利用者の成果が、どういう因果で事業・組織の成果になるか。
- 利用者にとって良いことと、事業にとって良いことがずれる場面。例：解約しにくくすると、事業の数字は上がるが、信頼を失う。
- 成果の測り方：最終成果、途中の兆し（効いているか）、悪化させてはいけないもの。数字にするときは、今の値・目標・分母を分ける。今の値が分からなければ、「仮置き」と測り方を書く。

### 2.8 危ない仮置きと確かめる順番

- 地図の〔仮置き〕〔あなたの見方〕の輪を並べる。
- 4つのリスクに分けて見る。
  - 価値：利用者は使うか。依頼者は効果を認めるか。
  - 使いやすさ：利用者は使いこなせるか。
  - 実現性：作れるか。運用できるか。データ・権限・外部の仕組みは使えるか。
  - 事業性：費用に見合うか。続けられるか。法令・契約・社内の規程に合うか。
- 外れたときの影響が大きく、根拠が弱いものから確かめる。多くの企画では、価値のリスクが最初に来る。手段から考えると実現性が気になりがちだが、作れても使われなければ意味がないため。

### 2.9 当たり前の品質

- 要求を3つに分けて見る（狩野モデル）。
  - 当たり前：なければ不満になる。あっても満足は上がらない。
  - 多いほど良い：充実するほど満足が上がる。
  - 魅力：なくても不満はないが、あると喜ばれる。
- 当たり前の品質は、誰も口にしない。Claude が見つけて地図に置く。

### 2.10 信頼と倫理

- 利用者をだます・誘導する設計（解約しにくくする、同意へ誘導する、急がせる）になっていないか。
- データの扱いを、利用者に説明できるか。
- 生成AIを使う場合：誤りが起きる前提で、利用者が結果を確かめ・直せるか。誤りが起きたとき、誰が気づき、誰が責任を持つか。

## 3. 体験を形にするときの観点

考えが画面や操作の話に進んだときに使う。企画の輪（2章）が空のうちは、ここに深入りしない。

| 観点 | 考える問い |
|-|-|
| 見つけやすさ | 欲しい情報や機能にたどり着けるか。言葉は利用者の言葉か |
| 分かりやすさ | 何の画面で、何ができるかが一目で分かるか |
| 操作しやすさ | 押せるものが押せそうに見えるか。手数は多すぎないか |
| 状態と反応 | 今どうなっているかが分かるか。読み込み中・空・失敗・成功の見え方 |
| 誤りの防止と回復 | 間違えにくいか。取り消せるか。失敗の文が、原因と対処を示すか |
| 覚えることの少なさ | 選択肢が多すぎないか。利用者に記憶を強いていないか |
| 一貫性 | 同じ意味のものは、同じ見た目と動きか |
| 使える人の広さ | 文字の見やすさ、キーボードだけでの操作、読み上げ、色だけに頼らない表現 |

## 4. 依頼の型ごとに空きやすい輪

| 依頼の型 | 空きやすい輪 | 先に考えるとよいこと |
|-|-|-|
| 「○○を作って」（ツール・システム） | 課題、今のやり方、価値 | 今どう片付けていて、何が困るのか。作れば使われるのか |
| 「AI化して」 | 課題、方向 | AI でなくても解けないか。誤りが起きたとき、誰がどう気づいて直すか |
| 「全部○○にして」（一律の変更） | 対象者と場面、成果 | 対象者ごとに合う・合わないの違い。悪化させてはいけないもの |
| 「仕組み・制度を作って」 | 起点、成果、事業性 | 誰が運用し、続けられるか。やらない場合に何が起きるか |
| 「○○みたいなものを」（他社・他部署の例） | 課題、対象者と場面 | 元の例が解いていた課題と、こちらの課題が同じか |

## 5. 考えを強くする材料

相談者の考えや Claude の仮置きを強くするのに、何があればよいか。問い詰めるためではなく、「これがあると強くなる」と添えるために使う。

| 今の考えの形 | 強くする材料 | 理由 |
|-|-|-|
| 一般論（「よくある」「いつも」） | 最後にそれが起きたときの具体的な事例 | 具体例のない課題は、本当にあるかを確かめられない |
| 未来の意向（「欲しい」「使うと思う」） | 今どうしているか、それに使っている時間やお金 | 意向は外れやすく、過去の行動は外れにくい |
| 原因の見立て | それを見た場面、ほかの原因の候補 | 原因の決めつけを防ぐ |
| 全体（「みんな」「全部」） | 特に困っている人と場面 | 対象者と場面を絞るため |
| 伝聞（「部長が言っていた」） | 元の発言者が見た場面 | 伝聞の元の事実に近づくため |
| 手段（「○○があれば」） | それができたら何が良くなるか | 手段の後ろにある目的を出すため |
| 感覚の数字（「半日くらい」） | 何から見積もったか、記録 | 実測・推計・仮置きを分けるため |

確かめ方は、安い順に：記録・資料を見る → 当事者に過去の行動を聞く → 見本・紙芝居で反応を見る → 人手で代わりに行って試す → 技術の試作 → 限られた範囲で導入する。
