# 台帳を TOON で書く決まり

台帳のファイルは、TOON（Token-Oriented Object Notation）の公式仕様 4.4 に従う。
仕様の写しは同梱していないが、`scripts/toon.py` が仕様の適合テスト（564件）に通る実装で、読み書きと検査をする。
表の列（キー）と値の種類は `references/ledger-schema.md` にある。

## 形

台帳の各ファイルは、ルートがオブジェクトの TOON 文書である。
表は「表形式の配列」で書き、行数 N と列名を見出しに一度だけ宣言する。

```toon
needs[2]{id,who,scene,want,why,obstacle,origin,confidence,adoption,reason}:
  N001,SH01,SC01,入荷した書籍を在庫に登録したい,棚に出す前に在庫数を正しく保つため,今は登録の画面がない,request,claim,adopted,""
  N002,SH02,SC02,同じ書籍が二重に数えられていない在庫数を見たい,棚卸しの差異を減らすため,"",stakeholder,hypothesis,adopted,""
current_links: []
```

- 見出しの `[N]` は、その下の行の数と必ず一致させる。
  行を足したり消したりしたら、N も直す。
  ずれていると、読み込みの段階でエラーになる。
- 行は見出しより2文字だけ字下げし、値をカンマで区切る。
  列の数と値の数を必ずそろえる。
- 空の表は `表名: []` と書く（`表名[0]{…}:` とは書かない）。
- 1つのファイルの中に、スキーマにない表やキーを足さない。
- ファイルの末尾に改行を入れない（入っていても読めるが、検査で警告になる）。
  `ledger.py fmt` で正しい形に整えられる。
- 字下げは半角空白2つにし、タブを使わない。
- 全行がコメントの行（先頭が `#`）は書かない。

## 引用符が要る値

値は、次のどれかに当たるときだけ、二重引用符 `"…"` で囲む。
囲まないと、別の意味に読まれるか、読み込みでエラーになる。

| 当たるもの | 例 | 書き方 |
|-|-|-|
| 空の文字列 | 理由なし | `""` |
| 半角のカンマ `,` を含む | `A,B を選ぶ` | `"A,B を選ぶ"` |
| 半角のコロン `:` を含む | `HH:MM の形式` | `"HH:MM の形式"` |
| 二重引用符・バックスラッシュを含む | `"はい" と答える` | `"\"はい\" と答える"` |
| 角かっこ・波かっこ `[ ] { }` を含む | `items[0]`、`{token}` | `"items[0]"` |
| 先頭か末尾が空白 | ` 前に空白` | `" 前に空白"` |
| `-` か `#` で始まる | `-1 は不可`、`#123` | `"-1 は不可"` |
| 数字・true・false・null に見える文字列 | 文字列の `200`、`001` | `"200"`、`"001"` |
| 改行を含む | 2行の文 | `"1行目\n2行目"` |

- 全角の読点「、」、全角のコロン「：」、全角のかっこ「（）」は引用符が要らない。
  文章の中の区切りは、なるべく全角を使う。
- 引用符の中では、`\\` `\"` `\n` `\r` `\t` だけが使える。
  ほかのバックスラッシュの使い方はエラーになる。
- 整数の列（`order`、`ev_line`、`round`）は引用符なしの数字にする。
- 真偽値の列（`first`、`git_dirty`）は `true` か `false` にする。
- 文字列の列に数字だけの値を入れるときは、引用符で囲む。
  囲まないと数として読まれ、検査で型の誤りになる。

## ID と参照

- ID は台帳全体で一意にし、決まった接頭辞と3桁の数字を使う（`N001`、`R001`、`S001`、`T001` など。接頭辞は `ledger-schema.md` の各表の説明にある）。
- 1つの欄に複数の ID を書くときは、半角空白で区切る（例：`N001 N003`）。
  空白は引用符が要らない。
- 参照する ID は、どこかの表に実在しなければならない。

## 書き方の手順

1. 表を書き足すときは、Edit で見出しの N と行をまとめて直す。
2. 書いたら、すぐに `python -X utf8 "${CLAUDE_SKILL_DIR}/scripts/ledger.py" validate <台帳>` で構造を検査する。
   TOON の誤り（行数のずれ、列数のずれ、引用符の閉じ忘れ）は、ここで行番号付きで分かる。
3. 品質の観点の台帳（`quality.toon`）は手で編集しない。
   判定は小さな TOON ファイルに書き、`quality.py set` で反映する。
4. タスクの行は、まず `ledger.py derive-tasks` で足し、空の欄を埋める。
