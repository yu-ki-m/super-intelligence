1. チケットのステータス変更（PATCH /api/tickets/{ticketId}）

1.1 処理概要

対象処理脆弱性チケットのステータスを変更し、変更履歴を登録する
種別Web API（同期）
HTTPメソッドPATCH
エンドポイント/api/tickets/{ticketId}
入力パス ticketId、ヘッダー Authorization（Bearer トークン）、ボディ status・comment
出力200：変更後のステータス・バージョン・変更前のステータス（JSON）／ 異常時 400・401・403・404・409・500
認証JWT（HS256）を JwtAuthenticationFilter で検証（No.01〜14）
トランザクションあり（1 つ。No.22 で開始、No.44 で COMMIT、例外時は ROLLBACK）
使用テーブルvulnerability_ticket（参照・行ロック・更新）、project_member（参照）、ticket_status_history（登録）
外部システムなし
起点（根拠）TicketController.java:24-30 updateStatus

1.2 入力項目

{
  "status": "in_progress",
  "comment": "調査を開始します"
}
項目受け取り位置型必須検証内容（コード上の条件）値の例
ticketIdパスlong必須long に変換できること（No.16）5012
Authorizationヘッダーstring必須Bearer で始まり、続くトークンが有効な JWT であること（No.03・07）Bearer eyJhbGciOiJIUzI1NiJ9.…
statusボディ（JSON）string必須@NotBlank（No.18）。前後の空白を除き大文字にして OPEN・IN_PROGRESS・RESOLVED・CLOSED・REJECTED のいずれか（No.24）"in_progress"
commentボディ（JSON）string任意@Size(max = 500)（No.19）。status が RESOLVED の場合は空白以外の文字を含むこと（No.36）"調査を開始します"
JWT のクレーム（No.07〜12 で使用）
クレーム使い方値の例
sublong に変換して userId"205"
tidlong として tenantId3
roles文字列の配列として roles（無ければ空）["TICKET_MEMBER"]
iss"ticket-auth" と一致すること"ticket-auth"
exp有効期限（過ぎていないこと）1793000000
