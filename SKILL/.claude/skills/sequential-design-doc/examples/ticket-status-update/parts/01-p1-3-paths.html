E1：No.10・11 でフィルター内の想定外の例外（NumberFormatException・NullPointerException）が発生した場合

No.処理内容根拠
E1-01例外は No.06 の catch（JwtVerificationException だけを捕捉）に一致しないため、doFilterInternal の外へ送出される。DispatcherServlet より前で発生しているため、GlobalExceptionHandler は使われない〔推定〕。トランザクションは未開始。JwtAuthenticationFilter.java:42-47
FW 仕様
E1-02応答サーブレットコンテナのエラー処理により、Spring Boot の既定のエラー応答（ステータス 500、ボディ timestamp・status・error・path）を返す〔推定〕。500 応答で終了FW 仕様（Spring Boot の /error）

E3：No.17 でリクエストボディを読み取れなかった場合（HttpMessageNotReadableException）

FW 仕様
E3-02応答ステータス 400、ボディは Spring Boot の既定の形式（timestamp・status・error・path）で応答する〔推定〕。400 応答で終了FW 仕様

E4：No.20 で入力検証の違反があった場合（MethodArgumentNotValidException）

No.処理内容根拠
E4-01分岐handleValidation が選ばれ、違反の一覧（getFieldErrors()）が空か判定する。GlobalExceptionHandler.java:18-21
違反の一覧が空のとき（No.E4-01 が成立）：field を空文字にする → E4-02
違反の一覧が空でないとき（No.E4-01 が不成立）：field を一覧の先頭の違反の項目名（例 "status"）にする。違反が 2 件のときにどちらが先頭になるかは Bean Validation の実装による〔推定〕 → E4-02
E4-02応答ステータス 400、ボディ {"code":"VALIDATION_ERROR","message": field}（例 {"code":"VALIDATION_ERROR","message":"status"}）で応答する。トランザクションは未開始。400 応答で終了GlobalExceptionHandler.java:22

E6：No.26・30・39・42・44 で DB の例外、または No.26 で取得値の変換に失敗した場合

DB の例外：接続断、ロック待ちのタイムアウト、制約違反など（Spring の DataAccessException）。変換の失敗：status 列が列挙に無い値・NULL（IllegalArgumentException・NullPointerException）。

No.処理内容根拠
E6-01TX非検査例外のため ROLLBACK する。No.42 で失敗した場合は No.39 の UPDATE も取り消される。No.44 の COMMIT で失敗した場合は、何も確定しない。行ロックは解放される。TicketService.java:33

E6-03応答ステータス 500、ボディは Spring Boot の既定の形式で応答する〔推定〕。500 応答で終了FW 仕様
