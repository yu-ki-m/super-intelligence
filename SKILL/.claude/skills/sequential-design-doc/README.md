# sequential-design-doc

既存のソースコードから、**実行される処理を実行順に日本語へ置き換えた**詳細設計書（単一 HTML）を作る Agent Skill。

- 起点（HTTP リクエスト・バッチの起動）から応答・終了まで、フィルター・入力検証・トランザクション・例外ハンドラー・コミット後の非同期処理も含めて追跡する。
- 共通メソッドやレイヤーで抽象化せず、呼び出し先の処理を呼び出し位置に展開して書く（メソッド名は根拠欄へ）。
- 分岐は成立・不成立の行き先、繰り返しは戻り先と抜け先、例外は finally・ROLLBACK・ハンドラー・応答までを書く。
- SQL は全文を残し、直後にバインド変数・取得データ・更新前後・登録データ・削除対象・件数ごとの処理を表で示す。ORM から推定した SQL は「参考SQL」として実行SQL と区別する。
- コードで確認した事実・フレームワーク仕様からの〔推定〕・確定できない〔未確認〕を分け、未確認事項と検証記録を文書に残す。

## ddoc.py

| コマンド | 内容 |
|---|---|
| `init <dir> [--procs N]` | 部品ファイルの雛形を作る |
| `build <部品|dir>... -o OUT.html --title T [--meta M] [--src-root DIR]` | 部品を連結してテンプレートに入れ、処理行の ID・参照のリンク・SQL の見出しを付け、検査する |
| `check OUT.html [--src-root DIR] [--coverage] [--refs]` | 構造の検査（3 列・番号・参照・分岐の「〜のとき」行・木の字下げ・SQL の必須表・未確認事項と検証状態）、根拠の行番号の照合、根拠から参照されていない注目行の列挙、参照の一覧 |
| `inventory <file|dir>...` | ソースの注目行（分岐・繰返・例外・SQL・DB・TX・外部・非同期）を関数ごとに列挙する |
| `render OUT.html [--shots DIR] [--tab ID]` | ヘッドレスの Chrome / Edge で表示し、横スクロール・はみ出し・文字サイズ・セル余白・装飾を検査し、スクリーンショットを撮る（`--tab` で 1 つのタブだけを撮る） |

## 設計上の判断

- **本文は HTML で書き、CSS はテンプレートに固定する。** モデルは表を含む HTML を自然に書けるため、独自のデータ形式を挟まない。見た目の一貫性はテンプレート、構造の正しさは `check` で担保する。
- **部品ファイルに分けて書く。** 大きな処理でも 1 回の書き込みを小さくでき、解析の台帳（`*.trace.md`）と合わせて、会話の文脈が長くなっても作業を続けられる。
- **SQL と表の対応を機械的に検査する。** `div.db` ごとに SQL の種類を判定し、必須の表（取得データ・更新前後など）、バインド変数、列名の一致を確かめる。
- **書き漏れを機械的に探す。** 根拠欄の `ファイル:行` から参照した関数を特定し、その中の分岐・例外・SQL などの行が参照されていなければ知らせる（`--coverage`）。
- **逐次処理表は 3 列（No.・処理内容・根拠）の木の形。** 分岐の下に結果ごとの「〜のとき」行を枝（├─）でつなぎ、結果の処理を 1 段下げる。繰り返し・try はブロックの終わりの行で閉じる（└─）。try・catch・finally は言語のキーワードのまま書く。横の罫線はブロックの間だけに引き、縦の罫線は常に通す。行き先は処理内容に「→ NN」で書く。
- **リクエスト・レスポンスは JSON の例と項目の表の両方で示す。** 表だけでは入れ子・配列・null の形が分からないため、表の前に実際の形の JSON（シナリオの値）を置く。異常時は形ごとに 1 つを横に並べる。`check` は JSON として正しいか、JSON の項目が表で説明されているかを照合する。
- **複数の処理はタブで切り替え、タブを関心事でまとめる。** 処理が 2 つ以上なら、build が「一覧」・処理ごと・「未確認事項・検証記録」のタブを作り、`data-group` ごとにグループ名をタブの上に出す。JavaScript を使わず URL の `#p2` で切り替えるので、戻る・リンクの共有・印刷（全タブを出力）がそのまま使える。処理の外からは `p2 No.05` で行を指し、押すとそのタブの行へ移る。
- **SQL・外部 API・判定表は、その行の中の項目（1. 2. …）。** 処理の文より 1 段下げて表示し、No.29.3 のように参照できる。`check --refs` で参照と参照先の文を一覧にして、番号のずれ・まとめの表との食い違いを確かめる。
