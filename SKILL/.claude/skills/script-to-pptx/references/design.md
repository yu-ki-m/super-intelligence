# スライドの型

その区切りで聞き手に見せたいものから、型を選ぶ。
座標はインチ。本文の領域は、左右 0.6〜12.733、上下 1.75〜6.8（`X0`, `XW`, `Y0`, `YB`）。
2列のときは、左の列が `X0`、右の列が `XR`（6.833）、幅はどちらも `W2`（5.9）。

## 1. 全体の決まり

| 要素 | 大きさ | 書き方 |
| --- | --- | --- |
| タイトル | 32pt 太字 | 伝えることを全角20字前後。句点を付けない |
| 段階名（左上） | 14pt 太字、朱 | 台本の ### 見出しが自動で入る |
| 本文 | 15〜18pt | 図の説明として一、二行 |
| 補足・注記 | 13〜14pt、灰色 | 前提や断り |
| 出典の行 | 11pt | 根拠と「説明のための例」などの断り |
| 部品の中の小さな文字 | 11〜13pt | 図のラベルだけに使う |

- 本文を 14pt より小さくしない。収まらないときは、文を短くするか、箱を広げるか、スライドを分ける。
- 段落を中央そろえにしない。中央にするのは、図の中のラベルと、暗い背景の一言だけ。
- 装飾の帯や、タイトルの下の線は付けない。区切りは余白と背景の色で作る。
- 箱と箱の間は 0.3 インチ前後。

## 2. 掴み・回収（暗い背景）

レイアウトは `DARK`。台本の最初の場面と、最後に戻ってくる場面に使う。

- 掴み：白い吹き出し（`R` に白の塗り、`r: 0.15`）に、場面の一言を大きく（28〜44pt）。下に問いを 22〜24pt の白で、中央そろえ。
- 回収：掴みと同じ吹き出しを左に置き、掴みでは隠していたもの（例：同じ応答に入っていた部品）を下に足して見せる。右に、今日の要点を番号付きで3つ。最後に「確かめの一問」の白い箱。答えは書かない。
- 掴みと回収で同じ見た目を使うと、聞き手が「最初の話に戻った」と分かる。

## 3. 問いを残す選択肢

問題集の四つの案のように、答えを後で出す選択肢。

- 4枚のカードを横に並べる（幅 `(XW - 0.9) / 4`、高さ 3.3）。左上に番号の丸、下に案の文（16pt）。
- 隠している答えは、チップで `？？？` と置く。正解のカードに枠を付けるかは、台本が正解を口にするかで決める。
- 下に「問い」の箱を置き、何を後で答えるかを書く。

## 4. 目標と話す順番

- 濃い帯（`R` に `C.text2`）に、目標を 22pt の白で一行。
- その下に、話す順番を矢羽根（`CHEV`）で5〜7個。文字は短く、2行に分けるなら `\n` を入れる。
- 連載なら、下に各回のカードを並べ、今回のカードに朱の枠を付ける。

## 5. やり取りの順番（シーケンス図）

利用者・アプリ・外部の仕組みの間の依頼と返事を、上から順に見せる。

```js
const LX = { U: 1.25, A: 3.65, Cl: 6.35, H: 8.75 };          // 登場する者の中心の x
for (const k of Object.keys(LX)) {
  ARW(s, LX[k], 2.2, LX[k], 6.75, { arrow: false, color: C.accent6, width: 1, dash: "sysDot" }); // 生存線
  R(s, LX[k] - 0.8, 1.75, 1.6, 0.45);                          // 名前の箱
}
msgs.forEach(([from, to, label, isReply], i) => {
  const y = 2.62 + i * 0.345;                                   // 12行まで入る
  ARW(s, LX[from], y, LX[to], y, { dash: isReply ? "dash" : undefined });
  // ラベルは矢印の上。生存線をまたぐ長い矢印は、ラベルを近い2本の線の間に置く（線に文字が重ならないように）
  T(s, label, Math.min(LX[from], LX[to]) + 0.05, y - 0.27, 2.3, 0.25, { fontSize: 11, align: "center" });
});
```

- 依頼は実線、返事は点線。出典の行に「実線は依頼、点線は返事」と書く。
- 鍵になる一行は朱で太くする。状態の名前（例：停止理由）は、その行の右にチップ（11pt）で添える。
- 右の列（x 9.75〜）に、図から読み取ってほしいことを番号付きで2〜3個。

## 6. 構造と説明（コード＋番号付きの説明）

設定ファイルや JSON の形を見せて、各項目の意味を説明する。

- 左に `CODE`（幅 6〜7、行の高さ 20〜22pt）。鍵になる値を `hl`（朱の太字）にする。
- 右に番号の丸と説明（14〜16pt）を、0.75〜0.95 間隔で4〜5個。
- コードの行が箱の幅を超えるときは、値を次の行に分ける（例：`"args": [` の後で改行）。折り返させない。
- 一部を省いた例のコードは、出典の行に「説明のための例」と書く。

## 7. 一覧表

種類の一覧（停止理由の7種類など）や、問題番号の一覧。

- `TABLE` を全幅で。見出しは `HD(…)`、列の幅は `colW` で中身の長さに合わせる。行の高さは1行なら 0.45〜0.5、2行なら 0.6〜0.66。
- 名前の列は等幅（`{ text: "max_tokens", options: { fontFace: CODE } }`。CODE は `D.FONTS.codeEa`）。
- 本題の行は薄い背景（`fill: { color: C.background2 }`）か、名前を朱にして目立たせる。
- 範囲の一覧のように行が多いときは、表を二つ並べる（幅 4.65 ずつ、x は 0.6 と 5.4）。

## 8. 前と後・二つの案の比較

- 左右の `BOX`（幅 `W2`）。良い方・正解の方は白の塗りに緑の枠（`line: C.accent2`）、もう一方は薄い灰色の塗り。
- それぞれの箱に、見出し、短い説明、結論（「→ 直接直す」のように矢印から始める一行）を入れる。
- 大きさの違いを見せるなら、箱の上部に `STAT`（「1 行」「60+ ファイル」）。
- 間に矢印を置くと、「前から後へ」の変化として読める。

## 9. 流れ・手順・循環

- 段階が3〜4個なら `FLOW`（箱と矢印）。最後の箱や結論の箱に緑の枠、処理の中心に `"dark"`。
- 循環（観測→仮説→調べる→直す→観測）は、`FLOW` の下に、最後の箱から最初の方へ戻る線を3本の `ARW` で引き、線の上にラベルを置く。
- 分岐（調べた結果で次が変わる）は、一つの箱から斜めの矢印を2本出し、行き先を点線の箱にする。

## 10. 時間の比較（横棒）

一件ずつ待つと足し算、同時なら遅い方、のような時間の比較。

```js
const tx = (t) => 3.3 + t * 0.95;          // 時間 t を x に。右端のラベルが 12.733 を超えないように係数を決める
R(s, tx(0), y, tx(3) - tx(0) - 0.04, 0.42, { fill: C.text2, r: 0.06 });
T(s, "価格の照会 3分", tx(0) + 0.1, y, 2.5, 0.42, { fontSize: 13, bold: true, color: C.background1, valign: "middle" });
```

- 行の名前を左（x 0.6、幅 2.8）、合計を右端に置く。台本が問いにしている合計は「？」にする。
- 仮の数字なら、出典の行に「仮の数字」と書く。

## 11. 対応付け（札と結果）

依頼と結果を番号で結び付ける話（届いた順と頼んだ順が違う）。

- 左の列に依頼のカード2枚、右の列に結果のカード2枚を、届いた順に置く。
- 同じ番号どうしを斜めの矢印で結ぶ（交差させる）。片方を朱、もう片方を濃い紺にする。
- 下に「順番だけで結ぶと…」のひっかけの行を置く。

## 12. 選択肢と判定

```js
ROWS(s, X0, 5.0, XW, [
  { tag: "ひっかけ", text: "決まり文句が出たら終える", note: "文章と未実行の依頼が同じ応答で届く" },
  { tag: "次善策", text: "回数に上限を付ける", note: "暴走は防げるが、次にすべきことは決まらない" },
], { inline: true, rh: 0.46, head: "ほかの選択肢" });
```

- 1行に収まるなら `inline: true`、収まらないなら2段（`rh` 0.8〜1.05）。
- 選択肢の文は短く言い換えてよいが、判定は原典どおりにする。
- 本題の図の下に置くことが多い。図との間に 0.4 以上あける（`head` の見出しが上に出るため）。

## 13. 大きな数字

```js
STAT(s, "65", "%", X0, 1.7, 4.5, 1.35, { pt: 80 });
T(s, "命名規則のカテゴリの指摘のうち、誤検知の割合", X0, 3.1, 4.5, 0.4, { fontSize: 15, bold: true });
```

- 数字の下に、何の数字かを一行。その下に、その数字が意味することを灰色で。
- 「100 と 1000」のように二つの数字を並べるときは、一つの `T` に runs で並べる（間の「と」を小さく）。

## 14. 問いの箱

```js
QBOX(s, "一問", "画面の規約を rules に置いたが、paths を書き忘れた。この規約は、いつ読み込まれるか", X0, 6.0, XW, 0.75);
```

- 台本が「ここで一問です」と言う所に置く。答えはノートにだけある。
- スライドの最下部に置くことが多い。上の図と重ならないよう、図の下端を 5.85 までに収める。

## 15. 範囲の一覧（最後のスライド）

- 左に二つの表（論点と問題番号）、右に細い列（x 10.25、幅 2.48）で「このあと」すること（濃い箱）と、次回の予告（薄い箱）。
- 論点の名前は、表の列に1行で収まる短さに言い換える（13字前後）。
