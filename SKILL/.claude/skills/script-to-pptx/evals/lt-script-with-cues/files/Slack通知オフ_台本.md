# Slackの通知を全部オフにしたら仕事が速くなった話

## 発表の条件

| 項目 | 内容 |
| --- | --- |
| 発表の型 | 知見の共有（社内LT） |
| 聞き手 | 社内のエンジニア30人くらい。全員がSlackを毎日使っている。【仮】障害対応の当番を持つ人がいて、話し手の失敗のときに対応した人も含まれるかもしれない |
| 場 | 社内LT大会。会場とオンラインの両方。会場の人には手を挙げてもらい、オンラインの人にはリアクションで答えてもらう。オンラインでは笑い声が聞こえないので、笑いのセリフも情報を運ぶ形にする |
| 持ち時間 | 5分。【仮】質疑なし |
| 発表の後にしてほしいこと | 【仮】明日の午前中だけ、急ぎの連絡が来るチャンネルを一つ残して、ほかのSlackの通知をオフにしてみる。設定の場所を最後のスライドに載せる |
| 話す題材 | Slackの通知を全部オフにして2か月試した結果。Slackを見る回数が、1日80回くらいから10回くらいに減った（話し手のスクリーンタイム）。始めてすぐに、障害対応の呼び出しに40分気づかなかった失敗がある |
| 制約 | 障害を扱うので、影響と謝罪を先に言い、笑うのは話し手が作った仕組みの穴までにする。社内の発表なので、そのとき対応した人が聞き手にいる前提で話す |

## 聞き手に起こしたい変化

Slackの通知に作業を何度も中断されている社内のエンジニアが、
通知を切ると、障害の呼び出しのような急ぎの連絡を見逃すので、切れないと思っていたが、
急ぎと急がない連絡を同じ道で受けているから「全部すぐ見る」か「全部遅れる」かになるだけで、急ぎの道を一つ残せば残りは切れると気づき、
明日の午前中だけ、急ぎの連絡が来るチャンネルを一つ残して、ほかの通知をオフにしてみる。

## 台本

### 掴み

〔スライド：タイトルの下に、クイズ「通知を切る前、私はSlackを1日に何回見ていた？」〕
クイズです。
通知を切る前、私は、Slackを1日に何回見ていたでしょう。
〔間〕
50回より多いと思う方は、手を挙げるか、リアクションをください。
〔手を挙げてもらう：約5秒。会場の手と、オンラインのリアクションの両方を見る〕
ありがとうございます。

〔スライド：「1日 約80回」。下に「自分のスクリーンタイム／8時間で割ると6分に1回」〕
答えは、80回くらいです。
自分のスクリーンタイムで数えました。
仮に、勤務時間の8時間で割ると、6分に1回です。
【仮】ウルトラマンなら、2回戦えます。
〔間〕
〔笑いが起きたら待つ〕

〔スライド：「通知を全部オフ → 2か月後、1日 約10回」〕
そこで、通知を全部オフにしました。
2か月たった今は、1日10回くらいです。
今、「障害のときは、どうするんだ」と思った方。
その心配は、正しいです。
〔間〕

### 背景

〔スライド：【仮】書きかけの変数名だけが残ったエディタの画面〕
では、なぜ、そんな危ないことをしたのか。
【仮】申し遅れました、〇〇チームの〇〇です。
6分に1回見ていると、作業も6分ごとに途切れます。
【仮】Slackから戻ってくると、何を書こうとしていたか、忘れています。
【仮】エディタには、書きかけの変数名だけが残っています。
〔間〕
【仮】それなら、全部切ってしまおう、と思いました。

### つまずき

〔スライド：「始めてすぐ、障害の呼び出しに40分気づかなかった」〕
ところが、始めてすぐに、大きな失敗をしました。
障害対応の呼び出しに、40分、気づかなかったんです。
【仮】その間、チームのメンバーが、代わりに対応してくれました。
【仮】お客様への影響は、〇〇でした。
対応してくれた皆さん、本当にすみませんでした。
〔間〕

〔スライド：「1日10回見るなら、8時間で割って48分に1回」〕
なぜ40分も気づかなかったのか、あとで計算してみました。
見るのが1日10回なら、8時間で割って、48分に1回です。
48分に1回しか見ない仕組みなら、40分気づかないのは、バグではありません。
仕様です。
〔間〕
〔笑いが起きたら待つ〕

### 原因の発見

〔スライド：「この仕様の、何が悪かったのか？」〕
では、この仕様の、何が悪かったと思いますか。
〔間〕
私は最初、通知を切ったことだと思いました。
でも、オンに戻すと、6分に1回に戻るだけです。

〔スライド：通知オン「急ぎにすぐ気づく／急がない連絡にも全部呼ばれる（6分に1回）」、通知オフ「呼ばれない／急ぎの連絡も次に見るまで待つ（48分に1回）」〕
オンなら、急ぎの連絡に、すぐ気づけます。
その代わり、急がない連絡にも、全部呼ばれます。
オフなら、急がない連絡には、呼ばれません。
その代わり、急ぎの連絡も、次に見るまで待たされます。
〔間〕
原因は、通知を切ったことではありませんでした。
急ぎも急がないも、同じ道で受けていたことでした。

### やり方と結果

〔スライド：【仮】変えたこと「障害対応チャンネルだけ通知オン／急ぎはこのチャンネルへ、とチームに依頼／ほかは全部オフ」〕
だから、急ぎの連絡の道だけを、分けることにしました。
【仮】障害対応のチャンネルだけ、通知を戻しました。
【仮】チームには、急ぎはこのチャンネルに、と頼みました。
【仮】それ以外の通知は、全部オフのままです。

〔スライド：「Slackを見る回数　1日 約80回 → 約10回」。下に「2か月／私一人／スクリーンタイム」〕
そうして、2か月たちました。
仕事は、速くなりました。
【仮】ただ、速さは、測っていません。
【仮】体感です。
〔間〕
〔笑いが起きたら待つ〕
測ったのは、Slackを見る回数です。
1日80回くらいから、10回くらいになりました。
2か月間の、私一人の、スクリーンタイムの数字です。
【仮】障害の呼び出しに気づかなかったのは、あの1回だけです。

### 一般化と持ち帰り

〔スライド：「障害のときは？ → 急ぎの道を一つだけ残す」〕
だから、最初の「障害のときは、どうするんだ」には、こう答えられます。
急ぎの道を一つだけ残せば、残りの通知は、切れます。
見逃すのが怖いのは、急ぎの連絡だけだからです。
届く連絡のほとんどが急ぎ、という仕事でなければ、皆さんにも使えると思います。
全部を切る必要は、なかったんです。
なので、タイトルを一か所、訂正させてください。

〔スライド：タイトルの「全部」に取り消し線を引き、「ほぼ全部」と書き直したもの〕
全部では、ありませんでした。
ほぼ全部、です。
〔間〕
〔笑いが起きたら待つ〕

〔スライド：「明日の午前中だけ、通知を"ほぼ全部"オフに」と、【仮】自分のSlackで撮った通知の設定画面〕
皆さんも、明日の午前中だけ、通知をほぼ全部オフにしてみてください。
「ほぼ」のところには、急ぎの連絡が来るチャンネルを、一つだけ残してください。
設定の場所は、このスライドに載せています。
【仮】スライドは、LT大会のチャンネルにも置いておきます。
ありがとうございました。

## 確かめてほしいこと

- 【発表の前に必ず】障害のときの影響と、話してよいかの了解。
  つまずきの【仮】の2行（代わりに対応した人、お客様への影響）を、実際の内容にする。
  お客様に大きな影響が出ていたなら、「バグではありません。仕様です。」の笑いは使わず、48分に1回の計算だけを落ち着いて話す。
  対応した人が会場かオンラインにいる可能性が高いので、話す前に本人たちの了解を取る。
- 【発表の前に必ず】失敗の後に、実際に何を変えたか。
  台本では【仮】で「障害対応のチャンネルだけ通知を戻し、チームに急ぎはそこへ書くよう頼んだ」としている。
  違うなら、やり方と結果の【仮】の3行を直す。
  最後の「全部ではなく、ほぼ全部」の締めと頼む行動は、Slackの通知を一部戻したことが前提である。
  障害の呼び出しを電話などSlack以外で受けるようにして、Slackの通知は今も全部オフなら、締めを例えば「タイトルは訂正しません。Slackの通知は、今も全部オフです。障害のときだけ、電話が鳴ります。」に替え、頼む行動もそれに合わせる。
- 【発表の前に必ず】80回と10回が、スクリーンタイムのどの数字か（スマホかPCか、開いた回数か通知の数か、1日全体か勤務時間か）。
  台本は「Slackを見る回数」と言っている。
  1日全体の数なら、「8時間で割ると6分に1回」「48分に1回」は実際より短い間隔になるので、割る時間を変えるか、回数だけを言う。
  10回が今の数ではなく2か月の平均なら、掴みの「2か月たった今は」を「2か月で」に替える。
- 仕事が速くなったことの根拠。
  台本では【仮】で「速さは、測っていません。体感です。」としている。
  測った数字や、目に見える例（〇〇が〇〇で終わるようになった、など）があれば、その2行を替える。
  替えるときは、続く「測ったのは、Slackを見る回数です。」も合わせて直す。
- 「障害の呼び出しに気づかなかったのは、あの1回だけです」が事実か。
- 背景の【仮】（自己紹介、通知を切ろうと思ったきっかけ）を、実際のものにする。
- 掴みのウルトラマンの例え【仮】は、言いにくければ別のものに替えるか、削る。
- オンラインの配信ツールでリアクションが使えるか。
  使えなければ、掴みの頼み方を「チャットに『はい』と書いてください」に替える。
- 質疑があるなら、質疑の後に「明日の午前中だけ、ほぼ全部オフにしてみてください」をもう一度言って終える。
- 最後のスライドに、自分のSlackで撮った通知の設定画面を載せる。
  LT大会のチャンネルにスライドを置けないなら、台本の最後の【仮】の1行を消す。
  LTの翌日が休みなら、「明日の午前中」を次の出勤日に言い換える。
