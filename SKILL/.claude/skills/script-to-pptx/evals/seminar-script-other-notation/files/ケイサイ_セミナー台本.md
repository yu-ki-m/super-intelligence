# ケイサイ セミナー台本「差し戻しメールを書かない月末へ」

| 項目 | 内容 |
|---|---|
| 枠 | 展示会のセミナー枠、20分（質疑は別）、対面、約50名 |
| 聞き手 | 中堅企業の経理担当が中心で、経理部長クラスが少し |
| ゴール | セミナーのあとに、30日間の無料トライアルを申し込んでもらう |
| 使った材料 | 製品資料（kaisai-factsheet.md）で、事実として話す数字と引用は、この資料にあるものと、そこから計算したものだけにした |
| 長さの目安 | せりふは約4,400字（注記と代わりのせりふを除く）で、1分に270〜300字の速さなら15〜16分、挙手・クイズ・QRコードの待ちと間を足して17〜19分（残りは、笑いや挙手が長引いたときの余裕） |

台本の中の【仮】は、仮置きした内容である。
【要確認】は、製品資料だけでは裏付けが取れていない内容である。
どちらも本番の前に差し替えるか、確認してから話す。
一覧は、末尾の「仮置きと確認事項」にまとめた。

## 話の設計

### 聞き手の認識の変化

話を聞く前の聞き手は、「差し戻しは、経理が月末に見つけて直すしかない」と考えている、と想定した。
話を聞いたあとには、「差し戻しは、申請した本人がその場で気づけば減らせるので、次の月末に自社の数字で確かめてみよう」と考えてもらうことを目指す。
無料トライアルの申し込みは、この「確かめてみよう」を行動にしたものとして提案する。

### 全体を通す題材

題材は「差し戻しのメール」に絞った。
製品資料の中でいちばん強い材料は、導入企業の経理課長の「差し戻しのメールを書く仕事が、ほとんどなくなりました」という言葉である。
経理担当にとって、差し戻しのメールは毎月の実感がある題材なので、冒頭から自分の話として聞いてもらえる。
冒頭の挙手で差し戻しのメールを話題にし、だんだん丁寧になるメールで笑いを取る。
導入事例では、同じ話題を経理課長の言葉で回収し、最後に冒頭の質問へ戻って締める。

笑いの対象は、差し戻しという仕組みと、話し手自身に限った。
申請する人を笑う場面は架空の佐藤さんだけにとどめ、「悪気はない」と添えている。
経理の場面は、聞き手が「あるある」と共感できる形にし、聞き手自身を笑いの対象にはしていない。
年間への換算は、計算の前提をスライドに出し、試算であることがわかるようにする。

## 台本

【】で始まらない行は、そのまま声に出すせりふである。
せりふの途中にある【仮：…】は、差し替える言葉の置き場所である。
【スライド】は画面に出すもの、【動き】と【間】は話し手の動作を示す。
「>」で始まる行は、予想と違う反応が来たときに使う、代わりのせりふである。

### 1. 先月の差し戻しメール（0:00〜1:30）

【スライド1】タイトル「差し戻しメールを書かない月末へ」、副題「経費精算SaaS ケイサイのご紹介」
【動き】名乗る前に、演台から一歩前に出て、質問から入る。

皆さん、こんにちは。
始める前に、ひとつだけ質問させてください。

【スライド2】「先月、差し戻しのメールを1通も書かなかった方」

先月、経費精算の差し戻しのメールを、1通も書かなかったという方。
手を挙げていただけますか。

【間】3秒、会場をゆっくり見回す。

……いらっしゃいませんね。
ありがとうございます。
いま手が挙がらなかったことで、このセミナーをやる意味が証明されました。

> 【手が挙がった場合】
> あ、いらっしゃいました。
> あとで、ぜひ秘訣を教えてください。
> 本気で伺いたいです。

では、逆に伺います。
先月、10通以上書いたという方。

【間】挙手を待つ。

ありがとうございます。
いま手を挙げてくださった皆さんが、今日の主役です。

> 【手がほとんど挙がらない場合】
> 控えめですね。
> では、心の中で挙げていただければ十分です。

改めまして、【仮：会社名】で、経費精算のサービス「ケイサイ」を担当しております、【仮：氏名】です。
これから20分、差し戻しのメールの話をします。
そして最後に、そのメールが本当に減るのかを、御社で確かめていただく方法を、ひとつご提案します。

### 2. 差し戻し1件の往復（1:30〜4:30）

【スライド3】差し戻しメールの1回目・2回目・3回目の文面を、上から順に並べる。

差し戻しのメールには、段階がありますよね。
1回目は、こうです。
「ご確認をお願いします。」
2回目。
「お手数ですが、ご確認をお願いいたします。」
3回目。
「たびたび恐れ入りますが、念のため、いま一度ご確認いただけますと幸いです。」

【間】

文面は、回を重ねるごとに丁寧になります。
そして、書いている人の気持ちは、その逆の方向に進んでいきます。

【動き】笑いが来たら収まるまで待ち、来なければ、うなずいて次へ進む。

書く側にとって大変なのは、1通を書く時間です。
文面を考えて、相手の顔を思い浮かべて、角が立たないように言い回しを直す。
送信ボタンを押す前に、もう一度読み直す。

受け取った側も、大変です。
受け取った人は、そこから探す旅に出ます。
財布の中、カバンの底、そして、自分の記憶の底です。
この日、誰と行ったんだっけ。
何の打ち合わせだったっけ。

【仮】次の2行は、話し手自身の実話に差し替える（実話がなければ、この2行と、この節の最後の1行を削る）。

私は先日、スーツのポケットから、きれいに洗濯された領収書を見つけました。
金額は、もう読めませんでした。

ここで、少しだけ真面目な話をさせてください。

【スライド4】差し戻し1件の往復の図
【図の中身】申請した人 → 承認する人 → 経理 →（差し戻し）→ 申請した人 → 承認する人 → 経理
【図の描き方】2周目の矢印を赤にし、2周目の承認は会社によるので点線にする。

差し戻しが1件起きると、何が起きるか。
申請は、申請した人から承認する人へ、承認する人から経理へと届きます。
経理の方が間違いに気づいて、申請した人に戻します。
申請した人が直して、もう一度出します。
直した申請は、もう一度、経理の確認を通ります。
会社によっては、承認もやり直しです。
差し戻し1件で、同じ申請が、もう一周するわけです。

しかも、この一周は、間違いに気づくのが遅いほど、時間がかかります。
領収書を受け取ったその日なら、領収書は手元にありますし、誰と何のために使ったかも覚えています。
月末になると、まず思い出すところから始まります。
領収書のほうは、ポケットの中で洗濯されているかもしれません。

### 3. 差し戻しの理由の1位（4:30〜7:30）

では、差し戻しは、どんな理由で起きているのか。
ここで、クイズです。

【スライド5】「差し戻しの理由で、いちばん多いのは？」A 上限を超えた金額／B 勘定科目の選び間違い／C 領収書の添付漏れ／D 同じ領収書の二重申請

ケイサイを使っている120社の、2025年度のデータです。
差し戻しの理由で、いちばん多かったのはどれでしょうか。
A、上限を超えた金額。
B、勘定科目の選び間違い。
C、領収書の添付漏れ。
D、同じ領収書の二重申請。

手を挙げていただきます。
Aだと思う方。
Bだと思う方。
Cだと思う方。
Dだと思う方。

【動き】挙手の結果を一言で実況する。

> 【Cが多い場合】
> Cが多いですね。
> さすが、毎月ご覧になっている皆さんです。
>
> 【割れた場合】
> きれいに割れましたね。

【スライド6】正解「1位 領収書の添付漏れ／2位 勘定科目の選び間違い」
【スライド6の注記】出典「ケイサイの利用データ（2025年度、利用企業120社）」

正解は、C、領収書の添付漏れです。
そして2位は、B、勘定科目の選び間違いでした。

2位のほうは、皆さんなら、すぐに例が浮かぶと思います。
会議費なのか、交際費なのか。
消耗品費なのか、工具器具備品なのか。

1位も2位も、悪意のある不正の話ではありません。
特に1位の添付漏れは、うっかりの代表です。

うっかりには、やっかいな性質があると、私たちは考えています。
知らないから間違えるのではありません。
知っているのに、忘れるんです。
領収書を付けなければいけないことは、全員が知っています。
ですから、規程をもう一度周知しても、なかなか減りません。

ちなみに、これはケイサイを使っている会社のデータです。
仕組みを入れても、人は領収書を付け忘れますし、勘定科目も選び間違えます。
うっかりは、なくせません。
私たちが変えられると考えているのは、うっかりに気づくタイミングのほうです。

### 4. 間違いに気づくタイミング（7:30〜8:30）

【スライド7】左に「いま：経理が、月末に気づく」、右に「ケイサイ：申請した本人が、その場で気づく」を並べる。

いま、多くの会社で、間違いに気づくのは経理の方です。
それも、月末にまとめて確認するときです。
経理の方は、会社の中で、いちばん最後に間違いに気づく係を引き受けている、とも言えます。

ケイサイが変えるのは、この順番です。
経理が月末にしていた確認のうち、規程に照らせば判定できるものを、申請の時点に前倒しします。
間違いに、申請した本人が、申請したその場で気づく。
それが、ケイサイの考え方です。

では、実際にどう動くのか。
領収書1枚の流れで、ご覧ください。

### 5. 佐藤さんの領収書（8:30〜13:30）

【スライド8】架空の営業担当「佐藤さん」のイラスト

ここからは、架空の営業担当、佐藤さんに登場してもらいます。
佐藤さんは、仕事はできるんですが、領収書を財布に入れたまま、1か月寝かせるタイプです。
皆さんの会社にも、たぶん、いらっしゃると思います。

【スライド9】スマホで領収書を撮影する画面と、日付・金額・支払先が入った申請の下書きの画面
【仮】画面のキャプチャを使う前提で書いたので、ライブで撮る場合は、ここで実物の領収書をスマホで撮って画面に映す。

佐藤さんが、取引先からの帰りに、タクシーを降りました。
受け取った領収書を、その場でスマホで撮ります。
すると、ケイサイが日付と、金額と、支払先を読み取って、申請の下書きを作ります。
佐藤さんがやったのは、撮っただけです。

ここで見ていただきたいのは、順番です。
これまでの申請では、多くの場合、領収書は最後に付けるものでした。
最後に付けるものは、忘れます。
ケイサイでは、領収書を撮るところから、申請が始まります。
【要確認】撮影した画像が、そのまま申請の添付になるか
1位だった添付漏れが、起きにくい順番です。

【スライド10】申請の時点で出る通知の画面【仮：実際の通知の画面に差し替える】

次に、佐藤さんは勘定科目を選びます。
急いでいたので、「会議費」を選んでしまいました。
タクシー代なのに、です。
ケイサイは、ここで、勘定科目の選び間違いの疑いを、佐藤さんに知らせます。
【要確認】タクシー代を「会議費」にしたこの例で、通知が出るか
月末に経理の方が見つけるはずだった間違いに、佐藤さん本人が、タクシーを降りて数分で気づくわけです。
金額が規程の上限を超えている場合も、同じように、申請の時点で知らせます。

さて、佐藤さん。
撮ったあとの紙の領収書は、やはり財布で寝かせていました。
1か月後、財布の中から、その領収書を見つけます。
もう申請したことは、忘れています。
もう一度、申請しようとします。
ケイサイは、ここで、同じ領収書の二重申請を知らせます。
佐藤さんに、悪気はありません。
ただ、経理の方にとっては、悪気がなくても見逃せない1件です。

【スライド11】承認する人のスマホの画面（承認のボタンと、差し戻しの理由の選択肢）

申請は、佐藤さんの上司の課長に届きます。
ところで、申請が寝ている場所は、佐藤さんの財布だけではありません。
承認を待つ一覧の中でも、申請は寝ています。
課長が出張中なら、なおさらです。
ケイサイなら、課長は、移動中でもスマホで承認できます。

差し戻すときは、理由を選択肢から選べます。
差し戻しのコメント欄に、「確認して」とだけ書いてあるのを、ご覧になったことはありませんか。
何を確認すればいいのかを、まず確認するところから始まる、あれです。
理由が選択肢になっていれば、佐藤さんは、何を直せばいいかがすぐに分かります。

もうひとつ、理由が選択肢で残ると、どの理由の差し戻しが多いのかを数えられます。
さきほどのクイズのデータも、こうして残った理由を数えたものです。
【要確認】理由ごとの件数を見る画面や出力があるか、利用データは選択肢で残った理由を集計したものか

【スライド12】承認済みの申請が、会計ソフトの仕訳になる流れの図【要確認：連携できる会計ソフトの名前を載せる】

最後に、課長が承認した申請は、会計ソフトに仕訳として連携されます。
対応している会計ソフトなら、経理の方が、承認済みの申請を見ながら仕訳を手で打ち直す必要はありません。

ここまでを、まとめます。
佐藤さんは、撮って、知らされたところを直しただけ。
課長は、スマホで選んで、押しただけ。
経理の方は、月末に間違いを探して、メールを書く仕事が減ります。
申請する人、承認する人、経理の方。
この三者の手間をそれぞれ減らすのが、ケイサイです。

### 6. 導入事例（13:30〜17:00）

【スライド13】導入事例「株式会社サンプル精機（製造業、従業員420名）」【要確認：社名を出してよいか】
【スライド13の中身】差し戻し「約180件/月 → 約40件/月」と、確認の日数「5営業日 → 2営業日」を左右に並べる。
【スライド13の注記】出典「導入企業へのインタビュー（2026年5月）」

では、実際に入れた会社で、何が変わったのか。
株式会社サンプル精機さんの例をご紹介します。
製造業で、従業員は420名の会社です。

導入前、差し戻しは月に約180件ありました。
経理担当の方は3名で、毎月、月末の5営業日を、精算の確認に使っていました。

導入から6か月。
差し戻しは、月に約40件になりました。
確認に使う日数は、5営業日から2営業日になりました。

正直に申し上げます。
差し戻しは、ゼロにはなっていません。
営業としては「ゼロになりました」と言いたいところですが、40件と伺っているので、言えません。
ただ、月に約180件あった差し戻しが、約40件です。
毎月140件ほどの「もう一周」が、減ったということです。

【スライド14】年間にすると「60営業日 → 24営業日」
【スライド14の注記】「毎月同じと仮定し、1か月を約20営業日として換算した試算」

日数のほうも、年間にしてみます。
毎月同じだとすると、5営業日の12か月分で、60営業日です。
1か月の営業日をおよそ20日とすると、3か月分にあたります。
この会社の経理チームは、1年のうち3か月分を、月末の精算の確認に使っていた計算になります。

【間】

それが導入後は、2営業日の12か月分で、24営業日です。
差は36営業日。
1か月半を超える時間が、チームに戻ってきた計算です。

皆さんの会社では、月末の何営業日を、精算の確認に使っているでしょうか。
その日数に、12を掛けてみてください。

【間】5秒、聞き手が計算するのを待つ。

それが、皆さんのチームが1年のうちに、月末の確認に使っている日数です。
部長の皆さんには、その日数が減ったら、チームに何をお願いしたいかを、思い浮かべていただけたらと思います。

【スライド15】経理課長の言葉「差し戻しのメールを書く仕事が、ほとんどなくなりました」
【スライド15の注記】出典「導入企業へのインタビュー（2026年5月）」
