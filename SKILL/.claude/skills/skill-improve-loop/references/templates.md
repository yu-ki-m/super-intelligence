# 記録の書式

設計フォルダに書く各ファイルの書式。項目は案件に合わせて増減してよいが、ID・ラベル・反証条件・意味を担う所・復元条件は省かない。後から「なぜこの設計になったか」「何が起きたら見直すか」を追えなくなるため。

ラベル（[観察] [発言] [資料] [推論] [仮定] [テスト] [調査]）の意味は SKILL.md の「証拠の扱い」を参照。

## 目次

1. 00_進行.md
2. 00_壁打ちノート.md
3. 01_設計ブリーフ.md

## 1. 00_進行.md

```markdown
# <スキル名> 設計の進行

- 状態：進行中 / 完了 / 中止
- 対象：既存（<スキルのフォルダ>）／新規
- 深さ：軽量 / 標準 / 徹底
- 起動時の決定：
  - ループ内のスキル：skill-creator（<フォルダ>）／<別のスキル>／使わない
  - 反復の上限：N 回（上限として扱う／その回数まで続ける）
  - 反映の方法：写しで直し最後に反映／本物を直接直す／写しだけ渡す（新規の反映先：<パス>）
  - 予算：テストの実行 N 回、トークン数 N（上限なしは「なし」）
  - 開始時の版：workspace/start-snapshot（写しで直す場合）
  - 既定のまま決めたもの：（確かめられなかった項目。[仮定]）
- 現在の工程：壁打ち／工程X（反復 NN の A〜G のどこまで）
- 反復番号：数えた回数 N（iter-NN の番号 M）
- 使った予算：テストの実行 N 回、トークン数 N（scripts/workspace.mjs budget の結果）
- 試作する案：C-01、C-02
- 今の版：C-01 → skill/C-01/<スキル名>/（反復 NN）

## 再開の履歴
| 日付 | 再開した地点 | メモ |
|---|---|---|

## 前の工程に戻った記録
| 日付 | 反復 | 戻った工程 | 理由 |
|---|---|---|---|

## 未解決事項・利用者への確認事項
| ID | 内容 | 種別（仮定の確認／判断依頼／技術確認） | 確認先 | 状態 |
|---|---|---|---|---|
```

## 3. 01_設計ブリーフ.md

括弧の番号は設計観点の No.。各項目にラベルを付ける。

```markdown
# 設計ブリーフ

| 項目 | 記入内容 | 根拠 |
|---|---|---|
| 使う人と場面 | 誰が、どんな状況で、どんな言い方で頼むか。頻度、入力の大きさ | |
| 成果物を使って判断する人（1） | 起動する人と結果を受け取る人が違えば両方 | |
| 答える問いと使う証拠（2） | | |
| 対象範囲（3） | | |
| 成果物と渡す先（4） | 会話を見られない人に渡すなら、何だけで判断できるか | |
| 完了・部分完了・保留（5） | | |
| 誤りの影響（6） | 見逃し・誤検出・誤操作・遅延が、誰にどの程度効くか | |
| 発動すべき依頼・すべきでない依頼（7） | 言い方の例 | |
| 主指標（55・57） | テストの合格率、フィードバック、所要時間とトークン数など | |

| 変えてよい範囲 | SKILL.md・references・scripts・evals。name は変えない | |
| 起動時に決めたこと | ループ内のスキル、上限、反映の方法、予算 | |
```

## 8. iter-NN/省いた文言.md

SKILL.md から省いた文言だけを記録する。手順・条件・確認は、ここで削らない。

```markdown
# 反復NN 省いた文言

|---|---|---|---|---|---|---|---|
| R-01 | C-01／SKILL.md の「手順」 | | 削除／短縮（後の文言）／ほかの表現に任せる | 重複／前置き／言い直し／言われなくてもすること | | 残した／戻した（理由） | |
```
