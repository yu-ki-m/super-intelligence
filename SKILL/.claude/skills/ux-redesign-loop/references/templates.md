# 記録の書式

各ファイルの書式。項目は案件に合わせて増減してよいが、ID・ラベル・反証条件・負担の移転先・復元条件は省かない。後から「なぜこの設計になったか」「何が起きたら見直すか」を追えなくなるため。

ラベル（[観察] [発言] [資料] [推論] [仮定] [机上] [AI模擬]）の意味は SKILL.md の「証拠の扱い」を参照。

## 1. 00_進行.md

```markdown
# <案件名> 設計の進行

- 状態：進行中 / 完了 / 中止
- 深さ：軽量 / 標準 / 徹底（反復の上限 N 回）
- 現在の工程：工程X（反復 NN の A〜G のどこまで）
- 保存先：<パス>

## 再開の履歴
| 日付 | 再開した地点 | メモ |
|---|---|---|

## 前の工程に戻った記録
| 日付 | 反復 | 戻った工程 | 理由 |
|---|---|---|---|

## 未解決事項・ユーザーへの確認事項
| ID | 内容 | 種別（仮定の確認／判断依頼／技術確認） | 確認先 | 状態 |
|---|---|---|---|---|
```

## 2. 01_設計ブリーフ.md

マニュアル7.1の表を使い、各項目にラベルを付ける。

```markdown
# 設計ブリーフ

| 項目 | 記入内容 | 根拠 |
|---|---|---|
| 対象ユーザー・状況 | 誰が、いつ、どの頻度・量・熟練度・権限で、どれくらい中断されながら使うか | [資料]/[仮定]… |
| 達成する成果 | 業務上の成功（操作の完了ではなく、正しい結果の確定） | |
| 対象範囲 | 開始条件、終了条件、含む例外（中断・失敗・引継ぎ） | |
| 現状と根拠 | 基準値、未測定事項と計測方法 | |
| 主指標 | 最も改善したい成果 | |
| 悪化を認めない条件 | 正確性、復旧、権限、アクセシビリティ等 | |
| 変更可能な前提 | 画面、工程、役割、データ、運用 | |
| 制約と確認先 | 確認済みか未確認か | |

## 速度と正確性が衝突したときの優先順位
## 初心者と熟練者で優先順位が異なる点
```

- 方法：シナリオ走査 / ヒューリスティクス点検 / アクセシビリティ点検 / スクリーンショット確認 / AI模擬評価

| ID | 箇所 | 問題 | 該当する観点 | 重大度 |

| シナリオ | 評価者の理解・行動 | 迷い・誤解 | 設計者の説明が必要だった箇所 |

| 仮説 | 結果（机上で破綻なし／机上で問題あり／未判定） | 根拠（T-ID） | 実ユーザーで確かめること |

## 8. iter-NN/反復記録.md

```markdown
# 反復NN 反復記録

2. 比較した異なる仮説：
3. 実際に変更した体験と操作（仕事の仕組み・状態・削減のどれが変わったか）：
4. 見つかった改善と悪化（[机上]/[AI模擬] の区別つき）：
5. 残すもの、統合するもの、削るもの：
6. 未検証事項と、次に戻る工程（理由）：
7. 判断を見直す条件：

## 各案の判定

|---|---|---|

## 失敗パターンの点検（マニュアル8章）

## 続けるか止めるか

```
