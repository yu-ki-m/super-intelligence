# FlowTS 構文・実行仕様書

仕様バージョン：0.4.0  
状態：Draft  
基盤構文：TypeScript  
ファイル拡張子：`.flow.ts`

## 1. 適用範囲

1. FlowTSはTypeScriptの構文を基盤とする。
2. TypeScriptに存在する通常の式、文、型、関数、制御構造を使用できる。
3. FlowTSは、引数を渡せる `goto` 文と、引数を受け取れるラベル付きブロックと、意味的な作業を指示する組み込み操作 `実施<T>()` を定義する。
4. FlowTSソースはAI直接実行モードとエンジン実行モードで解釈できる。
5. 本仕様で上書きしない構文・評価規則はTypeScriptに従う。
6. 言語組み込み操作に専用ライブラリのインポートは必要ない。

## 2. 実行モード

### 2.1 AI直接実行モード

生成AIがFlowTSの構文と作業指示を解釈して処理を進める。

実行環境は、対象関数、引数、利用可能な能力を指定する。

生成AIは条件式、反復、関数呼び出し、`goto`、組み込み操作を記述された意味に従って解釈する。

実際に確認していない情報や、実行していない外部操作の結果を生成してはならない。

モデル単独での解釈は、構文・状態遷移・型の完全な遵守を技術的に保証するものではない。

### 2.2 エンジン実行モード

エンジンはソースを解析し、標準TypeScriptの処理とFlowTSの拡張構文を実行する。

組み込み操作は担当に応じて外部処理へ委譲する。

エンジンは少なくとも以下を管理する。

- 変数と状態
- 条件分岐と反復
- gotoによる制御移動
- 組み込み操作の入出力
- 型検証
- 例外と終了処理

### 2.3 共通意味

両モードは、同じ入力と同じ操作結果に対して同一の制御規則を適用する。

外部操作、推論結果、実行時刻、物理的な並行性の一致は要求しない。

## 3. 関数

### 3.1 宣言

関数は標準TypeScriptの構文で定義する。

```typescript
function analyze(input: Input): Result {
  return process(input);
}
```

非同期処理を使用する場合は `async` を指定する。

```typescript
async function analyze(
  input: Input
): Promise<Result> {
  return await 実施<Result>(
    "入力情報を分析する",
    { input }
  );
}
```

関数宣言、関数式、アロー関数、クラスメソッドを使用できる。

### 3.2 関数本体

関数本体には通常のTypeScript文を記述できる。

ステップラベルは必須ではない。

関数の実行開始位置は、通常のTypeScriptと同様に関数本体の先頭とする。

### 3.3 実行順序

関数内の文は、通常のTypeScriptの評価規則に従って順番に実行する。

制御構造、例外、関数終了、`goto` などにより制御が移動する場合を除き、次の文へ進む。

### 3.4 関数終了

`return` は現在の関数を終了する。

`throw` は例外を送出する。

戻り値には関数の戻り値型を適用する。

## 4. 制御構文

次のTypeScript構文を使用できる。

| 構文 | 動作 |
|---|---|
| `if / else` | 条件分岐 |
| `switch / case` | 複数条件による分岐 |
| `for` | 回数・条件による反復 |
| `for...of` | コレクションの反復 |
| `for...in` | プロパティの列挙 |
| `while` | 前判定の反復 |
| `do...while` | 後判定の反復 |
| `break` | 対象のループやswitchから脱出 |
| `continue` | 次の反復へ進む |
| `return` | 関数を終了 |
| `throw` | 例外を送出 |
| `try/catch/finally` | 例外処理 |
| `async/await` | 非同期処理 |
| `Promise.all` | 複数の非同期処理をまとめて待機 |

条件式は実行時に確定した値を評価する。

生成AIによる意味判断が必要な場合は、組み込み操作の戻り値を条件として使用する。

## 5. ラベル

### 5.1 構文

```typescript
ラベル名: {
  // 処理
}
```

引数を受け取るラベル付きブロックは、ラベル名の後に引数の並びを書く。

```typescript
ラベル名(引数名: 型, 引数名: 型): {
  // 処理
}
```

ラベル名はTypeScriptの識別子規則に従う。

日本語識別子を使用できる。

### 5.2 配置

`goto` のジャンプ先となるラベル付きブロックは、対象関数本体の直下に定義する。

同一関数内のジャンプ先ラベル名は一意でなければならない。

通常のJavaScriptのラベル付きループは、別の規則に従う。

### 5.3 実行

ラベル付きブロックは通常のブロックとして実行する。

ラベルの位置に通常の制御が到達した場合、そのブロックを実行する（引数を持つラベル付きブロックを除く。5.4 を参照）。

ブロック末尾に到達すると次の文へ進む。

ラベルそのものは特別な実行処理を行わない。

### 5.4 ラベルの引数

- 各引数は「引数名: 型」の形で書く。型注釈は省略できない。
- 既定値、省略可能な引数（`?`）、残余引数（`...`）、分割代入は使用できない。
- 同じラベルの中で、引数名は一意とする。
- 引数名には、関数の引数と、関数本体の直下で宣言された変数と同じ名前を使用できない。
- 引数は、そのラベル付きブロックのローカル変数として扱い、再代入できない（`const` と同じ）。
- 引数は、ブロックに入るたびに、`goto` で渡された値で初期化する。
- 引数を持つラベル付きブロックには、`goto` でだけ入れる。直前の文の末尾から制御が流れ込む経路があってはならない。関数本体の先頭にも置けない。

## 6. goto

### 6.1 構文

```typescript
goto ラベル名;
goto ラベル名(式, 式);
```

ジャンプ先は同一関数に定義された、goto対象のラベル付きブロックとする。

引数を持つラベル付きブロックへは、ラベルの引数と同じ数の式を渡す。引数を持たないラベル付きブロックへは、引数を渡さない。

各式の型は、対応するラベルの引数の型に代入可能でなければならない。

ジャンプ先を文字列や変数の値で動的に指定することはできない。

### 6.2 実行

`goto` が実行された場合、指定ラベル付きブロックの先頭へ制御を移す。

- 引数があれば、`goto` の位置で左から順に評価する。評価中に例外が起きた場合、制御は移らない。
- 移動先ブロックの引数を、評価した値で初期化する。
- `goto` より後の文は実行しない。
- 共有スコープで有効な変数の値を保持する。
- 移動先ブロックのローカル変数は再入時に初期化される。
- 実行済みの外部副作用は取り消さない。
- 制御構造からの脱出に必要な終了処理を保持する。

### 6.3 使用可能位置

`goto` は、同一関数内の通常ブロック、`if`、`switch`、ループの内部から使用できる。

次は禁止する。

- 関数・コールバックの境界を跨ぐジャンプ
- ネストした関数から外側のラベルへのジャンプ
- ラベル付きブロックの途中へのジャンプ
- `try`、`catch`、`finally` 内部からのジャンプ
- 初期化されていない変数を使用可能にしてしまうジャンプ
- 宣言の再評価によって通常の字句スコープの意味を維持できないジャンプ

後方ジャンプは、変数のライフタイムと再初期化の整合性を検査したうえで許可する。

### 6.4 通常の制御との組み合わせ

```typescript
async function process(items: Item[]): Promise<Result> {
  let error: string | null = null;

  for (const item of items) {
    if (item.skip) continue;

    const result = await validate(item);

    if (!result.ok) {
      error = result.reason;
      goto エラー対応;
    }
  }

  return { status: "completed" };

  エラー対応: {
    return {
      status: "failed",
      reason: error
    };
  }
}
```

### 6.5 引数の受け渡し

`goto` の引数を使うと、共有スコープの変数を使わずに、`goto` の位置で分かっている値を移動先へ渡せる。

```typescript
async function 確認(対象: string[]): Promise<確認結果> {
  for (const 項目 of 対象) {
    const 判定 = await 実施<判定結果>(
      "項目を検証する",
      { 項目 }
    );

    if (!判定.妥当) goto 差し戻し(項目, 判定.理由);
  }

  return { 状態: "完了" };

  差し戻し(項目: string, 理由: string): {
    return { 状態: "差し戻し", 項目, 理由 };
  }
}
```

移動先が複数の場所から呼ばれる場合も、それぞれの `goto` が自分の値を渡す。

## 7. 組み込み操作

### 7.1 実施

FlowTSは、意味的な作業を表す組み込み操作 `実施<T>()` を定義する。

```typescript
実施<T>(
  指示: string,
  入力?: Record<string, unknown>,
  設定?: 実施設定
): Promise<T>
```

`実施<T>()` は組み込み関数として表現されるが、通常の外部ライブラリ関数ではない。

### 7.2 実施設定

```typescript
type 実施設定 = {
  担当?: "model" | "tool" | "human";
  能力?: string;
};
```

`担当` を省略した場合は `model` とする。

`tool` または `human` の場合は `能力` を指定する。

### 7.3 モデルによる作業

```typescript
const result = await 実施<Analysis>(
  "収集した情報から問題の原因を分析する",
  { observations }
);
```

AI直接実行モードでは、生成AIがこの指示を解釈する。

エンジン実行モードでは、モデルアダプターが処理する。

### 7.4 ツールによる作業

```typescript
const result = await 実施<DeviceStatus>(
  "指定機器の現在の状態を取得する",
  { deviceId },
  {
    担当: "tool",
    能力: "device.read"
  }
);
```

指定能力によって取得した結果を返す。

指定能力を利用できない場合は正常終了してはならない。

### 7.5 人間による判断

```typescript
const approval = await 実施<Approval>(
  "計画について承認者の判断を取得する",
  { plan },
  {
    担当: "human",
    能力: "approval.request"
  }
);
```

人間の回答が得られない場合、生成AIが承認済みの結果を創作してはならない。

### 7.6 型と戻り値

型引数 `T` は作業結果の型を指定する。

実行時に検証する型は、構造的な検証規則へ変換可能でなければならない。

戻り値を必要としない処理には `void` を指定できる。

エンジン実行モードでは返却データの型を検証する。

AI直接実行モードでは同じ型への適合を要求するが、外部検証なしにその成立を保証するものではない。

## 8. 変数とスコープ

変数にはTypeScriptの `const`、`let` を使用する。

通常の字句スコープを適用する。

`goto` による制御経路を含めて、変数の初期化状態を検証する。

異なるブロック間で共有する値は、それらの共通スコープで宣言するか、`goto` の引数で渡す。

ラベルの引数は、そのラベル付きブロックのローカル変数とする。

関数やコールバックのローカル変数は、外側の処理から直接参照できない。

## 9. 非同期・並行処理

`async` は非同期関数を宣言する。

`await` は対象のPromiseが完了するまで、現在の非同期関数の続きを中断する。

複数の非同期処理には `Promise.all()` を使用できる。

```typescript
const results = await Promise.all(
  items.map(item =>
    実施<Result>(
      "対象を分析する",
      { item }
    )
  )
);
```

エンジン実行モードではPromiseの通常の規則を適用する。

AI直接実行モードでは独立した複数操作と完了待ちを解釈する。実際の物理的な並行実行は保証しない。

## 10. 静的検査

コンパイラーは、次の条件を検査する。

| 分類 | 検査内容 |
|---|---|
| 構文 | TypeScriptおよびFlowTS構文への適合 |
| goto | ジャンプ先ラベルの存在 |
| goto | ジャンプ先の一意性 |
| goto | 不正なスコープ移動 |
| goto | 字句スコープと再初期化規則 |
| goto | 引数の数と型の整合性 |
| ラベル | 引数の書き方と名前の重複 |
| ラベル | 引数を持つラベルへの、goto 以外からの進入 |
| 変数 | 未初期化参照 |
| 型 | 型の整合性 |
| 実施 | 型引数と引数の整合性 |
| 実施 | 実行時の出力検証規則への変換可能性 |
| 非同期 | Promiseとawaitの型整合性 |
| 関数 | 戻り値の整合性 |

AI直接実行モードでは同じ規則への適合を要求する。ただし、静的解析器による検査を行わない場合は、検査済みとみなしてはならない。

## 11. コンパイル規則

1. 通常のTypeScript構文は、その評価規則を維持する。
2. `goto` はJavaScriptで表現可能な制御構造へ変換する。
3. `goto` の引数は、`goto` の位置で評価して、移動先のラベルの引数を初期化する処理へ変換する。
4. 組み込み操作はエンジンが提供する実行アダプターへ変換する。
5. コンパイル後のコードにはFlowTS独自のgoto文を残さない。
6. 制御移動は変数の初期化、型の絞り込み、例外、ループの終了処理の意味を保持する。
7. 元ソースの位置を診断およびデバッグ情報に対応付ける。

## 12. 構文サンプル

```typescript
type 依頼情報 = {
  目的: string;
  対象: string[];
};

type 計画 = {
  項目: string[];
  不足条件: string[];
};

type 検証結果 = {
  対象: string;
  妥当: boolean;
  理由: string;
};

type 承認結果 = {
  判断: "承認" | "中止";
};

type 準備結果 =
  | { 状態: "完了"; 件数: number }
  | { 状態: "要確認"; 理由: string }
  | { 状態: "中止" };

export async function デモ準備(
  依頼: 依頼情報
): Promise<準備結果> {

  // 依頼内容を分析する
  const 作成計画 = await 実施<計画>(
    "目的に適したデモデータ作成計画を立てる",
    { 依頼 }
  );

  if (作成計画.不足条件.length > 0) {
    return {
      状態: "要確認",
      理由: 作成計画.不足条件.join("、")
    };
  }

  // 各項目について妥当性を並行して検証する
  const 検証一覧 = await Promise.all(
    作成計画.項目.map(対象 =>
      実施<検証結果>(
        "デモデータの作成条件を検証する",
        { 対象, 依頼 }
      )
    )
  );

  // 検証結果を順番に確認する
  for (const 検証 of 検証一覧) {
    if (!検証.妥当) {
      goto 担当者確認(検証.理由);
    }
  }

  // 人間による承認を得る
  const 承認 = await 実施<承認結果>(
    "作成計画について承認者の判断を取得する",
    { 作成計画 },
    {
      担当: "human",
      能力: "approval.request"
    }
  );

  if (承認.判断 === "中止") {
    return { 状態: "中止" };
  }

  // 承認後にデータを作成する
  for (const 対象 of 作成計画.項目) {
    await 実施<void>(
      "指定されたデモデータを作成する",
      { 対象 },
      {
        担当: "tool",
        能力: "demo.create"
      }
    );
  }

  return {
    状態: "完了",
    件数: 作成計画.項目.length
  };

  // 通常処理では扱いにくい経路だけgotoを使用
  担当者確認(確認理由: string): {
    await 実施<void>(
      "実行前に担当者へ問題を通知する",
      { 確認理由 },
      {
        担当: "human",
        能力: "notification.send"
      }
    );

    return {
      状態: "要確認",
      理由: 確認理由
    };
  }
}
```

このサンプルは、通常の逐次実行、条件分岐、反復、並行処理、組み込み操作、引数付きのgoto、関数終了の組み合わせを示す。

デモデータの作成操作は実行環境が提供する能力に依存する。外部副作用の冪等性、部分失敗時の復旧、推論結果の事実性は、組み込み操作の戻り値型だけでは保証されない。
