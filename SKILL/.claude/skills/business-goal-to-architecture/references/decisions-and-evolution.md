# 構成判断と進化

## 比較の順序

1. 満たさなければ採用できない条件を示す。条件自体が仮説なら合意状況も示す。
2. 現状維持、運用の変更、既存内部の改善、モジュール型モノリス、特定境界の分離、より広い分散化から案件に意味のある案を選ぶ。方式固定ならその方式内の構成・段階案を比べる。
3. 事業成果、品質、費用、組織、移行の同じ条件で比べる。勝たせたい案だけ理想状態、他案だけ悪い現状という比較をしない。
4. 推奨理由と最も大きな不利益を並べる。前提が変わった際に別案を選ぶ条件を示す。
5. ADRと実験で判断を更新する。

## 品質シナリオ

| 観点 | 具体化するもの | トレードオフの例 |
|---|---|---|
| セキュリティ | 誰が、どの境界・データに、何を実行できるか | 分離による影響限定と接点・認証経路の増加 |
| プライバシー | 目的、必要項目、保持・削除、コピー先 | 検索・分析の利便性とデータ最小化 |
| パフォーマンス | 対象操作、負荷、データ量、応答時間の分布 | ネットワーク往復と局所処理 |
| スケーラビリティ | 増える負荷の種類、上限、増設単位 | 独立拡張と分散運用の費用 |
| レジリエンス | どの故障で何を継続・停止し、いつ復旧するか | 冗長化・再試行と重複や複雑さ |
| 複雑さ | 学習、変更箇所、依存、運用手順、診断の負担 | 局所の単純化とシステム全体の複雑化 |

「高速」「高可用」だけでは判定できない。数値が不明なら計測計画を示す。提案値は事実として扱わない。プライバシー上の削除や保持について法的判断が必要なら、適用法令と責任者の確認を分ける。認証方式、暗号、法令、製品の仕様を判断に使う場合は、現在の公式の一次資料で確かめる。

## 技術の誤結合を防ぐ

- イベントで業務を理解することと、ブローカーを導入することは別の判断。
- 非同期化は時間的な結合を弱めるが、スキーマ・意味・所有者・運用上の結合は残る。
- イベントソーシングは状態変化をイベント列として保持・再構成する選択。監査ログだけで足りるかを比較する。再生、スキーマ進化、訂正、削除・保持、運用技能の負担も含める。
- CQRSは書込モデルと読取モデルを分ける選択。物理DB分離やイベントソーシングを必須としない。照会の複雑さ・更新特性に見合うかを判定する。
- 単純な連携ではコレオグラフィを、進行・期限・補償を明示的に管理したい複雑な処理ではオーケストレーションを比較する。ステップ数だけで決めず、処理責任と障害時の見通しを見る。
- 複雑な業務規則はドメインモデル、集約の不変条件、関数的な核と副作用の分離を検討する。単純CRUDにも重いモデルを強制しない。
- Ports and Adapters等の内部構造と、モノリス／分散の配置方式を同じ分類軸に混ぜない。
- 方式やパターンの名前から、性能や安全性を保証しない。期待する効果は、案件の計測で確かめる。

## 分離候補

独立した変更頻度、リリース待ちの損失、特定機能だけの負荷、障害の影響限定、所有チームの自律性など、実測または確認できる必要性を探す。全項目に該当する必要はないが、「将来大きくなるかも」だけで分離を決めない。

候補ごとに、価値、境界の明確さ、依存、データ共有、技能、観測可能性、復帰可能性を点検する。初回の抽出は大きいコアか簡単な周辺かを機械的に決めず、価値と学習と危険のバランスを説明する。

## 段階導入カード

| 項目 | 記述内容 |
|---|---|
| 開始条件 | 前段階の検証、契約、データ所有、担当者 |
| 変更単位 | 対象業務、コンテキスト、呼出元、対象利用者 |
| データ | 正本、書込先、読取先、複製先、IDと版 |
| 移送 | バックフィル、増分同期、順序、重複、照合方法 |
| 切替 | トラフィックや処理の切替手順と観測 |
| 停止 | 業務損失・誤処理・遅延等の中止条件 |
| 復帰 | データ更新後も戻せる範囲、逆同期、戻せない場合の前進修正 |
| 完了 | 成果指標、品質、旧経路の参照停止、残る依存 |
| 解消 | 暫定的な連携・二重更新を廃止する条件と担当 |

既存の仕様をそのまま全て温存することと、既存の業務を壊さないことを区別する。回帰テストは重要な振る舞いを守るために用い、明らかなバグを正しい仕様として固定しない。仕様意図が不明なら決定者に結び付ける。

## ADRの最低内容

ID／題名／状態／解く問題／関連目標・要件・品質条件／選択肢／決定または推奨／根拠／良い結果／悪い結果／未検証事項／判断者／判断期限／再検討トリガー／置き換えるADR。

決定履歴を上書きで消さない。「承認済み」は権限者の意思を確認できる記録に限定する。提案の完成と業務承認の完了は別である。
